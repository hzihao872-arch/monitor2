# 新基底第三轮检索：ProTracer 优先诊断，SARM2 条件备选

检索日期：2026-10-03，Asia/Shanghai。执行入口：[研究流程](../PROGRESS_MONITOR_RESEARCH_WORKFLOW.md)第一至第四步。A＝作者报告；B＝本轮官方源码/元数据核查；H＝待验证解释。没有模型推理、训练、大权重下载或付费调用。

## 1. 本轮决定

**优先继续 ProTracer 的长轨迹失败起点定位诊断；SARM2 保留为更贴近进展估计的条件备选。尚未确立新颖方法。** ProTracer 是覆盖多项执行评价任务的离线诊断系统，不是输出连续进度的在线监测器；这是研究范围内相邻任务的选择，不能悄悄改称在线 progress monitor。若研究必须限定连续进展输出，则本轮没有找到一个材料齐备、可以立即替代旧基底的合格新对象，SARM2 还缺已发布实验权重的确认。

这次扩展了此前候选池，没有重启 RoboMeter—ProgressCompass 或 VLAC-Cut—ARS 的高重合切口，也不把 RynnValue 策略筛选负收益当评价器直接误判。此前结果保留在原文件。

先按近30天（9月3日起）、90天（7月5日起）筛选；由于进展模型的开放材料不足，扩至180天（4月6日起）纳入SARM2。LRM只作更早补充，9月更新不计为新方法首发。以下排名是研究可推进性排序，不是跨基准性能排名。

## 3. ProTracer：为什么值得继续，以及证据止于哪里

### 原生现象与分母

下表为作者Table I，非本地复现。无反思经验的版本符合本项目当前默认信息约束；+Exp使用带标签校准经验，单列。

| 配置/数据 | 起点MAE（秒，低为好） | acc@0.5s | acc@1s | 成败判定准确率 |
|---|---:|---:|---:|---:|
| 原生ProTracer / Short | 0.59 | 71.18% | 81.03% | 99.34% |
| 原生ProTracer / Long | 4.06 | 40.35% | 49.12% | 87.00% |
| +Exp / Long | 3.27 | 45.61% | 50.88% | 88.00% |

来源：[论文Table I及§V-A](https://arxiv.org/html/2609.21369v1)。**不能说“平均都在亚秒级”，也不能说“长视频一半检测失败”。** 失败定位与成败检测不同。Short/Long同时变化平台、场景及长度，因此不是长度单因素消融。

B：核读固定版[evaluation.py](https://github.com/Chang-AIML/ProTracer/blob/63dafa9b703be0347d80f63d049304269f8d000f/code/protracer/evaluation.py)：MAE只聚合真失败、预测也为失败且有数值起点的记录；容差准确率以所有真失败为分母，漏检也损失得分。代码用`<=`，论文文字用`<`，正式复现须固定边界口径。已完整读取Long标签：**100 episodes、13任务、57失败/43成功、ALOHA30/SO-10170**。按57作分母，40.35%和49.12%分别与23/57、28/57相容；这是算术核对，未恢复作者逐例预测，也不能确定余下29例各自为什么失败。

### 由已确认现象得到的问题候选

H-P：在多阶段长执行中，候选时刻选取与最后的错误归因是否分别限制了起点定位？它来自上面的原生残差，不是假定基底“缺记忆”。暂分三种竞争解释：

1. 关键事件附近未被选入证据，或被压缩后的时间描述不足以保留它。
2. 证据在输入中，但把早期可恢复偏差、最终未恢复失误及更晚结果混在一起。需要真实错例才能成立。
3. 差异主要来自机器人坐标、任务上下文、视觉识别或类别组成，而非长时间推理。公开实现的平台配置不同，必须先排除。

原生系统已具有变点选帧、信号叙述、视觉关系、最终状态核验、两轮推理；可选经验还会根据标签纠错。**上述组件不能重新命名为我们的贡献。** 代码第二轮保留第一轮图像消息，不是“只看文字、丢失全部视觉”，见[pipeline.py](https://github.com/Chang-AIML/ProTracer/blob/63dafa9b703be0347d80f63d049304269f8d000f/code/protracer/pipeline.py)。任务XML含substages并注入诊断；它不能被描述为只有裸指令，后续要固定这些原生输入。

值得先核的一处具体配置：论文将Long最大阶段预算概述为39；代码ALOHA固定14，SO-101按时长在14—39之间取值。**不能直接宣布这是bug或错误原因。** 它只是必须按平台核实的实际输入条件；扩大预算属于必要简单对照，不能单独当新架构。

### 正确对照、反证和缺项

- Short定位较强；Long中也有约23条在0.5秒容差内。需要保留这些正确控制，不能仅挑最差片段。
- 作者Figure 4展示ProTracer在Long定位正确的例子，不可把该图冒称其失败案例。
- +Exp已改善部分结果，说明免训练反思不是空白；但它使用校准标签，不属于默认零样本条件。
- 查完整Git树未发现正式逐例预测dump。公开失败标签描述的是机器人失败，**还不是评价器错题清单**。
- Long标签允许一个episode多类型，本轮8类计数总和大于57；不能把多标签当独立样本。具体统计见metadata_audit.json。
- 未运行Gemini或其他VLM；普通模型的输出不能冒充作者原法成绩。

## 4. SARM2：保留更贴近进展监测的第二条线

A：Table 9按每任务10条held-out episode评阶段估计；收伞57.74%、摆餐桌70.85%，折短裤97.52%、折T恤98.27%，全帧micro平均85.22%。这些是按时间步的动作原语识别率，不是10次任务成功率。模型整体价值MSE较强，因此值得检查它的局部阶段错误，而不是宣布系统总体失效。[论文§6.12](https://arxiv.org/html/2606.10305v1)

H-S：错误动作原语是否会选到不合适的价值门控，使某些复杂任务产生不必要的进展跳动？原文说明阶段预测参与门控，公开[价值头](https://github.com/xdofai/opensarm/blob/9978198d4c6601f34063fa40e63f9ddc5baf7f68/models/moe_deco_gate_reward_model.py)接受外部gate index；这建立了可诊断接口，**没有证明错误已经传播到进展输出**。

竞争解释包括原语标注边界容差、稀有动作、视觉歧义，以及两个原语虽不同却属于同一语义门组。若错原语多数仍选相同组，或价值输出依然正确，就不应把“阶段错”强行扩大为奖励错。折衣高分及完整系统优于去阶段/去多门控消融必须保留。

作者另承认高度揉皱衣物前期展平进展有时平坦/噪声，这是任务级原生线索；目前不沿旧折毛巾/完成验证思路继续。优先检查可核的阶段—门控链。

开放限制：当前配置的dataset、状态归一化和阶段checkpoint均需用户自填；HF同名搜索命中旧SARM个人模型，未核为SARM2。故不能启动“冻结已发布SARM2”的承诺，更不能为保住它先从头训练。下一步若拿不到官方原生输出或权重，仅保留论文诊断候选。

## 5. 重合核查：已提前排除的泛化方案

实际检索了模型名＋improvement/inference/training-free，以及failure onset、temporal grounding、action segmentation、phase estimation、OOD monitoring等同义概念。精确后续检索未确认直接修复本轮两个具体入口的文章；这不代表领域不存在。搜索命中的自动论文评论不作错误证据。

| 查重线与最接近工作 | 已有机制/信息条件 | 对本轮约束 |
|---|---|---|
| 直接基底：ProTracer自身/+Exp | 两轮多模态推理、物理叙述、视觉关系与终态核验；+Exp用校准标签形成反思记忆 | 补传感器、加关系、加记忆、完成验证都已有；必须先证明具体剩余错因 |
| 同任务免训练：[KITE](https://arxiv.org/html/2604.07034v1) | 运动关键帧、对象检测、布局、时间戳和机器人信息组成失败诊断输入 | “结构化证据＋关键帧”高度重合；比较需匹配骨干及可见信号 |
| 同机制免训练：[FV-Action](https://arxiv.org/html/2608.08315v1) | 将时间戳生成改为冻结VLM的二元判断、粗到细扫描及排序 | “分窗问是/否再定位”已有明确先例；通用事件定位与失败起因语义不同，但不能只换应用名称 |
| 阶段推断免训练：[OVTAS/SMTS](https://arxiv.org/html/2602.21406v1) | 帧—动作相似度，再用带时间先验的最优传输产生一致分段 | 简单时序平滑/一致性后处理不是空白；原语纠正必须进一步证明能改善原生价值输出 |
| 训练型强法：[ViFailback-8B](https://arxiv.org/html/2512.02787v1)、RoboMonitor | 前者训练多任务失败诊断；后者用Temporal SFT学习阶段一致性 | 问题已有训练型方法；ProTracer论文的同卷结果优先于跨榜比较。不能把不训练本身当贡献 |
| 在线邻近法：[Rewind-IL](https://arxiv.org/html/2604.16683v1)、FARM | 前者检查动作chunk一致性，并用成功示范校准/恢复库；后者训练轻读出 | 输入/目标不同；在线首报警不能冒充完整轨迹的事后最早起因定位 |
| 关系建模：[RAFAIL](https://arxiv.org/html/2609.18324v1) | 成功示范经VLM标关系重要性与进展，学习关系表征，再做异常检测 | “只关注任务相关关系”已有训练型先例，且原生需要额外信息 |
| 历史边界：ARS、ROVER、ProgressCompass | 自适应检查、局部分段、验证及上下文组织 | 不恢复旧路线；泛化“补看＋验证”不作为新提案 |

**继续理由是“有强基底、有真实残差、有材料能区分解释”，不是“本轮已查明无人做过”。** 本轮尚未形成具体架构，因此也不可能完成架构级最终查新。

## 6. 下一件最便宜、有区分力的动作

对ProTracer建立“GT起点—原生候选时刻—输入证据”的小诊断，不先付费跑整套VLM：

1. 固定本轮Git commit和HF revision，在Long中预先选约6—10条开发episode，跨两机器人和至少3任务，覆盖失败及成功控制；不按想要的错因只选例。当前本轮只读取标签，没有下载这些视频。
2. 仅获取所选episode，运行原生确定性选帧/叙述模块，记录GT最近候选间距、平台预算、时间单位和输入视角。核查任务XML的额外上下文；不把onset/type/reason标签送入诊断提示。
3. 先判断是否存在候选覆盖不足。候选附近有GT只是必要证据线索，并非保证VLM能判对；无近邻也不等于VLM绝不可能从连续叙述推断正确时间。
4. 只有需要区分“信息没到”与“信息到了仍判错”时，再明确API/本地骨干资源进行小推理，保存原法逐例输出。必要对照：原生、等帧数均匀采样、原生已有参数变化；具体机制再与KITE/FV-Action/ARS核查。

失效条件：原生候选已覆盖而只是格式/版本不一致；所谓残差被简单对照消除且无新机制价值；或最终方案仍只是已有扫描验证。出现这些情况就降级，不通过新增任务或换术语维持方向。SARM2更便宜的前置动作是获取原生阶段/门控/价值三联输出；未有数据不开展模型训练。

## 7. 可向老师汇报

> 我们停止了与现有上下文验证框架重合的方向，重新筛查了机器人执行评价系统。目前ProTracer最便于继续：它原生覆盖失败检测、分类、解释和起点定位，公开代码与长轨迹数据；作者结果显示长轨迹定位仍有明显残差。我们准备先区分候选时刻选择与最终判断两个环节，尚不认为错因已经确定。若坚持连续进展估计，SARM2更贴近目标，其复杂任务阶段识别已有明确低分，但公开权重仍需确认。已有关键帧、反思和粗到细定位方法会作为比较，不能把这些组件重新组合就宣布创新。
