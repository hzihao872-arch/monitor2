# 机器人 Monitor 研究方向与师姐讨论准备

日期：2026年10月12日，北京时间。

这次讨论需要先确定 Monitor 如何改善机器人，再选择值得训练或扩展的能力。师姐的建议可以整理为三个研究主线候选：少量数据训练可靠 Monitor、执行反馈驱动的 Monitor 适应、具有短期预测能力的 Monitor。换模型、图像编辑造数据和导航方法借鉴可以支持这些主线。用户接受根据调研调整核心问题；RSI 暂不纳入本次比较。

在算力有限、主要使用仿真的假设下，建议先以少量监督建立可用基线，再比较静态 Monitor 与反馈适应的 Monitor。完整视频世界模型的训练和机器人策略 RL 涉及更多工程依赖，适合在资源明确后决定。这里的优先级是成本与可检验贡献的判断，不是论文录用概率预测。

## 师姐建议的分类

| 建议 | 主要作用 | 对当前项目的含义 |
|---|---|---|
| 换 Qwen3.5 系列或更大模型 | 改进底座和建立强对照 | 检查当前视觉、时间绑定和事实更新错误是否主要受底座限制；换模型本身通常不足以成为论文主贡献 |
| 构造少量数据进行微调 | 改进现有能力，也可支撑训练型研究 | 从依靠提示流程转为学习状态和任务关系；需要具体监督设计、泛化验证及下游收益 |
| image editing 构造变化样本 | 数据构造手段 | 可增加结构变化和易混淆样本；需区分任务作用与纯外观变化，并检查生成图是否真实改变了预期条件 |
| world model 生成数据 | 数据构造手段 | 生成状态转移或轨迹；其预测只能作为候选数据，不能直接当物理后果真值 |
| 让 Monitor 预测未来 | 扩展能力的研究候选 | 从“已经怎样”扩展到“执行某个动作或技能后可能怎样”，用于提前纠错或选择候选动作 |
| TTT 或执行后更新 Monitor | 区别于固定评价器的研究候选 | 少量标注初始化，之后从实际执行中获得监督、适应新任务或新环境；重点是更新什么、监督是否可信和何时更新 |
| 借鉴 image-goal navigation | 方法借鉴 | 学习目标与当前状态对齐、局部结构匹配、记忆更新和到达核验；不必立刻转向导航任务 |
| 调研 Monitor 如何影响机器人 | 明确研究接口和实验终点 | 在在线纠错、候选动作选择、数据筛选和 RL 奖励中选一个主要接口，避免只展示评分更准而没有用途 |

“有几个方向”需要说明计数口径：上表列出了具体建议，但按可独立组织研究的主线可归并为三个。静态训练、反馈适应和预测能力也可以递进组合，当前不需要把全部模块同时加入。

师姐对后半部分的认可，说明她认为“评价服务于学习”值得继续。她最后的问题则是在确认：评价输出究竟如何改变机器人，以及奖励模型用于 RL 是否已有成熟先例。

## Monitor 如何影响操作和导航

“Monitor”在不同论文中可能叫 execution monitor、success detector、verifier、progress model 或 reward model。它们的输出义务不同，下面按接入机器人系统的位置分类。

| 接入位置 | 输出怎样被使用 | 参数是否必须更新 | 代表工作 |
|---|---|---|---|
| 技能执行过程中 | 检查约束、阶段、失败和完成；触发恢复、重规划或下一技能 | 可以保持机器人策略冻结 | DoReMi、Code-as-Monitor、RoboMonitor |
| 动作执行之前 | 评价和细化多个候选动作，再选一个执行 | 可以保持基础策略冻结 | RoVer |
| 离线策略训练之前 | 根据评价保留或加权轨迹片段，再做行为克隆 | 下游策略接受监督学习 | ARS |
| 策略 RL 过程中 | 提供终局奖励、密集奖励或奖励塑形，用于策略优化 | 更新策略；奖励模型可固定，也可校准 | RoboCLIP、RoboReward、HiRE |
| 世界模型中的训练或规划 | 评价想象中的轨迹或预测状态 | 依具体系统训练世界模型及策略 | World-Gymnast、GenRL |
| 导航决策过程中 | 目标匹配结果决定继续探索、接近候选位置、核验或排除候选 | 大模型可以冻结；其他模块的训练状态另行区分 | UniGoal、ImagineNav++ |

表中最后两行是相邻接口，并非所有论文都把相应模块命名为 Monitor。分类用于回答系统如何利用评价，不能把这些模块直接视为同一评测任务。

**在线纠错有明确先例。** DoReMi 让 LLM 生成执行约束，VLM 连续检测约束违反并触发恢复；Code-as-Monitor 把反应式和主动式失败检测统一为时空约束检查，并使用生成的代码进行监测。RoboMonitor 在任务编排器中预测阶段、失败和完成，触发预定义恢复行为。它们说明 Monitor 不必输出完整动作，也可以通过高层接口影响执行。[DoReMi](https://arxiv.org/abs/2307.00329)、[Code-as-Monitor](https://arxiv.org/abs/2412.04455)、[RoboMonitor 方法与闭环评价](https://arxiv.org/html/2609.30715v1)

**动作评价可以直接影响下一步。** RoVer 用机器人过程奖励模型给候选动作评分，并预测动作空间中的细化方向；推理时筛选候选，基础 VLA 权重保持不变。这属于测试时增加计算和动作验证，需要与更新 Monitor 参数的 TTT 区分。[RoVer](https://arxiv.org/abs/2510.10975)

**离线筛选与 RL 是两条不同路径。** ARS 用动作块前后的进度差决定保留哪些片段，随后做行为克隆。其主要下游实验不是“用 ARS 奖励进行在线 RL”，尽管论文讨论了与价值学习的兼容性。[ARS 第3.7节](https://arxiv.org/html/2609.34484v1#S3.SS7)

**用视觉评价信号强化机器人策略，答案是有。** RoboCLIP 从预训练视频语言模型获得奖励并训练 RL 策略；RoboReward 训练机器人奖励 VLM，并部署到真实机器人 RL。HiRE 则利用成功和失败的执行历史，在冻结视觉表征空间中非参数地修正奖励，用于 RL 微调。[RoboCLIP](https://arxiv.org/abs/2310.07899)、[RoboReward](https://arxiv.org/abs/2601.00675)、[HiRE](https://arxiv.org/html/2609.27068v1)

**世界模型也有相关接口。** World-Gymnast 在动作条件视频世界模型中 rollout VLA 策略，再用 VLM 给想象轨迹奖励；GenRL 把多模态基础表征与世界模型潜在空间对齐，使策略能在想象中学习。前者清楚地区分“预测未来的模型”和“评价未来的模型”，这对设计 Monitor 很有参考价值。[World-Gymnast](https://arxiv.org/abs/2602.02454)、[GenRL](https://arxiv.org/abs/2406.18043)

选择下游接口时，当前项目最容易先接离线筛选或固定技能的高层恢复；RL 需要额外打通策略优化、环境交互、奖励更新和独立任务成功评价。这是依工程依赖作出的成本判断。

## 图像编辑和导航可以借什么

### 图像编辑的数据设计

原始图像不天然是正样本，编辑图像也不天然是负样本。若目标是把方块放进盒子，原图盒盖关闭可能表示未具备条件，编辑后的开放入口反而可能表示有利变化。标签应根据训练目标定义：可见状态、发生了什么变化、变化与目标的作用，需要分别标注。

建议的数据组织是“同一目标下不同变化”和“同一变化下不同目标”，再加入外观相近但作用不同的困难样本，以及改变光照、背景却不改变任务条件的控制样本。生成前后图适合监督局部状态和结构变化；撤销、遮挡后重现和时间绑定仍需要连贯短序列。

图像编辑用于机器人已有先例：LfVoid 编辑初始观测生成目标图，再训练目标判别器提供 RL 奖励；SuSIE 用编辑模型生成子目标图，由低层策略执行。RoboReward 的反事实目标重标注和时间截断则说明构造负例、近成功样本也已有基础。[LfVoid](https://lfvoid-rl.github.io/)、[SuSIE](https://rail-berkeley.github.io/susie/)、[RoboReward](https://arxiv.org/abs/2601.00675)

因此，论文贡献需要落在“哪种监督解决了哪种可靠性问题，能否迁移到真实或独立仿真数据”上。训练集应按源轨迹、场景及编辑模板划分，防止同源图进入训练和测试；生成质量检查应独立于被训练 Monitor，避免它仅学习编辑痕迹。

### 导航方法的借鉴

师姐提到的 image-goal navigation 要区分两种目标：到达拍摄目标图的地点，或找到目标图中的特定物体实例。它们与操作任务的共同点是目标与当前观测对齐，但视觉相似不一定意味着操作条件成立。

UniGoal 将目标和观测统一成图表示，按零匹配、部分匹配和完全匹配选择探索策略，接近候选目标后继续核验，并记录失败匹配。可借鉴的是身份与关系匹配、分层核验和防止重复误判；移植到操作时必须验证这些机制是否改善当前实体绑定。[UniGoal](https://arxiv.org/html/2503.10630v1)

ImagineNav++ 通过未来视角想象、候选视图选择和观察记忆辅助导航，包含 instance-image-goal 评价。对 Monitor 的启发是针对当前不确定的关系选择下一观察，而不是固定重复看同一批帧。其未来视角模块与控制模块的训练依赖不能省略；使用冻结 VLM 不等于整套系统无需训练。[ImagineNav++](https://arxiv.org/html/2512.17435v1)

ZSON 的 zero-shot 指迁移到 ObjectNav 时不需要该任务奖励或示范，它此前训练了 ImageNav 策略。这提示我们逐模块说明训练状态，避免把 zero-shot 全部解释为纯提示工程。[ZSON](https://arxiv.org/abs/2206.12403)

### 预测能力的三个层次

预测“下一帧或未来特征”、预测“某个动作的结果”、预测“后续成功概率”是不同目标。建议先考虑短技能的结果预测或失败风险，明确输入动作、预测时域和评价真值。机器人最终成功概率还受后续策略影响，不能等同于当前进度。

RoboMonitor 已用动作条件未来特征预测等自监督任务预训练，再微调因果执行监测器；它不等于完整的生成式视频世界模型。其预训练使用八张 H100、监督微调使用四张 GPU，说明论文的少量标注优势不等于整个训练流程便宜。若本项目走这一方向，应优先复用表征并验证有限的预测能力。[RoboMonitor 第IV节及第V-E节](https://arxiv.org/html/2609.30715v1)

## 如何理解师姐的 TTT 建议

师姐的重点是让监督者从执行中改善，而机器人原模型可以保持不变。但需要确认她说的“原模型”是机器人策略，还是 Monitor 的基础 VLM。两者冻结的是不同参数。可用基础 VLM 冻结、适配器或小预测头更新实现参数上的区分，但这还不是确定的研究方法。

经典 TTT 在测试样本上构造自监督目标并更新参数；师姐描述的“每次任务结束后，用实际结果继续微调”更接近部署后的在线适应或持续学习。如果只更新检索记忆、阈值或提示，则属于其他适应方式，名称应随具体实现确定。[Test-Time Training](https://arxiv.org/abs/1909.13231)

这里有一处需要在讨论时补充：**最终任务成功，不能推出所有中间状态都应被判成有利。** 例如“开盖、关盖、再开盖、放入”最终成功，中间关盖仍可撤销准备；成功轨迹可能包含失败尝试、无关动作和恢复。最终失败也可能保留有价值的中间进展。

可行的监督来源包括可信终局结果、之后能够确认的状态转移、技能执行反馈、少量人工复核和仿真标签。终局信号可以作为弱监督，但要通过时序归因或局部核验确定具体更新对象。由 Monitor 自己打分再直接把分数当真值，容易放大已有偏差。

这个方向的相邻工作必须比较：HiRE 已用带结果的交互历史修正奖励，Demo2Reward 已从少量示范优化 VLM 奖励提示，ARS 已可接受终局标签辅助离线评价。它们分别更新奖励支持集、提示和推理上下文，并非都更新 Monitor 权重。潜在区别可以研究“在少量可信反馈下，怎样改善局部判断并控制错误监督传播”，但当前尚未证实新颖性。[HiRE](https://arxiv.org/html/2609.27068v1)、[Demo2Reward](https://arxiv.org/abs/2606.00083)、[ARS](https://arxiv.org/html/2609.34484v1#S3.SS6)

HiRE 的仿真实现仅将在线成功和失败的终局帧加入相应缓存，明确避免强化成功轨迹中的次优中间行为，以及惩罚失败轨迹中的有效中间行为；真实机器人实现使用的帧选择有所不同。这说明局部归因风险已有认识，不能把发现这一风险本身当作首次贡献。其局限部分也指出终局反馈遗漏中间控制信息，可作为进一步研究的入口。[HiRE 附录A.3及局限](https://arxiv.org/html/2609.27068v1)

评价应记录每次更新前对新轨迹的预测，再在结果出现后更新；同时保留固定测试集测遗忘。不能用一条轨迹的终局标签更新后，再把这条轨迹的中间预测称为实时泛化能力。至少比较静态模型、记忆或提示适应、参数适应，并匹配反馈和标注预算。

## 候选方向的成本与贡献比较

以下为计算资源有限、仿真为主的条件判断。GPU、预算、机器人和投稿周期尚待确认；推理成本、标注成本与交互成本分别考虑。

| 候选 | 可以提出的研究问题 | 主要投入 | 必须建立的贡献 | 初步位置 |
|---|---|---|---|---|
| 少量监督训练可靠 Monitor | 哪类状态和变化监督能减少任务相关误判，并改善混合质量数据利用 | 数据构造、人工核验、小规模微调、一次固定策略训练流程 | 跨场景泛化、标注效率、独立下游收益；仅换模型或 SFT 不充分 | 最适合先建立基础，但独立论文贡献尚需验证 |
| 执行反馈适应的 Monitor | 少量终局及局部反馈能否改善新任务判断，且不放大伪监督错误 | 反馈来源、顺序数据流、轻量更新、适应与遗忘评价 | 可信局部归因、受控更新及下游收益；比较 HiRE 和提示适应 | 值得优先与师姐深入讨论，监督设计是主要风险 |
| 短期预测与主动纠错 | 能否提前识别某个技能会失败，并减少无效执行 | 动作条件数据、预测模块、技能接口、闭环评价 | 匹配误报率和时延下的提前预警及任务收益；比较主动监测和预测预训练 | 资源足够时保留，先从短技能做起 |
| 继续纯提示变化先行架构 | 局部关系推理在公平输入与成本条件下是否优于强直接法 | 强底座与消融推理、独立评测 | 明确机制净收益，且与 ARS 有实质区别 | 成本较低，可诊断；当前不宜直接定为主线 |
| 完整转向导航任务 | 导航场景是否提供更清楚的反馈和监测需求 | 新数据、仿真平台、基准和闭环系统 | 新任务上的问题证据及强方法比较 | 有现成导航资源时再考虑，当前先借鉴方法 |

“TTT”“world model”和“微调”都是技术选择，文章仍需一个清楚的问题。第一、二条可以衔接：先得到静态小数据基线，再检验可信执行反馈带来的增益。如果反馈无法可靠归因，就先收缩到监督训练；如果强底座已解决当前八例，需要在独立任务上重新找剩余需求。

建议先做的共同诊断是：用同一组独立核验的状态问题检查当前 8B、一个较新小模型及一个可负担的强模型，再决定数据训练和架构的投入。进入下游时选一个主接口即可：离线筛选或固定技能恢复通常更便于隔离 Monitor 的贡献。拟定训练研究时应使用新划分，不用已反复看过的开发例报告泛化。

若选数据筛选，至少加入成功轨迹筛选、等量随机筛选和现有奖励筛选对照，并固定任务配比与策略训练预算。保留片段更少、任务分布改变和 Monitor 判断更准确会影响同一个下游成绩，需要分别检查。局部零进度片段也可能用于接近、保持或恢复，不能未经验证就全部丢弃。

评分准确也不保证用于优化后行为正确。近期 CriticHack 展示了视觉奖励优化会同时增加成功和错误物体行为的情形。因此独立任务成功、错误行为比例和恢复结果应作为下游评价，不能用 Monitor 自己的分数证明收益。[CriticHack](https://arxiv.org/abs/2610.02527)

## ARS 和模型信息的核对
