# 执行反馈反过来训练机器人 Monitor：直接先例与对比设计

2026-10-13。本轮仅检索和核验论文；未训练、评估或运行机器人。沿用 nature-academic-search 多源检索流程。全文 HTML、PDF、作者项目页已检查。

## 直接先例

**Model-Based Runtime Monitoring with Interactive Imitation Learning**，Huihan Liu、Shivin Dass、Roberto Martín-Martín、Yuke Zhu，ICRA 2024；预印本 2023。

- [论文](https://arxiv.org/html/2310.17552)
- [PDF](https://arxiv.org/pdf/2310.17552)
- [作者项目页](https://ut-austin-rpl.github.io/sirius-runtime-monitor/)
- DOI: 10.1109/ICRA57147.2024.10611038；Undermind 元数据检索返回 Liu23。

它是机器人执行期间的失败/OOD 监控器，使用部署轨迹与人类接管记录训练，并在后续轮次重训。故满足“机器人 Monitor + 执行数据反过来训练 Monitor”，但不是连续任务进度模型，也不是完全自动物理监督。

关键核验：§III-B 在训练策略与动力学模型后，在冻结隐空间上训练失败分类器。人类接管前状态作为不理想/失败风险的代理标签，区分正常 rollout、failure、intervention 三类；分类器实现为 LSTM。§III-C 用潜空间预测未来，再检查 OOD 和失败风险。§III-D 明确储存状态、动作、下一状态、干预标签，并在下一轮使用累积数据重训。

§IV-A 在两项仿真和两项真实操作任务上检查系统效果；策略也同步更新，整体成功率不能单独归因于 Monitor。§IV-B 另外对错误预测器作独立测试，以预测区域与人类标签区域的 IoU、预测时刻到接管时刻的距离 DCI 测量监控效果。首轮需要全程人工监控来获得干预标签。

作者网页的 Code 链接当前指向后续 Sirius-Fleet 仓库，不能不加说明地当成 ICRA 2024 原版可直接复现实现。此轮未安装或运行代码。

## 与当前方案的联系及边界

已有共同点是“部署执行 → 获得反馈 → 训练监控器 → 再部署”，不能作为我们的首创点。

当前拟研究的不同问题是指定物理条件的成立/失效，以及一次交互证据可用于哪一段历史；使用独立范围校准来选择监督扩展策略。上述论文主要学习人的风险判断，不能直接等同于物理条件真值或任务进度下降。这些区别目前是设计目标，尚无实证收益。

## 对比优先级

1. 主实验固定同一 Monitor 架构和初始权重，在匹配的人力/反馈预算下比较直接标注、事件锚点、未经校准传播和校准传播。计入事件审核、传播器训练、校准成本，控制训练计算或透明报告差异。
2. 在另一种可训练 Monitor 上适配同样的监督方法，核验是否也提升。物理条件标签不能直接冒充阶段/进度标签：可增加相同条件头或统一接口，两组必须同样适配，并单独检验最终进度收益。
3. 与其他完整 Monitor 比较统一输出与测试任务。部署输入、未来信息、状态信息、人工反馈预算需一致或分组报告。ARS 完整录像离线核验不能直接当成与前缀在线 Monitor 同等信息条件的比较。

先测试条件成立/失效与变化定位；再测试帮助/阻碍/无关/成果撤销和适用的下游效果。保持普通目标物体任务测试，检查环境条件能力改善是否伴随其他能力退化。
