# 主线 B 独立核查：执行反馈改善 Monitor

核查日期：2026-10-12，北京时间。范围：论文正文、附录、官方项目页与可读源码；未运行训练、策略学习、模型下载或机器人实验。文献日期为 arXiv 显示的 UTC 首次提交/版本日期，不等于正式录用日期。

## 1. 条件判断

**把少量标注初始化的 Monitor 变成随执行结果更新的监督者，是可研究的设置，但这个设置本身已有很强覆盖。** HiRE 已有非参数结果反馈适应，GCR 已有参数奖励适应，eVTA₀/RLER 已有目标与近期视频输入、终局结果监督、LoRA 奖励模型与策略交替更新。仅把它们换成当前 Monitor 底座或四阶段链，贡献不足。

资源有限时，不建议先做“终局反馈驱动的 VLM 奖励模型 + 在线 RL”作为独立新方向。可以把 B 保留为 A 的第二阶段：先有可靠的原子状态/关系监督，再问在固定反馈预算下，新执行暴露的错误如何改善下一次的局部监测。优先做短诊断，只有出现区别于静态重训、提示校准和非参数记忆的稳定优势，再投入闭环策略学习。

**最值得保留的窄问题是：成功含撤销、失败含准备、证据延迟可见时，哪些事后证据能够合法地监督前缀 Monitor，有限局部复核如何分配，且更新是否真的改善新执行而不遗忘？** 目前这是有文献动机的候选，并非已确认的新机制。“最终成功不能标所有段有利”早有针对性方法，不能把这个风险提示当贡献。

## 2. 必须分开的预测目标

设输入为目标 g 和视频前缀 h_t，不额外默认策略参数、机器人动作、仿真物体坐标或人工介入信号。

| 目标 | 输出例子 | 标签怎样确定 | 与终局反馈的关系 |
|---|---|---|---|
| 可见原子事实 | 盖开/闭；物体仍被抓持；承托板位于目标区下面 | 指定时刻视觉/独立事实标注 | 成功本身不充分确定每时刻事实 |
| 局部任务作用 | 开盖帮助“放入”；关盖撤销此前入口开放 | 同一关系的前后事实 + 目标语义 | 需要局部信息；不可直接广播成功位 |
| 成功概率 | P(最终成功 \| g,h_t,执行策略/数据分布) | 多次结果或终局监督回归/自举 | 适合终局反馈；随策略变化 |
| 价值 | 在策略下的期望累计奖励 | 奖励定义、时域和策略 | 有折扣时不等同成功概率 |
| 动作优势 | 选动作 a 相比参考动作/策略的收益 | 动作条件、反事实或 Q/V 估计 | 当前接口没有动作，不能直接声称得到优势 |

本报告自己的反例：一种强恢复策略会在“开盖→关盖→再开盖→放入”中可靠地完成任务，盖关前后成功概率可能同为接近 1。准确成功概率模型不必把“关盖”输出成负变化；局部入口关系确已撤销。相反，真实的局部准备可以发生在最终失败轨迹中。这里是**预测义务不同**，不是成功概率学习算法逻辑错误。若选择研究 reward/value，应重新定义任务，不能继续把 help/harm/reversal 当它的自然真值。

另一个边界：差分成功概率表示新观测对成功预期的改变，可能包含信息增益、遮挡解除或策略分布的变化；它不能自动成为某个动作的因果贡献。要研究因果作用，必须说明干预/动作对照权限和混杂控制。

## 3. TTT、在线适应与记忆的实际边界

| 设置 | 更新对象 | 监督来源 | 对当前项目的可实现版本 | 最主要成本/风险 |
|---|---|---|---|---|
| 原始意义 TTT | 模型参数；通常辅助自监督分支与共享表征 | 当下未标注测试样本的自监督损失 | 帧序、跨视图或预测一致性辅助目标，更新视觉 adapter | 辅助目标是否与状态/关系任务同向；信心增强不代表语义更准 |
| 标签可得的在线适应 | 分类头、adapter/LoRA，或全模型 | 执行后终局位、局部人工纠错、传感器核验 | 少量监督初始化后每个 episode/batch 更新 | 更新延迟、可信标签、分布漂移、错误累积 |
| 持续学习 | 参数 + 记忆，跨多个任务/环境保留更新 | 上述反馈随任务序列到达 | 多任务流，独立旧任务集测遗忘 | replay/正则成本及稳定性；不能只报告最后任务 |
| 非参数适应 | 支持集/密度/原型/阈值；底座冻结 | 成败状态或核验过的事件 | HiRE 式状态参考库，或目标关系检索校准 | 记忆污染、库大小、时域失效、任务混淆 |
| 提示适应 | 文本指令/例子/规则；权重冻结 | 少示范或显式错误案例 | Demo2Reward 式成功条件提示，局部输出可另校准 | API/VLM 调用开销、过拟合提示、条件遗漏 |
| 推理时计算/验证 | 搜索与采样，无持久参数变化 | 模型评分、约束检查 | 候选动作/假说多样采样与重排 | 延迟与调用预算；不能标为参数 TTT |

术语依据：Sun 等的 TTT 以无标签测试样本构造辅助训练，预测前更新参数；Tent 以预测熵优化 normalization affine 参数；CoTTA 面向连续变化分布，用教师平均与随机权重恢复减少伪标签累积与遗忘。这些概念不要求机器人策略更新。[TTT 正文 §2–3](https://proceedings.mlr.press/v119/sun20b/sun20b.pdf)，[Tent 论文](https://arxiv.org/abs/2006.10726)，[CoTTA 方法 §3](https://arxiv.org/html/2203.13591v1#S3)

**本轮若明确使用终局成功位训练 Monitor，应称结果反馈驱动的在线监督/弱监督适应。** 广义测试时适应可以包含它，但不能用“TTT”暗示只依赖未标注输入。若更新的只是提示或库，也直接写清楚。

## 4. 直接覆盖与证据边界

以下每篇概述控制为短机制摘要；后面的候选和实验是本报告的设计判断。

### 4.1 HiRE：最接近低成本结果适应

HiRE §4.1 用冻结视觉表征中的成败 KDE 密度比形成势函数，§4.2 在线维护支持库，Eq.(6) 通过 potential difference 与稀疏成功奖励结合。负库收**失败终局帧**，不是所有失败帧都标负。§5.4/Fig.2 展示丢失目标、恢复与纠偏的奖励曲线；§6 明确承认终局反馈忽略中间控制信息，成功中的重试/恢复坏段需更细 buffer。实测包括仿真和两项真实机器人策略 RL。[HiRE §4–6](https://arxiv.org/html/2609.27068v1#S4)

当前代码的额外核查：`docs/integration.md` 说明离线正样本来自示范，在线正负默认都是终局观测；`configs/reward/hire.yaml` 的 `positive_buffer.online.add_mode=last_frame`；`reward.py` 也实现 `all_substeps` 与 `episode_stride` 正库模式，不能说源码只有终局一种能力。负库更新固定 `last_frame`。因此正文“成功 rollout observations”的宽泛说法，应以具体配置报告。[官方集成说明](https://github.com/HiRE-Project/HiRE/blob/bea7dfb15d1d279bc8f76ff0e8e44b838f696acc/docs/integration.md)，[默认配置](https://github.com/HiRE-Project/HiRE/blob/bea7dfb15d1d279bc8f76ff0e8e44b838f696acc/configs/reward/hire.yaml)，[buffer 更新源码](https://github.com/HiRE-Project/HiRE/blob/bea7dfb15d1d279bc8f76ff0e8e44b838f696acc/backends/dice_rl/src/hire_dice_rl/integration/reward.py#L802)

**结论：**“历史成败对比、在线修改奖励且不用额外梯度训练”高度重合。若只改用 VLM feature 或加入库筛选，要证明解决具体标签污染/局部关系问题；更换编码器不足以构成区别。

### 4.2 Demo2Reward：少示范提示适应，非在线参数训练

正文 §3.1 的示范含逐步二值成功标签，§3.3 把示范转成前缀片段，meta-critic 迭代重写提示，目标强偏重真负率以减少提前宣告成功。优化完成后提示冻结再用于策略学习；VLM 权重不更新。§4.6 有真实机器人 RL；§5 说明少量示范/视角变化可能导致提示过拟合，当前只做二值成功。[Demo2Reward PDF，§3、§4.6、§5](https://arxiv.org/pdf/2606.00083)

公开 prompt loop 和独立 RL 仓库；优化仓库 README 明说示范数据不直接包含，HDF5 可以从 sibling RL 代码生成。`demo2reward.py` 可读到提示提案、评价与保留循环；公开代码并不意味着本次已复现。[官方优化仓库](https://github.com/cgumbsch/Demo2Reward/tree/2b5082465a4ce7151f479e715df7ab7881807f27)，[RL 仓库](https://github.com/cgumbsch/Demo2Reward_RL)

**结论：**它是低成本强对照。把少数局部错误写回提示可能有用，但只是改到多类局部标签时，仍属于能力扩展且需证明泛化与下游收益。

### 4.3 eVTA₀/RLER：终局结果训练与监督者随策略演化已被实现

§3.2 以任务文本、近期观测窗、reward token 估计最终成功概率，用终局结果及 EMA 目标网的下一观测预测做 TD 回归；§3.3 周期性用新 rollout 更新评价器。附录 B 给失败轨迹 soft 终局目标；C.3 明确 Qwen3-VL-4B + LoRA16，策略另用 IQL；两轮 reward evolution 与固定评价器匹配数据/训练预算。D.1 发现过长历史可保留旧进展而损害回退响应。[eVTA₀ §3、附录 B/C.3/D.1](https://arxiv.org/html/2609.33653v1#S3)

当前官方源码已公开，优于论文中“计划公开”的旧状态。可读代码显示冻结底座原权重，训练 LoRA、reward token embedding、线性 head；soft failure 标签用冻结 V-JEPA2 表征、DBSCAN、距离映射。V-JEPA2 此处供标签增强，不是 eVTA₀ 自身动作条件未来预测。HF collection 可见模型和数据条目，未下载/运行。[官方 model README](https://github.com/duowuyms/eVTA0/blob/8017928d59bc1d3d9051eba43011bd140bf76f54/evta0/README.md)，[模型实现](https://github.com/duowuyms/eVTA0/blob/8017928d59bc1d3d9051eba43011bd140bf76f54/evta0/evta0/model.py#L160)，[模型与数据集](https://huggingface.co/collections/notmuch2/evta0)

**结论：**“只用稀疏执行结果学习密集成功概率、与策略交替更新”高度重合。完整模型以 soft 标签增强，不能把全部实测都归为纯 binary-only；不同监督权限的比较要复算。

### 4.4 GCR：成熟参数奖励在线适应

GCR §V-A 把 VIP 时序目标与 goal contrastive 正负损失结合；失败回合最后 β 比例帧进入小型在线负库，纠正高相似但错误的目标。§V-B 使用势函数差分，§VI 含仿真、Franka 和 Spot 在线 RL，对照冻结/在线 VIP。论文提供附录外链，本轮未完整核查该外链；本次未核实到官方完整代码/权重。[GCR §V–VI](https://arxiv.org/html/2410.19989v2#S5)，[官方项目页](https://gcr-robot.github.io/)

**结论：**“失败结果更新视觉表征/奖励，消除伪高分”已是成熟机制，不因将 encoder 改成 VLM adapter 就变成独特问题。

### 4.5 PACT：成功内坏段信用分配的直接先例

PACT v2 §3.2 用示范时间进展伪标签训练冻结 ResNet 表征上的轻量 progress head；执行完成后结合人工介入点定位回退/恢复段。§3.3 用人工动作与重采样策略动作的 Q 差构造方向性纠正，修改坏段 Bellman target。附录 C.3 确认 progress model 在线前训练、全轨迹定位；§6 承认非单调/重复执行会影响定位，counterfactual advantage 不是精确逐步价值真值。五项真实任务有策略与定位诊断。[PACT v2 §3、§4、§6、附录 C/F](https://arxiv.org/html/2606.03949v2#S3)

**结论：**“成功包含坏段”“发现回退并重新分配信用”不为空白。其定位/纠正权限含动作、proprioception、人工介入点和完整轨迹，与当前前缀 Monitor 不同；这可以产生不同问题设置，但少权限本身不是优越性证明。若目标是 credit assignment，应采用同动作权限的公平对照，而不能只比检测字段。

### 4.6 SOLE-R1：事实/反转教师和时序推理训练的强覆盖

SOLE-R1 v2 §2.1 用目标、近期帧及上次预测输出变化推理与进度；§3.1.2 仿真从 privileged 几何状态生成进度/模板解释，真实示范用时间序，反转片段继承原时刻监督形成负进展；§4 SFT + RLVR，部署奖励模型固定。附录 J 有真实非专家轨迹，K 说明全参数训练。它覆盖事实教师、反转监督和 advance/regress 推理，不能称现有训练只靠最终成功。[SOLE-R1 v2 §2–4、附录 J/K](https://arxiv.org/html/2603.28730v2#S3)

当前官方模型仓库提供推理、8B 权重与训练数据链接；README 声明完整训练数据约 2TB，可流式读，且公开测试视频/输出链接。本轮只读材料未下载这些资产。[SOLE-R1 官方模型仓库](https://github.com/Philip-MIT/sole-r1-model/tree/1c4f3f8340b45fbee5bd5c303fc41ed53072fbbf)

**结论：**“用更多事实信息教师监督 causal prefix student”不能仅靠 teacher/student 命名区别。延迟的新可见证据与合成/privileged 教师的标签可用性不同，仍需核查同机制与实测可辨优势；目前未确认独特方法。

### 4.7 不同名称的同机制约束

| 工作 | 本轮读到的直接事实 | 对 B 的作用 |
|---|---|---|
| RUDDER，§3、附录 A2.8 | 回报预测与连续预测差分构造 reward redistribution；讨论后状态解释掉早行动及伪贡献 | 不能把“终局转局部信用”视为新概念；需区别语义事实与贡献分析 [论文](https://arxiv.org/pdf/1806.07857) |
| TAMER，原作者介绍及 K-CAP 2009 | 学习人类即时评价模型，处理评价延迟，并按模型直接选动作 | 反馈窗口/延迟归因已有历史；它需要人工局部评价，非自动终局扩展 [原作者页面](https://www.cs.utexas.edu/~bradknox/TAMER.html) |
| PEBBLE，§4、Algorithm 2、Fig.5 | 主动询问行为片段偏好，更新 reward model 后重标历史 replay，以处理奖励变化 | 查询选择与 replay relabel 不算新机制；需要明确新的查询单位/标签可信性 [正文](https://proceedings.mlr.press/v139/lee21i/lee21i.pdf) |
| Eureka，§3.2–3.3 | 固定 LLM，依据策略训练中的 reward components/fitness reflection 进化奖励代码 | 监督者改善不限神经权重；执行性能闭环修改代码已存在 [正文](https://arxiv.org/html/2310.12931v2#S3) |
| ProgAgent，§3.3–3.5、Algorithm 1 | 奖励模型在线 push-back 正则，PPO、coreset replay、SI 保留旧任务 | 持续进化+防遗忘已覆盖；正文真实机器人叙述与§6未来部署表述存在张力，故不据此给强真实证据 [正文](https://arxiv.org/html/2603.07784v1#S3) |

这些是本轮明确读到的机制，未把二手综述的功能列表当成实测。传统过程也能解释本项目的需求，不必把所有贡献包装成 TTT。

## 5. 逐项重合矩阵：从建议变成问题

| 候选问题 | 输入与输出 | 监督/更新 | 最近方法 | 重合等级 | 剩余区别必须证明什么 |
|---|---|---|---|---|---|
| B0 终局位训练 VLM reward，随策略演化 | g + 视频窗 → 成功概率/奖励 | 终局位、TD、LoRA，与策略交替 | eVTA₀/RLER | 高度重合 | 新标签/机制/适应目标及公平闭环优势；仅任务集不同不够 |
| B1 不训练 reward，历史成败修正分数 | 视觉状态 → potential/delta | 结果支持库、底座冻结 | HiRE | 高度重合 | 目标关系条件下库标签与局部作用失配，有效处理与成本收益 |
| B2 少量示范/反馈自动写提示 | g + prefix → 二值或多类判断 | prompt 迭代，权重冻结 | Demo2Reward | 二值设置高度；多类部分 | 少量局部标签的跨对象/环境迁移；非单纯 prompt engineering case study |
| B3 成功内坏段定位并纠信用 | 含动作、介入/本体信息 → segment + critic correction | progress model、偏好/Q correction | PACT、RUDDER | 问题高度；当前权限部分 | 无介入视频前缀下何种监督可替代，且真的帮助策略而不制造伪信用 |
| B4 新可见事实监督过去前缀 | g+prefix → 原子事实/关系/撤销 | 延迟视觉核验，少量复核，再 adapter/head 更新 | SOLE-R1 的教师与 temporal监督；CoTTA/PEBBLE 的更新 | 部分重合/新机制待确认 | 合法回填边界、查询效率、同预算胜于静态重训/检索/提示 |
| B5 无标签 TTT 改变化感知 | g+prefix → state/effect | 自监督 adapter 更新 | TTT/Tent/CoTTA | 范式成熟，机器人任务部分 | 辅助任务与目标标签相关，抵抗事实/目标反例；本项目尚无证据 |
| B6 仅逐次追加记忆和规则 | g+prefix+历史案例 → 判断 | 无梯度、人工校正库 | HiRE、Demo2Reward、Eureka | 部分/高度依设置 | 超出已有库/提示方式的独特需求与实测，不因称监督者进化而新 |

未搜到完全同名方法不等于不存在；“待确认”仅表示当前核查尚不能封闭创新判断。

## 6. 值得保留的研究候选与合法监督

### B4：延迟证据与少量局部核验的流式事实适应（有条件保留）

研究问句可以写成：**初始化后，在每个任务仅允许少量局部纠错的情况下，哪些执行后可见证据能训练下一次的前缀状态/关系 Monitor，使其在新物体/新环境中减少撤销漏检，而不牺牲旧知识？** 这保留当前输入义务，又允许训练。

先将“事后证据”分四类，而不是把所有结果当真值：

1. **当前/后来清楚显示的事实**：可以标后来那个时刻；回填早期状态只在已知该状态持续、无中间变化且身份可绑定时成立。后来看到物体在盒内，不充分推出前一被遮挡时刻已放入。
2. **独立传感器/仿真真值**：在训练可用，但部署输入不能暗中拥有同权限；评价时单列 privileged teacher 设置。
3. **执行终局位**：监督最终结果或成功概率；不直接监督每段 help/harm/reversal。相同物理前缀后续可成功也可失败，不能让后续偶然结果“改写”发生过的事实。
4. **本模型自己的高置信判断**：是伪标签，不能因终局成功自动升级成正确局部事实。只有独立核验/交叉证据支持才进入可靠监督集；其覆盖率与错误率均应报告。

最低实现选择：冻结视觉/VLM 底座，训练小型 state/relation head 或 LoRA；与只更新阈值、检索库和提示并排。不要一开始上全参数训练、多个教师与 world model。先可解释清楚标签，才比较更新机制。

对 B4 的贡献标准不是“加入回填模块”：必须证实**标签来源/可用时机**与旧方法不同，在相同人工分钟数或局部查询数下，对未来执行的独立局部标签与下游动作筛选/恢复有收益。若只是拿到更多正确标签，胜于不拿标签的 baseline，不足以说明机制贡献。

### B3 的替代设置：固定技能库中的局部恢复选择（可与 C 相接，暂缓主攻）

若实验资源允许，可提供“尝试技能后，入口/承托/抓持是否保持”的验证结果，学习技能后果和恢复适用性。策略冻结，Monitor 输出技能切换/拒绝建议，避免同时更新大策略与大评价器造成归因不清。

它变成 action/skill 条件预测时属于 C；只对已经发生的局部关系进行修正则属于 B。需要把请求输入扩到候选技能/已执行动作，明确不能在原无动作接口下称 action advantage。与 PACT 相比，不使用人工介入动作时监督更弱，完整论文须证明真实/仿真可迁移的替代监督。

### 不保留为主贡献的方案

“终局成功给全前缀正标签”“LLM 自己总结错误后继续训练自己”“给 reward model 加 FIFO/replay”“换强模型/换 LoRA/称 TTT”均应暂缓。它们要么标签义务不对，要么被上述工作高度覆盖，要么尚未排除确认偏差与数据量解释。

## 7. 最低成本、能区分竞争解释的诊断设计

下面是**尚未执行的设计**。数字是可调整的初始预算，不是样本复杂度/论文充分性保证。

### 7.1 先判断是否真的需要局部监督

从三类已有机制（入口、承托、障碍）迁移到至少两个新对象/场景版本；先构造 24–48 对短轨迹，以 episode/场景划分，避免同视频前缀跨 train/test。每对控制相同目标和近似终局：

- 成功单调 / 成功含撤销再恢复。
- 失败含有效准备 / 失败无有效准备。
- 同视觉变化配两种目标，作用正负/无关翻转。
- 早期不见、随后可见事实 / 同早期前缀却不同后续（检验非法回填）。

人工独立标注指定帧状态、身份、关系变化、撤销和完成时刻，允许 unknown；局部作用由至少两人按同合同复核，记录分歧。终局位另标。终局成功判断准确不代表局部标签准确，两个分母分开。

对照：强冻结 VLM 直接前缀读出、当前简单 state/relation 基线、eVTA₀ 目标义务匹配的成功概率、SOLE-R1/ARS 的 progress/delta、HiRE potential/delta；对于不同输出，预先固定映射与阈值，在开发集调。不要在测试例上逐个读解释“算对”，也不要把不能映射字段自动算错。PACT 只在提供它所需输入的扩展组运行/比较，或明确它不是同权限 baseline。

**支持继续：**在完成判断相近的情况下，局部撤销/准备标签仍有稳定且可重复差异；并且 differences 影响固定筛选/恢复接口。**降级：**强冻结/公开模型已能覆盖，或分歧主要来自参考标签含糊；此时 B 的新机制需求不成立，应改监督定义或只做应用基线。

### 7.2 再判断执行反馈能否合法提供局部标签

固定流顺序，先让旧模型作预测，再公开当前 episode 结束后允许的反馈，随后更新。下一个 episode 才评估更新收益，严格 **predict → reveal → update → next episode**。报告事后整段分析与线上前缀预测两个通道；过去预测不允许用新标签重算后替换原结果。

组别按反馈权限递增：F0 无反馈；F1 只终局；F2 终局+延迟可见证据（合法回填约束）；F3 终局+少量局部人工纠错；F4 privileged/完整局部 oracle 作上限。F4 的优势不能被归因于 F2 方法。

必须比较：终局直接广播局部标签、eVTA 式成功概率自举、只可信局部锚点更新、选择性回填、同预算随机局部核验。终局广播是受检的失败基线，不是预设待发布方法。查询预算可以先用 0/8/32/96 个局部纠错，也统计实际标注分钟数、拒答/复核及 VLM 调用时间，避免“一个标签”复杂度不同。

**支持继续：**F2/F3 的标签在独立真值下准确，既保留成功内撤销也保留失败内准备；反馈预算曲线优于终局自举和随机核验。**降级：**合法回填覆盖率很低、伪标签错得更自信、结果只由新增人工信息解释，或成本接近全面重标注。

### 7.3 排除“在线只是多看数据”和遗忘

固定同一 stream 与标注预算，比较静态初始化；所有已到达数据的累计 batch 重训；提示校准；关系检索记忆；简单 head；LoRA；提出的更新机制。均只使用该时刻已到达反馈，不能给静态/离线对照未来数据，也不能给在线方案更多优化步。另设最终全数据 oracle 离线组作上限，清晰标注其额外未来权限。

分两类 shift：外观/相机变化且语义关系相同；语义/目标变化且外观近似。只有第一个改善可能只是视觉 domain adaptation；第二个有助区分目标关系更新机制。设置旧任务→新任务→旧任务 return 流，固定未参与更新的旧任务遗忘集；测新任务增益、旧任务退化、错误更新后恢复速度与 calibration。置信阈值不在测试流反复调。

**支持继续：**过去已标注例重训的上限对照、提示/库和轻量 adapter 都不能解释全部收益，且多流顺序下旧任务稳定。**降级：**在线和累计同预算重训等效；只有已见对象记忆收益；改善以大幅遗忘为代价；更新后高置信错误增长。

### 7.4 一个下游接口足够先验证

最低成本选择固定技能/脚本：Monitor 在“继续放入/先开盖”“继续放置/先恢复承托”等少数分支控制切换，策略底座冻结；分别报成功率、无效恢复次数、额外步数及 inference latency。或在同规模动作片段库筛选/加权后训练固定 BC 配方，匹配保留动作数与数据多样性。这能排除纯评价指标提升但无用途。

完整 B 论文如选择 RL，需要独立成功判定，不可拿更新中的 Monitor 自评分当最终 success；同时监控 reward hacking、replay旧奖励重标、评价器/策略更新 cadence、种子与任务。更新奖励和更新策略形成非平稳闭环，PBRS 与经验 relabel 已有理论/工程先例，不能只引用势函数名就认为所有动态更新已保策略最优性。

## 8. 原策略、Monitor 底座、可训练部分分别更新什么

| 阶段 | 机器人策略 | Monitor 底座 | 可训练/可变部分 | 可支持的结论 |
|---|---|---|---|---|
| 首轮离线流式诊断 | 冻结或读已有视频 | 冻结 | 阈值/库/提示/head/LoRA，各组独立 | 标签合法性与未来预测适应，不宣称闭环机器人收益 |
| 固定技能闭环 | 技能权重冻结，高层分支会变 | 冻结 | 选定最小更新部件 | Monitor 的输出改变执行，有可归因恢复收益 |
| 筛选后 BC | 离线按固定配方训练 | 冻结 | Monitor 在筛选前已适应或固定 | 数据筛选价值，不是在线 RL |
| 奖励共同演化 RL | actor/critic/残差等按算法更新 | 基座冻结为宜 | head/LoRA/库随反馈更新 | 动态 reward + policy 的系统收益；需要奖励更新消融 |
| 全参数持续学习 | 可固定或更新 | 更新 | 多模态主体与输出 head | 算力/遗忘/工程成本最大，当前基础不优先 |

世界模型造数据、未来表征和实际结果监督要分账。生成后果不是真实结果；图像编辑正负标签由目标状态决定；它们可补充输入但不能替代真实局部校正的可信性证明。

## 9. 成本与是否形成论文

| 工作量 | 先验证所需 | 完整论文通常新增 |
|---|---|---|
| 数据 | 小块新场景配对轨迹、事件/结果标注 | 多任务/对象/视角/扰动、混合质量轨迹与任务级划分 |
| 标注 | 选定帧事实、局部作用分歧复核、反馈分钟数 | 完整预算曲线、跨任务协议与独立评价集 |
| 算力 | 固定模型推理与轻量更新对照的设计；本轮未训练 | 数个 adapter/head 对照、多次流顺序/种子；RL interaction 会成为主要成本 |
| 策略集成 | 固定技能分支或固定片段筛选 | RL 的 actor/critic/replay 与奖励非平稳处理，或更多技能恢复泛化 |
| 论证难度 | 能否得到可信局部反馈；公开模型是否已解决 | 区别于 eVTA/HiRE/PACT/SOLE 的机制、同预算增益、闭环价值 |

有成熟仿真/策略管线和可获得独立局部反馈时，B 的排名会升高；只有当前短视频例和少量 API 预算时，A 的基础监督诊断应先行。若资源充足但核心方案仍是 terminal TD，不会自动降低撞题风险；更多算力不能代替问题区别。

## 给主报告的简洁建议

与师姐讨论时可以直接说：**B 的大方向合理，但普通的“终局结果+reward LoRA+交替策略训练”已被 eVTA₀/RLER 覆盖。先从 A 得到能绑定时刻、对象和关系的可靠监督，再做反馈预算受限的流式纠错。我们要检验局部撤销/准备是否与成功概率存在实际需求差距，以及事后可见事实如何合法生成局部监督；如果静态重训、提示或支持库已经解释收益，B 就降为系统配套。**

可以保留 B4 为有条件第二候选；B0/B1/B2 作为强基线；B3 如果确实能拿到动作/介入反馈且策略 RL 管线成熟，则转为更明确的信用分配/恢复问题；B5 当前缺少与本项目标签同向的实证，不应因 TTT 名称优先。
