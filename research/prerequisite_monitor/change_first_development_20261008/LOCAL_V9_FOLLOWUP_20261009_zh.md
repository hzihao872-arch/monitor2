# S1 失败后的本地修订：v9 候选

日期：2026-10-09。此文件记录 S1 之后的本地尝试，不改写 S1 真实模型结果。

## 已定位的问题

- v8 的相邻帧差分按运动强度取候选，机械臂的较大运动会占据裁剪名额。A/E、B/E 的目标结构在首末状态有可见差异，却没有优先的局部对照图；S1 的 V1 原答主要描述机械臂和方块。
- S1 的 768 输出 cap 常截断 V1。1536 cap 的八次诊断全部生成完整 JSON，但仍有四次前后证据时间倒置。由此可分开处理长度与时间绑定，不能把调高 cap 当作语义修复。

## 本地做过的修订与检查

- 目标盲采样增加首尾持久差异候选，优先使用前后同一局部区域的裁剪；至多合并两个足够大的局部连通区域。原有中段覆盖和瞬时变化候选继续保留；相机明显位移时不提出该首尾候选。
- V1 提示列出实际展示的完整帧 ID 和毫秒时间，明确 `before_refs` 必须早于 `after_refs`，提醒检查非机械臂结构的首末状态。V1 输出上限从 768 改为 1536；目标盲 V1 仍不接收目标文本。
- 对 18 条已暴露开发视频的 CPU 审读保存在 `private_eval/review_v4/`；A/E、B/E 的首尾候选优先，A/R、B/R 无首尾候选。新匿名输入 `model_input/pilot_v6/` 的 A/E 裁剪直接显示盖板开到闭，B/E 裁剪显示承托板沿轨道位移。这是像素输入检查，并非模型识别成功证据。
- `python -m unittest discover -s experiments/prerequisite_probe/tests/change_first -v`：39/39 通过。脚本假后端用 v9 输入完成 8 查询、80 次阶段请求，80 个阶段载荷均通过合同；该结果仅检查流水线。`verify_bundle.py`：`valid=true`。包 `packages/pilot_v9.zip` SHA-256 为 `06554cba6d46c71247f7cfcabd3b51da7bf2538d4ecef5427549568fba082004`；冻结身份见 `protocol_freeze.json`，旧 v8 身份见 `protocol_freeze_v8.json`。

## 仍未解决或验证

- 还没有对 v9 发起真实模型调用；不能断言 V1 会识别开盖、承托板移动，或三臂判断会改善。
- 首尾差异也可能来自未识别的相机变化、遮挡或光照，以及机器人停在不同位置；现有启发式只减轻一部分风险。首尾相同的可逆事件仍依赖中段帧和原候选。
- 下一步应在新的真实请求预算下，先做 A/B 的 E/R 小门控：分别审阅结构变化召回、时间引用有效性和错误结构候选，再决定是否进入完整三臂比较。原 96 次上限已用满；不能把旧账本复用为 v9 试跑。
