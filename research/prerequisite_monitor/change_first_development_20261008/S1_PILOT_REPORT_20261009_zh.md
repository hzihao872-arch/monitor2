## 第一失败点与视觉审读

1. **768 输出预算首先挡住了 V1。** v8 七条三臂查询中，六条 V1 都生成到 768 token 上限；其中五条 JSON 被截断，另一条虽完整却有倒序时间引用。只有 A/G 可进入有效的 C4/D4 全链。直接比较后续三臂状态会混入上游失效，不能当作方法优劣。
2. **加长输出解决解析，未解决时间绑定。** V1-only 诊断八条均未触及 1536 cap（输出 427–978 token），八条 JSON 都完整；A/R、A/H、B/G、B/R 的前后引用时间倒置，严格合同有效率 4/8。A/R 和 B/G 把早期相似姿态的帧当作后来“回到原状”的证据，说明模型混淆了外观相似与事件时间。
3. **可解析仍不等于抓到关键结构。** 对已暴露 A/E、B/E 的人工粗读：V1 叙述主要围绕机械臂和小方块，未清楚提出盒盖入口开启或承托板位移；而 CPU 联系表的首、中、末帧可见这些结构变化。这是当前最直接的研究瓶颈。该粗读不是双人标签或正式召回率。
4. **目标先行对照也会编事件。** v8 的 A/G 首块里，C4 与 D4 四阶段 JSON 有效；K4 在 L4 引用了不存在的变化 ID，因此该槽无效。模型对完成状态的表述仍需人工核对图像，schema 通过只证明引用和格式合法。

## 结论与下一门槛

服务器、模型加载、证据隔离、请求账本、断点续跑与封存链条在真实 8B 上可运行，显存低于预警线。**方法效果未得到支持**：当前 V1 的格式长度、时间顺序和对入口/承托结构的关注不足；不能宣称变化先行优于 Robometer、直接法或目标先行法，也不能据此进入盲批和策略学习。

下一步应在本地修 V1 的紧凑输出与严格时间窗口，优先区分非机器人结构的持久变化、纯机械臂移动和遮挡；对 A/B E/H/R 的原答做独立审读。新方案必须另冻版本、在新请求预算下先过小样本门，再比较完整三臂。提高 token cap 本身不是视觉正确性修复。
