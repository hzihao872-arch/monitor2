# 本地实现决定与边界（2026-10-08）

1. **数据身份。** 原 `dev_v2` A/B 各九段经源 manifest SHA 和实际视频 SHA 对齐，共 18 条不同 RGB 视频。条件映射和源路径只在 `private_eval/source_inventory.json`；S1 从每组 E/H/R/G 各选一段、统一 14 秒。公开包使用随机匿名查询 ID，保留旧材料不覆盖。
2. **前缀。** 制包时只物化 `≤as_of_ms` 的 PNG；推理端只接收该包。超过 2 FPS 的源按不高于 2 FPS 的固定时间步扫描；旧 1 FPS 不插值。非整数截止保留之前真实帧，不编造当前帧。每张图、裁剪及访问都有哈希和时间；同前缀换未来的程序测试要求同签名。
3. **候选。** 低分辨率亮度中位数校正差分、连通区域和时序分散排序，最多三候选；六个均匀时点先占全帧额度，余位给运动锚。相位相关位移只用作相机运动风险提示；候选附稳定端点。超过三段独立运动事件时标溢出，V1 不可声称覆盖完整。前版 A/R 漏中段的审读结果保留在 `review_v1`；最终在 18 段上生成 `review_v3`。算法仍可能偏向机器人运动，视觉正确性待真模型和人工核查。
4. **共同像素。** V1/V3 每次最多八张 512×384 全帧与四张 256×256 自动裁剪。三臂收到同一取证集合；V3 重新从像素文件读取并写新访问日志。V1 无目标；V3 只见结构性绑定及中性问题，屏蔽 V1/L2 的作用解释。
5. **三臂。** D4/K4/C4 共享一次 V1 原答；K4 的槽2只见初始中性场景，槽3重新见共同像素。`KPLUS4` 可在槽2见共同变化；`D4DIRECT` 的首视觉槽可见目标，均只作后续强对照入口。D4DIRECT 仍用同一紧凑视觉 schema，正式比较前需在 S3 报告其真实强度，不能拿仅赢 K4 作完整方法优势。
6. **合同。** 模型只填短 JSON；宿主验证 exact fields、枚举、引用、时间、完成/就绪/部分分离及撤销引用。`unknown` 为合法认知值；无效 JSON、引用及预算故障单列。事件 ID、当前确认时间和第一失败点由宿主补齐，不让模型发明审计元数据。`stage_schemas.json` 是 JSON Schema 导出，运行时另有语义验证。
7. **运行。** 账本先 fsync 记 issued，再记原答与实耗；未有 durable 答案的已发请求视为 ambiguous，不自动重试。请求上限按 issued 计；同身份完成记录可续用；代码或提示变动触发新的 run 身份。模拟结果标记 `scripted-mock-no-model`。
8. **评价。** 私有评价按实体/时间先匹配，再评作用；漏检/unknown/invalid 留在可审定分母。物理真值与视觉可判性分层；当前没有两位独立人审，故软件和 S1 接口检查不升级成方法性能结论。
9. **S1 资源。** 名义 8×3×4＝96 槽；共享 V1 后完整执行预期 80 次真实请求，上限仍是 96。每槽 token 上限来自蓝图。只读预检后，在 2 小时总窗口及 15 分钟封存缓冲内运行，系统性故障即时停止。没有任何本地 8B 实测吞吐或质量结果。
