# 变化先行 Monitor：本地先行开发与分阶段验证实施计划

> **For Codex / Claude：**在新对话中使用 `superpowers:executing-plans`，按本计划逐任务执行；核心行为采用 `superpowers:test-driven-development`。用户已选择新对话执行，不必再询问执行方式。阶段汇报用于展示证据，普通本地开发不需要逐项确认。

**Goal：**把已完成的变化先行蓝图落成可审计的最小系统，先在本地完成不需要大模型的开发与检查，再通知用户打开现有服务器，用有上限的小试跑决定是否继续。

**Architecture：**严格前缀输入 → 目标盲变化候选与视觉提取 V1 → 变化与目标的局部关系判断 L2 → 新上下文重新读取像素 V3 → 受约束读出 L4 → 程序校验与归档。使用同一底座顺序调用，先比较共同感知、共同证据的 D4/K4/C4，保留强直接法与强目标先行法作为后续必要对照。

**Tech Stack：**Python 3.12、现有 OpenCV/Pillow、标准库 unittest/JSON/hashlib；真实模型适配现有 Transformers 与 Qwen3-VL-8B-Instruct。本地使用脚本化假后端验证软件行为，不下载大权重、不要求本机跑 8B。结构合同可使用已有 JSON Schema 库；缺少时只补轻量依赖并记录，不为本计划重建整个环境。

## 2. 开发者先建立的直觉

以“把蓝块稳定放在高位目标区”为例：先从视频发现板移动了；再问这项移动是否可能提供支撑；然后回看板的位置、目标足迹和稳定性，允许推翻“提供支撑”的猜想；最后报告有利、无关、阻碍、部分准备或看不清。物体已经放好是另一条完成证据，不能因准备关系解析失败一并抹掉。

实现不是把四段提示词简单串联。必须解决：移动的是否同一物体、遮挡是否伪变化、开后又关如何记撤销、多变化是否截断、视觉核验是否真的看图、没有证据时是否停止推断，以及基线是否获得了同样的观察机会。第一版的价值是让这些错误可定位，而非预设复杂流程一定更强。

### 2.1 第一版范围

- 一个共享 8B 底座、顺序调用；不同时加载四个模型、不搭多智能体平台。
- 每个查询独立重建截至 `t` 的事实。历史语义输出只归档，不输入下一查询；允许复用目标盲、因果的 CPU 采样缓存。
- 模型输入只有目标原句、RGB 前缀、固定通用能力。仿真真值、路线名称 E/H/G、正确变化、标签、未来视频长度和事件时间不能进入模型包。
- V1 无目标；L2 只围绕实际变化；V3 隐藏先前作用标签与置信度并重新读取图像；L4 无新图像，不创造新事实。
- `goal_done`、`direct_ready`、`partial_preparation`、事件作用、`net_effect`、`reversal` 分开；没有可信数值标定就不输出百分比进度或训练奖励。
- 第一版不做语义记忆、多模型调度、训练检测器、全任务图、在线机器人控制、RL。

## 4. 固定接口与几个容易出错的决定

### 4.1 请求、证据、事实和输出

| 对象 | 必需内容 | 禁止或限制 |
|---|---|---|
| 查询 | `query_id`、匿名 `clip_id`、`as_of_ms`、目标、能力版本、前缀包哈希 | 不带路线/标签/最终总长；`clip_id` 与目标不暗示真值 |
| 证据句柄 | `evidence_id`、实际时间、`as_of_ms`、帧哈希、可选裁剪边界、来源句柄 | 程序生成；时间≤t；不能由模型编造路径 |
| 访问记录 | 请求ID、阶段、句柄、实际像素哈希、时间、像素与token成本 | 同图重读允许，但 V3 必须有新访问记录与新图像载荷 |
| V1 | 中性初态≤6条、变化≤3项、实体引用、证据、覆盖缺口 | 无目标、无有利/有害标签；漏检与无变化分开 |
| L2 | 每变化≤2个假说，总≤6；中性核验问题、可推翻条件 | 不新增“已发生事实”，不展开全任务树 |
| V3 | 每个 test 在 before/after/current 的真假/unknown、证据、变化核对、完成事实 | 不接收 L2 的作用标签、解释和置信度；不奖励 |
| L4 | 假说结果、事件、三种状态、净作用、撤销、未解决项 | 每个判断必须引用可用的已核验事实 |
| R | 字段有效性、失败码、事件快照、成本、原答引用 | 模型不可填写审计元数据；不整体丢掉独立有效字段 |

模型三值使用字符串 `"true" / "false" / "unknown"`，不要混用 JSON boolean。完成后的就绪/准备字段按蓝图使用 `not_applicable`，并明确条件。`unknown` 是有效认知输出；`invalid_json`、`invalid_reference`、`budget_exceeded` 是工程故障，不得相互替代。

事实键建议由宿主生成 `test_id + "@" + at`（例如 `T2@after`），避免同一 test 在前后两时刻重名。宿主还需验证 test、实体和证据均来自本查询合法集合；字符串形状正确不等于引用有效。此命名是本计划的实现细化，W1 冻结后使用。

解析采用单一完整 JSON、明确枚举、长度上限和额外字段拒绝。原答一字不改留存。首个固定四调实验不自动追加修复请求；缺失依赖就短路并记未执行槽成本为0。可执行的独立完成核验继续。因失败少用了调用也要报告，不能只统计成功链。

### 4.2 前缀、图像包和公平输入

制包器逐帧读取到合法截止时间，生成独立前缀图像清单；解码器为了解码读取压缩流并不等于未来帧可成为算法输入，候选器和模型不得接收截止之后的已解码内容。对于带重排序的编码，按展示时间戳过滤后才交给下游。不得从全片计算“最佳关键帧”再截前缀。

首轮公共取证在模型运行前冻结：同一查询所有方法 V1/V3 获得相同图像集合。L2 的测试可关联这些句柄，但不能在主机制实验中给 C 额外清晰图。关系驱动的自适应补图留到系统实验另测。V3 无法从共同图包判断的问题必须 unknown，不能偷偷换图。

V1 和 V3 各最多8张全帧512×384、4张裁剪256×256；这是图像像素上限，不是保证能放进token预算。少图时不重复填充。每阶段实际processor token超限时，按预注册、各臂一致的删减顺序重新构造请求；保留初始/当前全帧和时间覆盖，并记录删减与覆盖不足。仍超限则记录故障，不调用超预算请求。不要截断模型 JSON 后手工补齐。

### 4.3 多变化和失败的确定性规则

- 变化超过3项：目标盲排序、保留全帧、标记 overflow。不能因未覆盖全部变化就断言整个视频“无关”。
- 无变化：保留当前完成判断；零事件不是漏填有利标签。观测覆盖不足与确实无变化分别输出。
- 遮挡/相机运动：候选器只标记风险，VLM允许不知道；不把大像素差直接当物体状态改变。
- 先开后关：中间事件和撤销必须可表达；净作用可能不变，不能只看末帧。
- 同时有利和有害：保留两个事件或 mixed，不能通过固定数字相加抹掉冲突。
- 延后才获得证据：当前可确认“截至现在”的情况，但不得篡改之前保存的判断快照。

```python
def test_future_changes_do_not_change_prefix_package(self):
```

### S3：强对照与必要消融

先跑D4-direct与K+4，防止靠弱对照形成结论。实现D1并绘制质量—实际GPU秒/token—覆盖率前沿；D2或C2压缩只在有明确成本需求时扩展。四调用上限相同不代表实际等成本，差异>10%时需邻近预算点比较或明确写不等成本，不能靠无意义填充补齐。

最多从蓝图§9预选6项有针对性的消融：去关系、去视觉核验及其等额像素自检对照、同上下文核验、首末帧vs时序、公共裁剪vs无裁剪、目标/变化置换或中性提示。具体6项在看该批结果前冻结，不能只报告有利的项。ARS-prefix最多6调用作为改编参照，官方27B/完整轨迹设置不可混称同预算。

视觉核验要统计“改对”和“改错”的净变化，也要比较覆盖；大量unknown导致的表面精度提高不算净收益。若收益完全来自更清晰图像，应把结论收缩为取证改善。

**开发停止：**最多两轮有明确第一失败点归因的实质方法修订；仍不能解决E/H/R，或强D/K同成本更好且oracle无可修复增量，就接受简单方案、停止变化先行优势主张。

### S4/S5：方法冻结与真正未见评估

1. 形成`METHOD_FREEZE_zh.md`与哈希清单：最强D/K/C、提示、阈值、采样、预算、标签、主指标、统计单位、停止规则；旧A/B及所有已见材料全归开发。
2. 新布局/资产/初态为cluster，含多个目标/视频/前缀；至少两个新机制，不能只换颜色。模型侧匿名封存，不接触真值和未来；开发者见过的探索批不能再称确认盲批。
3. 探索情景12 clusters×8视频—目标×4前缀；确认情景独立48 clusters，同条件。前缀选择采用预先秒表规则或独立截断，不能按事件真值取最容易时刻。
4. 按cluster配对bootstrap、两个主要差值校正、逐族结果、覆盖与完成非劣共同报告。候选方法门：主端到端作用宏F1比强D/K提高≥0.08且校正区间下界>0、覆盖≥80%、完成召回非劣3个百分点、完成误报增加≤3个百分点。样本量不足以判断非劣则结论未定，不能用两个旧G都对替代。
5. 根据功效/区间精度与预算在开跑前定样本量；12/48是成本情景，不是自动满足统计功效。不得因中途显著或好看临时停样；预算停止明确标为未完成。

研究结论用下列层次，不能跳级：

1. **软件检查通过：**边界、接口、失败与预算能正确执行。
2. **真模型接口可用：**在指定8B/硬件上跑通，小样本未发现阻断问题。
3. **开发有收益：**对已见A/B和交叉任务、同输入同实际成本有可检查改善。
4. **未见机制有收益：**方法冻结后独立评估支持主要指标及覆盖/完成保护。
5. **下游有用：**同训练预算真实策略成功率提升。

前一层是后一层的必要准备，不能替代后一层证据。
