# 想法冻结：从已发生的变化判断桌面操作任务进退

- 日期：2026-10-08
- 状态：**研究问题、推理边界和主要信息流已确认；方法细节、有效性与创新性仍待研究验证。**
- 用途：交给下一段对话研究可审查的架构蓝图；蓝图确认后再实现。本文件不启动模型评测、训练或服务器任务。
- 优先级：继承[原研究冻结文件](RESEARCH_IDEA_FREEZE_20261008_zh.md)中的问题、对象、输入边界与原始证据；若先前的[实施计划](../../docs/plans/2026-10-08-change-guided-task-knowledge-monitor-plan.md)或[架构备忘](../../docs/plans/2026-10-08-change-guided-architecture-design.md)存在“先从目标反推可能前置条件”的主路线，以**本文件的变化先行路线**为准。先前文件的实验事实不因此失效。

## 1. 要回答的问题

**桌面机械臂的行为已经发生；给定最终目标和截至当前时刻的单视角 RGB 视频，monitor 能否判断视频里实际发生的变化是帮助、妨碍、撤销了任务进展，还是与任务无关？** 首组任务包括开盒/开入口、建立承托，以及抓取、搬运、放入、稳定放置。Monitor 先评价轨迹，将来才考虑用其评价筛选或加权数据、提供奖励，训练更好的机器人策略。它不负责先规划出完整操作序列。

“事后评价”只表示动作在当前时刻之前发生。对时刻 `t` 的任何判断，模型只能访问 `t` 及此前的视频，不能借离线完整视频偷看未来。正式推理输入限定为：最终目标文字、截至 `t` 的 RGB 视频前缀，以及固定的通用任务/机器人能力约定。不得提供人工正确变化描述、场景专用关系、正确裁剪、准备动作清单、仿真状态、真值事件时刻、未来帧、未来结果或成功示范。制作标签时可在模型输入之外使用仿真真值和续行试验。

## 2. 本轮最终确认的信息流

当前受控视频的环境变化通常较集中，因此先研究如何从视频里抓住**已经发生的变化**，再讨论它与目标的关系。不要从目标出发，枚举所有可能的前置条件，然后在视频里逐一寻找；这种主路线会引入大量与本次行为无关的猜测。

```text
截至 t 的 RGB 视频前缀
  → 发现并定位实际、持续的变化，保存变化前后视觉证据
  → LLM 关系推理：实际变化 + 最终目标 + 可见上下文 + 通用能力
       → 提出这次变化对目标可能有利、有害、无关、只完成部分准备或尚不能判断的假说
       → 指出必须在画面中核查的条件和可能推翻假说的证据
  → 重新读取前缀内原帧/裁剪进行视觉核验
  → 输出已核实的状态、任务作用、撤销及证据/不确定性
```

**LLM 组件明确放在“实际变化被视觉提取之后、最终视觉核验之前”。** 它的主要职责是判断**这项已观察变化**与最终目标有什么关系，而不是自行编出场景变化、生成完整任务树或直接把合理故事当视觉事实。核验之后可以让同一 LLM 基于已核实事实完成简短读出。逻辑阶段需分开、证据需可追溯；是否使用同一模型权重、多轮调用或不同模型，是蓝图阶段要比较的工程选择，不预设庞大多智能体架构。

变化提议先来自视频前缀，例如稳定的变化前后画面对照、局部区域对照、对机械臂遮挡与短暂运动的排除。当前固定机位可允许简单起点，但**固定变化区域不是给模型的真值框或事件提示**。提议阶段可以没有变化、可以有多个变化，也可以标记对象/端点不确定。只有发现变化之后，目标与目标区域才进入关系推理和核验。将目标先行生成条件列为公平对照，不作为本方法主线。

## 3. 一个例子与必要区分

目标是“把蓝块稳定放在高位标记区域”。视频显示一块板被推向该区域，蓝块尚未移动。先确认板的实际位移和停留位置，再由 LLM 提出“这可能建立放置支撑”的局部命题；视觉核验要检查板是否真正覆盖目标足迹、是否稳定停在需要位置，以及还有没有明显缺口。板只是在旁边移动，应判无关或不确定；撤走已有支撑可能是有害；不能因为检测到运动就自动给进展。

至少分开记录：`goal_done`（目标已完成）、`direct_ready`（当前是否具备直接执行目标物操作的可见条件）、`partial_preparation`（部分准备）、变化对任务的作用，以及 `reversal`（先前进展是否被撤销）。盖子开了一部分，可能减少剩余准备工作，但未必直接就绪；不能简单归零或说已完成。开后又关，末端净状态可能回到初始，但中途的进展与撤销仍需记录。单视角遮挡、稳定性或替代路线无法判断时，允许 `unknown`，同时报告覆盖率。具体标签合同、数值读出和奖励映射尚未冻结。

## 4. 文献定位：借鉴什么，差别在哪里

- [VICtoR](https://arxiv.org/html/2405.16545v2)以任务知识、视觉状态和进度奖励处理长时程操作。其任务知识生成会使用目标、给定对象/状态/动作词表和环境信息；不能把它简化成“人工写死全部步骤”。本项目要检验的差别是：**先由视频发现具体已发生变化，再仅围绕此变化生成局部任务关系并核验**。这种信息流是否带来独立收益仍是待验证假说。
- [ARS](https://arxiv.org/html/2609.34484v1)提供免新增奖励模型训练的事件提出、自适应取证、独立核验及下游数据筛选参照。ARS 面向离线完整轨迹，允许未来证据回看过去；本项目正式评估是逐时刻视频前缀，必须重新设计取证边界。多次调用或加一个“验证器”本身不是创新。
- [ReSET](https://arxiv.org/html/2509.18043v1)和 [SOLE-R1](https://arxiv.org/html/2603.28730v2)可用于校准主动准备、视频前缀进度及训练型对照。不要因文献相近就改掉当前研究问题，也不要把未经同预算实验检验的信息流称为已证实创新。

## 5. 已有证据和失败，不应重写

项目已有两类开发场景：盒盖/入口 A 与承托板 B。P0 中 TOPReward 的有效准备 E 在六个指定配对为 0/6 胜；Robometer 在 B 的三个 E 配对为 3/3 胜，所以不能说既有方法普遍不会识别准备。旧 Qwen v0.2 的 E/H 关键区分为 0/4；P6 标签表面为 14/18，但 E/H 仍 0/4；P5 视觉结果只有 9/18 可解析且存在状态错误。旧自动关系与反主张探针因候选未通过校验，18 段都退化为相同回退文字，**不能当作已经验证了关系真假判别**。文字改写曾改善部分排序，但一般准备提醒和中性等长文字也能改善，不能将收益单独归因于正确关系知识。

这些是已暴露的开发证据，不是未见测试性能。已有 A/B 运动学预设动作和有限续行试验可以支持受控视觉评价，不能单独证明策略能学会主动操作环境。此前 RTX 5090 上 Qwen3-VL-8B 的 v0.2 记录约 162 次调用、1588 秒模型时间、峰值显存约 17.09 GiB；新蓝图须重新估算预算，不能直接承诺在本机约 8 GiB 显存复跑。服务器现况也须重新核对。

## 6. 已确认、待验证和待设计的边界

**已确认**：研究桌面操作；monitor 评价实际行为；逐时刻前缀推理；变化先行；LLM 负责实际变化与目标的关系假说；假说必须回到视觉证据核验；保留有利、阻碍、无关、部分、撤销、完成与不确定；首先研究无需新增任务专用训练的候选流程。

**待验证假说**：变化先行会比直接评分或目标先行局部知识更可靠；局部命题能降低关系臆测；独立视觉核验能纠正而不是放大视觉错误；改进能在新布局/机制及下游策略学习中保持。任何一项都不能仅凭架构图成立。

**待蓝图决定**：变化检测/切窗/遮挡处理；事实和命题的最小接口；LLM 提示及输出解析；核验怎样真正重新取证；是否共享模型和如何匹配调用/视觉 token 成本；多变化与无变化处理；`direct_ready`/部分/撤销标签合同；数值进度是否必要；场景制样、统计、停止规则和服务器预算。不要把当前备忘中的具体模块数、阈值、奖励公式视为定案。

在核对文献与项目原始材料后，先交付一份**可审查但尚不执行的实施蓝图**：

1. 精确的问题、输入/输出和前缀隔离合同，逐模块数据流、失败处理及可追溯证据格式。
2. 至少比较简洁的实现备选，并解释为何选定某种变化提取、LLM 关系判断、视觉核验和读出组合；给出示例输入、提示词、输出 schema 与一例完整证据链，但将其标为设计候选。
3. 在同一底座、同一合法输入与可比调用/帧/token 预算下，设计直接评分、目标先行、变化先行三条核心对照；加入去核验等消融与人工正确变化/裁剪的额外输入诊断上限，严格区分主成绩。
4. 最小交叉实验：同一变化换目标、同一目标换变化；从有效/无关扩展到不充分、阻碍、撤销、完成和无动作。锁定标签、成对指标、覆盖率、完成阳性及原始失败归因。
5. 已暴露 A/B 开发回归、新场景/新机制盲评、计算与标注预算、阶段通过/停止条件；评价成立后再设计等训练预算的下游数据筛选或策略学习验证。

先完成蓝图与审查，不直接实现、下载大权重、运行昂贵模型实验、租新服务器或训练策略。若简单直接法或目标先行法在公平对照中已足够，应接受该结果；若变化先行未见增益，应相应收缩方法与论文主张。
