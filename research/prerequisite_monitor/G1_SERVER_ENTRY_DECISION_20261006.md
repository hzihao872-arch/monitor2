决定：**G1 通过；仅批准在现有服务器上进行开发性试跑和原因诊断。G2 正式验证尚未批准。**

## 准入范围

仅使用 `access_gate/dev_v2` 与 `support_surface/dev_v2` 两套各九段的冻结匿名输入。按原计划依次执行：服务器只读资源预检、旧输入格式 smoke、新开发视频的 TOPReward 与 Robometer 原生推理。不得把开发结果称为未见配置泛化结果；正式验证须另行完成 G2 预注册。`dev_v1` 与中止的 A `dev_v3` 均不得进入模型推理。

## 审批依据

1. A 的实体盒底、四壁和顶框仅留一个顶孔；蓝块最小投影宽度 46 mm，大于封闭/部分开放时的 0/30 mm 净空，完整开放净空 110 mm。B 的目标高位中心在板面收起时没有承托；导轨和绿色边界在合法完整足迹之外。两机制分别完成替代路线挑战，并明确只证明“完成前必须改变必要状态”，不证明“必须先独立做准备动作”。
2. 两组各有两条抓放路线、三个成对扰动种子；开放态 6/6 达到有直接接触、松爪和稳定窗口的终态，阻挡态 0/6。每组九条件完整，只有 G 达成目标。
3. 独立读者在不接触真值的前提下，对两组的目标起末、结构状态、撤销和保持末态能否完成的九段分类均与记录一致。后续未揭盲补充给出 A 的单入口/部分开口不足/R 时间，以及 B 的板面未到目标区/无其他路线/R 时间。补充由用户转录和确认，并非读者直接签署；这一来源限制随结果保留。独立判断与作者几何论证合用，满足本计划 G1 的开发场景准入要求；不将简短的盲审理由写成穷尽的物理证明。
4. 审查时重新运行 21 项测试，结果 `OK`；重新核验冻结清单，949 个文件、`issues=[]`，清单 SHA-256 为 `be2af5aaa8afe8d32a1e5481631f190c6748b825ea7d0c8027a09d873a60534b`。两组模型 ZIP 的 SHA-256 分别为 `3e57af3072091bafbc10b81eea17d8ebd597337458cae5edd6b8433ab5842e78` 和 `3124b5117820707f3458696d4a553f0fee27d41aa969d45eca78bfd84b6cfc9d`。18 段视频逐一核得 640×480、1 FPS、15 帧；模型 ZIP 仅含数字视频、目标句和公开媒体清单。四次原生 runner dry run 各有九项视频输入、零项模型结果。

## 解释边界和后续门槛

准备结构由预设运动学轨迹与机械臂同步移动，蓝块抓放才是动态接触。这足以检验监测器是否反映可见的前置状态改变，尚不足以声称系统证明了自由动力学的准备动作、独立规划能力或现实机器人因果能力。A 的半透明侧壁、B 的导轨/边界可能影响模型解读，须在开发结果里作为混杂因素核查；盲审补充的转录来源也应明示。

G1 只解除本地制样门禁。服务器仍需先做只读预检并记录端点、资源、模型版本与权重身份；若预检或旧输入 smoke 失败，应停下排查，不得直接解释新场景分数。G2 需在看到未见配置的模型输出前，固定新配置、规模、提示、读出、指标、停止规则和重新验证的几何/可见性证据。

本审批时没有连接服务器、下载权重或产生这批场景的新模型结果。此决定文件置于冻结包之外，不改变其清单或输入哈希。
