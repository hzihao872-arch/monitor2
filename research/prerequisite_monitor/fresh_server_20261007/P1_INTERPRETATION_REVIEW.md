# P1 独立问答诊断审查（2026-10-07）

## 与研究问题对应的结论

研究问题是：只给最终目标和准备视频，模型能否把**完成前必要状态已解除**与“蓝块已经放到位”区分开，并据当前状态判断后续仍能否合法完成。P1 的单独 Qwen3-VL-8B 诊断未做到：它对两机制各 9 段的必要性问答，只在两段已完成目标的 G 回答 `yes`，对其余 **16 段全部回答 `no`**。其中两机制各有 `E`、`I_o`、`N_o` 三段在最终状态下保持必要入口／承托面开放，蓝块虽未移动，但允许后续只移动蓝块完成目标；这 **6 段开放但未完成**均被答成 `no`。

更重要的是理由：不少 `no` 回答说“视频中机器人没有移动蓝块”“蓝块仍在目标外”，把提示要求的**从可见末态出发还能否完成**答成了**视频中是否已经完成**。对两组 `E`，它分别以“机器人没有碰蓝块”或“没把蓝块放到承托面”为理由回答 `no`，没有建立“必要状态已解除 → 允许后续移动蓝块完成”的关系。这是本次问答的直接可观察错误，不需要从数值分数反推。

## 输入与封存

- P1 有独立的视觉事实阶段和必要性阶段，各有 18/18 原始模型回答、0 模型失败、18/18 JSON 解析有效。本地重新运行 `optional.seal_p1 --verify`，两份状态均为 `complete`、`issues=[]`。先前 `run_remote_extra.sh` 第一次启动曾因 shell 的 `tag: unbound variable` 停止；最终隔离重试产物已完整封存，不能把第一次失败算作模型结果。

## 视觉阶段究竟看到了什么

视觉回答多数能说出蓝块没有到位，也能描述 G 已完成；但它**没有稳定指出区分正负例的关键结构状态**。例如入口盒 `E`（`0007`）提到盒顶开放、蓝块仍在外面，阻挡静止 `N_b`（`0009`）却也被描述成顶端开放。承托板 `E`（`0008`）只说黄色平台和蓝块未放置，未说明承托板从收起变为可支撑；阻挡态的其他回答也常把黄色面描述成现成的平台。因此，视觉阶段的“JSON 有效”不等于前置状态识别正确。部分事实可能确实看错，也可能只是在开放提示下没有选出关键事实；P1 不能再细分这两种情况。

## 对 P0 的解释边界

- P1 **加强了研究动机**：一个独立、显式要求判断合法后续路线的基础视觉模型仍把“未完成目标”几乎等同于“不能完成”，并对全部 6 个开放但未完成的末态给出错误的 `no`。这正是研究希望 Monitor 区分的两件事。
- P1 **不能证明 TOPReward／Robometer 的内部错误原因**。它是另起提示的 Qwen 问答，不是两方法内部状态或因果轨迹。尤其 P0 的 Robometer 在承托板 `E` 三个配对都正确，而 P1 对同一 `E` 回答 `no`；两者并不共享可直接等同的读出。
- P1 的必要性提示和模型回答暴露了强烈的**任务理解／反事实问法混淆**，同时视觉事实没有稳定提取关键结构关系。当前不能断言只有视觉错误，或只有因果推理错误；需要基于冻结 P1 原答做更细的人工证据审读，并用 P2 检查 P0 排序稳定性。
- 这仍是两套开发场景，不是正式 G2 未见验证；不得以 `16/18 no` 推断任意模型、任意机器人任务的总体失败率。
