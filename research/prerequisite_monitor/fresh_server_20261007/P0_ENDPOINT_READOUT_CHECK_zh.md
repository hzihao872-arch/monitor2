# P0 末帧读出核查（事后描述性，不改主指标）

从已验封的 [`analysis_p0.json`](local_results/p0/analysis_p0.json) 直接比较同机制同方法的 t14 原生值，检查原先 `末三秒中位数 − 首三秒中位数` 是否可能单独制造 TOPReward 的 E 失配。表中均为 E 减对照，正数才是希望方向；这是事后诊断，**不替代预注册六对**。

| 机制 / 方法 | E−S t14 | E−I_b t14 | E−N_b t14 |
| --- | ---: | ---: | ---: |
| access_gate / TOPReward | −0.625 | −0.250 | −1.000 |
| support_surface / TOPReward | −0.750 | 0.000 | −0.500 |
| access_gate / Robometer | +0.005657 | −0.017775 | −0.050989 |
| support_surface / Robometer | +0.133428 | +0.175920 | +0.092005 |

TOPReward 的 E 在两机制 t14 仍没有超过 S 或 N_b；因此只换成末帧绝对值不会消除主要失配。A 的 Robometer 末帧 E 对 S 优势极小，且仍低于 I_b/N_b；B 的优势保持。这不证明模型没有编码前置状态，因为原生输出可能有别的读出方式，也不能把事后末帧读出当作新主指标。P4 改变任务文字可继续检验是否对明确写出的前置关系敏感；P5 检验独立基础 VLM 在指向关键结构后是否能正确描述可见状态与前瞻路线。
