# Process reward methods: executable mental models

## ARS — [paper v1](https://arxiv.org/html/2609.34484), Appendix A/C/D/F

Target is progress along an observed offline trajectory, not `q_action−q_control`. Video+instruction enter a subagent, which proposes events and requests temporal windows/crops; a separate main context rechecks claims, revises event boundaries, then writes a progress curve. The event tools, prompts and harness are inference-time rules around a Qwen3.6-27B model. Optional terminal outcome, visual reference and external reward audit are **not legal** for this Monitor. Its wrong-object mismatch truth uses instruction swaps and video evidence, not same-start obstacle removal. App. F short benchmark ablations remain close (full FPSR 0.918; without verification and inspection 0.915); the larger downstream long-task comparison also changes query/token use. For B+, ARS should grant limited preparation progress only if the bar–source/destination relation is verified; B0 should reject the temporary lift after endpoint revisit; U0 should not credit movement outside the critical region; H− should allow regression. Occlusion or ambiguous alternate route warrants uncertainty. Its code URL was unavailable via `gh repo view` on 2026-10-05, so there is no executable official commit or result. Falsifier of claimed insufficiency: official ARS, with only legal video/goal inputs and recorded budget, gets all main paired directions and valid relation evidence on admitted mechanisms.

## Robometer — [paper v2](https://arxiv.org/html/2603.02115), §III and App. D

Progress and success are separate heads on task-conditioned video features. Expert-frame progress supervision, comparison preference, and suboptimal trajectories train the model; success labels/trajectory pairs are training privilege, not extra inference inputs. The official code at local `352d160389daa964788de1ec933d1925f3a6de4f` decodes 1 FPS into `ProgressSample`, collates task/video, then returns per-frame progress and success arrays. `+Preference` in Table III improves ranking while pure progress may retain higher correlation on one set; that ablation does not target prerequisite causality. In our B+/B0/U0/H−, expected event delta signs are +/0/0/−, but this is a desired evaluation interpretation, not the paper's guaranteed signal. Existing source-side B+ pairings are positive; target-side ones are not. No entity/relation trace means no internal first-error localization. Strict unmodified source failed dtype; local outputs are `robometer_pr33_compat`, not original. Falsifier: compatible native model repeats valid pairwise ordering on new admitted source and target mechanisms; then any general deficit claim must narrow.

## TOPReward — [paper](https://arxiv.org/html/2602.19313), §3 and App. B/E

For every prefix, the model scores `log p(True | video prefix, statement that task is completed)`. The method needs no extra reward training. It can read goal+preparation video, but it has no explicit prerequisite state variable. A B+ prep video may still look incomplete and remain flat/down; B0/U0 moving objects can fluctuate; H− may not be negative; G+ should increase as completion becomes visible. App. B chooses `True` for separation and App. E tests prompt/template choices; neither tests our six-condition causal construct. Original Qwen code at `4877a0ee5098cbec18485125466631b1dcc4a573` already produced 54 indexed development curves. Six-family B+ rankings fail while G+ anchors succeed, a task-scope result rather than a claim that TOPReward's completion score is defective. Falsifier: on new mechanisms its same native prefix statistic repeatedly separates all pairs, in which case the old failure is scene-specific.

## ROVER / ProcVLM / PRIMO R1 — [ROVER](https://arxiv.org/html/2508.01943), [ProcVLM v2](https://arxiv.org/html/2605.08774), [PRIMO R1 v2](https://arxiv.org/html/2603.15600)

ROVER recursively sets a current subtask and a sliding frame window, then combines per-subtask progress; its ablation separates window from recursion and its limitation states a wrong subtask can misalign progress. ProcVLM predicts stage/remaining atomic actions before progress; its training has synthesized procedure labels and a value head, while its native inference only needs video+goal. PRIMO R1 uses initial frame + sequence + current frame from the same video and emits reasoning plus a number; its post-training uses progress/outcome rewards. For B+, these can count cleared obstruction as a step; B0 must check the endpoint, U0 must avoid inventing a needed step, and H− must admit regression. The concrete failure risk is treating movement-like appearance or a generated “clear bar” subtask as progress without verifying the final relation. ROVER local example needs external VLM service; ProcVLM and PRIMO dedicated weights are absent locally. Falsifier: a native, legally supplied method with existing weights correctly handles new source/target six-conditions and cites valid evidence; D2/structured candidate then need to beat it on matched cost or narrow the claim.
