# TOPReward（Chen et al., arXiv:2602.19313v2）

一手：[论文](https://arxiv.org/html/2602.19313)、[官方代码](https://github.com/TOPReward/TOPReward)。对视频每个前缀，计算指令完成陈述之后 `True` token 的对数似然；它预测的是 VLM 对“该前缀完成指令”的支持，不是后续固定控制器成功概率。无额外奖励训练；不同骨干可用。论文展示 success detection、奖励排序和策略学习；附录解释 `True` 单 token 的选择。

路径：15 帧→1..15 前缀→相同指令/完成判断模板→Qwen 前向 loss→原始前缀对数分数，可另作视频内归一化。项目主要读原生 `prefix_rewards`，不以每条视频 min–max 当主指标。代码 `qwen.py` 157–290、327–391；本地适配器只有解码与参数传递。旧六族开发分数：B+ 对 B0/U0 全部逆向但 G+ 全部正向，说明在本受控视频里完成 token 信号未可靠反映准备可行性；不能据此称其自身训练目标失败。

理论推演：B+ 如果不接近已完成最终放置，分数可能不升；B0/U0 可能因红物体动了而误升；H− 未必下降；G+ 应明显升。反证：在全新机制中原生前缀分数稳定给 B+ 正确排序、H− 正确方向及 G+ 正向，旧现象范围就要收窄。已运行原版 Qwen3-VL-8B，证据见本地六族报告；新方法不能读取这些分数作为提示。
