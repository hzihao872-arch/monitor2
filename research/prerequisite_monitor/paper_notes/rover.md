# ROVER（Schroeder et al., arXiv:2508.01943v2）

一手：[论文](https://arxiv.org/html/2508.01943)、[官方源码](https://github.com/Philip-MIT/rover-vlm)。目标文字 `g` 与逐帧视频观测作为输入；逐帧输出描述和进度百分比，论文以仿真目标几何距离/状态构造进度真值，非固定续行策略的 `q`。543 个 RoboCasa 视频跨 27 任务，含专家与受扰轨迹；另测 OpenX 视频。

路径：帧序列→提示拆子任务→当前子任务滑窗逐帧解释/估完成比例→子任务完成时递归进入下个→按子任务比例组合总进度。官方 `rover_model.py` 是 API 调用＋文本解析，无训练权重；`run_eval.py` 抽至 30 帧并将进度与真值相关。Table 1 的 100 真实＋100 仿真视频错误分类中，ROVER 仍有 9%/7% 错误子任务与 3%/4% 冗余子任务；这不能直接换算本题正确率。论文的滑窗和递归消融支持其对长视频幻觉的帮助。

B+ 若被拆成“清障”且完成可正向；B0 可能因看到移块便把子任务标完成；U0 可能先错误引入无关清障子任务；H− 可能没有负进度的显式机制。关键不是是否会拆解，而是是否检查目标可行性变化。本项目不能把“递归步骤图”当新贡献。反证：在无步骤提示的完整六段，仅以官方允许输入运行，若它自发提出正确隐含准备、稳定区别 B+/B0/U0/H−，则我们的结构化检查价值需缩小。

执行边界：官方 README 要外部 VLM API，当前未付费运行。静态代码发现递归调用签名疑点，详见 `code_traces.md`；不能因静态疑点直接断言方法无效。
