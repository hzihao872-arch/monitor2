# ProcVLM（Feng et al., arXiv:2605.08774v2）

一手：[论文](https://arxiv.org/html/2605.08774)、[项目/代码](https://github.com/ProcVLM/ProcVLM)。这是训练式程序进度模型：从原始操作轨迹用大 VLM 标注阶段、完成状态和剩余动作，按子任务结构与阶段内视觉变化构造密集目标；模型先推剩余动作，再预测连续进度。ProcCorpus-60M/ProcVQA 提供训练监督。真值是合成程序标签和论文各基准，不是固定控制器 `q`。

路径：原始轨迹→自动程序标注/筛选→ProcVQA 预训练＋精炼→推理时阶段/剩余动作→进度 value head。论文 §3、§4 评估程序理解、奖励辨别和 RoboTwin 策略收益；并做 value head 消融。它已经覆盖“计划步骤或剩余动作辅助进度”，故不能将这一点本身算新颖。

B+ 可能被识别为完成必要准备；B0 可能被视觉移动误识为阶段完成；U0 可能出现无关动作被算入步骤；H− 应识别阶段回退。论文未直接用本项目配对检验这些预测。官方代码 `evqa/inference.py` **确有视频＋目标原生入口**：最近8帧滑窗，`procedural_c.txt` 只将任务写进提示并要求先推剩余动作。它可以按本题许可输入成为强基线；若正确，则 H 的额外质疑未必有用。`extract_progress` 失败时原代码沿用上一个数值，评估必须把 `parsed_progress=None` 当无效输出另报，不能让填充值掩盖失败。权重未下载，**未运行**。
