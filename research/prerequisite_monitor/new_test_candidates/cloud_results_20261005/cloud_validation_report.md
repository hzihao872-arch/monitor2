## 旧开发诊断与方法冻结

最初 v8 的 8B smoke 中 D/P/F 都因证据 JSON 形状和空字段无效，原文保留。仅使用旧六段修输出格式后，v9 达到 24/24 结构有效，却仍将 B+ 准备动作判零。v10–v12 对旧段的通用前置条件措辞逐次检查，v12 的 P 对 B0、H− 报假进展，F 仍多退回最终目标关系。自由描述诊断表明 8B 能说出“红块从托盘移走”，却把未在目标中点名的红块判为无关；先描述动作再自由推理仍没有修复。

替代候选 `action-caption endpoint-slot v1` 于**新测试推理前**冻结，见 `../method_freeze_caption_slots_v1.json`。第一调用只描述视频中的动作和起终位置，第二调用只从该描述抽取源／目标区域的非目标物与目标完成六个三值事实，程序固定比较；两次调用、8 帧一次、文本一次，每次最多 192 输出 token。旧开发六段为 B+ 正、B0 零、U0 弃答、H− 负、G+ 正、N0 零；其中 B0 的占据事实虽错、方向碰巧正确，N0 的零依赖字幕的静止陈述。其“25”只是暂定证据索引，不是成功率或因果必需性。

## 现成原生基线

TOPReward 与 Robometer PR #33 dtype 兼容版各在每组 6/6 生成有效 15 点曲线；按预冻协议比较各自原生曲线首 0–2 秒和末 12–14 秒的中位数差值，不跨模型数值归一。两者都在两组赢 G+>N0，隐含条件排序如下：

| 机制 | TOPReward：B+>B0 / B+>U0 / H−<N0 | Robometer：同序 |
|---|---|---|
| s01 | 负 / 负 / 平 | 负 / 负 / 负 |
| s02 | 负 / 胜 / 负 | 负 / 负 / 负 |

这是两种原生不同语义的奖励曲线，不可用绝对值互比。逐段曲线、数值、日志及评分在 `server_results/` 和 `s01.native.score.json`、`s02.native.score.json`。

## 事后视觉诊断与下一步

所有新测试原始结果封存后，才对 s01/s02 的 B+、H− 各取 0、14 秒做指定空间关系问答。这是**事后诊断**，不进入任何盲测得分。s02 取物端：B+ 起点完整帧错判横杆未跨蓝块，源区裁剪正确判跨越；终点两视图均判未跨；H− 起点两视图判未跨、终点两视图判跨。s01 放置端：完整帧对 B+ 的“跨托盘→未跨”和 H− 的“未跨→跨”均正确，而固定托盘裁剪在有横杆时反而误判未跨。精确像素裁剪、提示、原文与帧哈希见 `new_tests/server_results/*crop_posthoc.jsonl`。

可证伪的下一版方向是：先提出来源／目标处的候选几何关系，再按该关系选完整帧或局部视图进行**明确的起终状态核查**，保留视图矛盾为弃答；最后才做可达性和替代路线挑战。不能把已评分的 s01/s02 用来再宣称下一版盲测，下一版必须另造完整正反配对机制。尤其需要检验“裁剪改善源端却损害目标端”的现象能否在新几何原型重现。当前任何方法均未证明因果前置条件识别有效。
