0051: Human demonstrations for robot imitation learning often contain mistakes and corrective behaviors, such as imprecise grasps, object misalignment, unstable contact, and repeated attempts. While these segments are commonly treated as noisy or suboptimal data, they provide valuable evidence about when execution deviates from a desirable path and how task feasibility can be restored. However, existing reward and value models often rely on monotonic progress assumptions, which capture coarse task advancement but may overlook local execution errors and corrective behaviors in imperfect demonstrations. In this work, we propose ReTVL (
0052: ReT
0053: ry-Supervised
0054: V
0055: alue
0056: L
0057: earning), a framework for learning mistake-sensitive value functions from mixed-quality robot demonstrations by leveraging retry events as sparse supervision. ReTVL captures the local degradation-and-recovery structure around mistakes by combining global progress calibration with local pairwise preference learning induced by sparsely annotated retry keypoints. The learned value model is then used to reweight demonstration chunks for downstream behavior cloning, reducing the influence of harmful execution errors while preserving useful corrective behaviors. Experiments on real-robot manipulation tasks show that ReTVL produces more fine-grained value estimates than progress-based baselines and improves imitation learning from imperfect demonstrations.

0145: Addressing this issue requires explicitly accounting for retry events during value learning.
0146: Such retry events are common in robot demonstration data and often incur little additional labeling cost, yet they are typically ignored or discarded.
0147: An intuitive observation is that a retry event often indicates that execution has deviated from a desirable path and is subsequently brought back through corrective behavior.
0148: Rather than treating such retries as noisy or low-quality data, we leverage them as sparse supervisory signals for value learning.
0149: Specifically, the temporal neighborhood around a retry reveals a local value structure: value should decrease as execution drifts toward a degraded state that requires correction, and increase as corrective behavior restores task feasibility.
0150: These retry events therefore induce local pairwise preferences, allowing the value model to capture value drops and rebounds around subtle execution errors without requiring dense frame-level progress labels.
0151: Based on this insight, we propose ReTVL, a new value learning framework that leverages retry events as sparse supervision.
0152: Specifically, ReTVL constructs state pairs around retry events and introduces a preference-based loss to train the value function.
0153: We find that this design is critical for accurate value estimation, whereas a naive strategy that simply penalizes retry events within conventional progress-regression-based value learning performs poorly.
0154: We evaluate ReTVL on four real-world robot manipulation tasks against three representative value estimation methods: TOPReward

1061: Experiments
1062: Our experiments aim to study whether ReTVL can produce mistake-sensitive value estimates for subtle execution errors and thereby improve downstream policy learning. Specifically, we organize our experiments to answer the following questions:
1063: (Q1) Value Evaluation:
1064: Does our value model better capture sublte
1065: execution errors and show value changes than progress-based reward or
1066: value models?
1067: (Q2) Policy Learning:
1068: Given the same mixed-quality demonstration dataset,
1069: can our learned values identify more useful trajectory segments and improve
1070: downstream imitation learning?
1071: (Q3) Ablation and Analysis:
1072: Which components of ReTVL are most important, and why does it improve value quality and policy performance?
1073: Baselines.
1074: We compare ReTVL against the strongest available reward and value models
1075: that can provide dense scores for robot learning. These baselines cover three representative forms of dense supervision for robot learning: zero-shot VLM-based progress estimation, general-purpose robotic reward modeling, and progress-supervised value learning.
1076: •
1077: TOPReward
1078: [
1079: 14
1080: ]
1081: directly prompts a pre-trained VLM to judge whether
1082: the task is completed and use the normalized probability of the “true” token as a progress score.
1083: •
1084: Robometer
1085: [
1086: 29
1087: ]
1088: is a general-purpose robotic reward model trained on large-scale robot data. It uses trajectory rewinding and trajectory-level preferences to learn rewards for failed and suboptimal executions beyond progress supervision.
1089: •
1090: RECAP-Value
1091: denotes our implementation of the value component in RECAP
1092: [
1093: 3
1094: ]
1095: . It uses Monte Carlo step-to-success targets to learn a progress value function with a discrete value head.
1096: Tasks and Datasets.
1097: We evaluate our method on 4 real-robot manipulation tasks using a Piper robot
1098: arm, as illustrated in Appendix A.
1099: Pick up Spoon
1100: is a
1101: relatively simple pick-and-place task, while the other three tasks are
1102: long-horizon tasks covering different manipulation challenges:
1103: Stack Blocks
1104: requires fine-grained alignment when stacking three blocks,
1105: Fold Towel
1106: involves deformable-object manipulation, and
1107: Open Drawer
1108: requires interacting with an articulated object.
1109: For each task, we use 30 annotated trajectories to train the value model and evaluate the learned values on 20 held-out trajectories.
1110: The trained value model is then used to score a separate mixed-quality dataset for downstream policy learning, consisting of 200 trajectories per task except
1111: Pick up Spoon
1112: , which uses 80 trajectories.

1372: Conclusion
1373: We presented ReTVL, a retry-supervised value learning framework for robot imitation from mixed-quality demonstrations.
1374: By using sparsely annotated retry keypoints as local supervision anchors, ReTVL combines global progress calibration with retry-induced preference learning to capture both coarse task progress and local mistake-recovery structure.
1375: The learned values further improve downstream behavior cloning by down-weighting harmful mistake segments and emphasizing useful recovery behavior.
1376: Real-world manipulation experiments show that ReTVL improves local mistake sensitivity over progress-based baselines while maintaining competitive global value estimation, leading to better imitation learning from imperfect demonstrations.
1377: These results suggest that corrective behaviors are not merely noisy artifacts, but useful supervision for learning mistake-aware robot policies.
1378: Limitations
1379: ReTVL still has several limitations.
1380: First, we assume that values around retry events follow a local degradation-and-recovery pattern.
1381: Although this is more flexible than a monotonic progress assumption, it may not cover all real-world correction patterns, such as exploratory retries or unsuccessful corrections.
1382: Second, we currently use the learned value model only for offline behavior cloning reweighting, and have not explored broader closed-loop policy improvement or online RL settings.
1383: Third, our experiments are conducted on a limited set of real-robot tasks rather than large-scale datasets, so broader evaluation is needed to assess generalization across more tasks, robots, and demonstration styles.

2065: A.1
2066: Value Model Training
2067: Data preprocessing.
2068: All value models are trained and evaluated using the same local 5 Hz data
2069: protocol. The raw robot trajectories are recorded at 30 Hz and then downsampled
2070: by taking every sixth frame. We use this lower frame rate because adjacent 30 Hz
2071: frames typically show very small visual changes, which adds temporal redundancy
2072: and can make value estimation more sensitive to frame-level noise. Since the four tasks have substantially different horizons, we do not
2073: truncate trajectories to a fixed length after resampling. Instead, we keep all
2074: usable 5 Hz frames and construct fixed-length inputs later during sampling.
2075: Each trajectory used for value-model training contains the task instruction,
2076: primary-view images, wrist-view images, the success/failure outcome, and retry
2077: keypoints. For the value-model test set, we additionally annotate bad-action
2078: start points and back-to-normal points, which are used only for analysis and
2079: evaluation. In all value-model training and evaluation, the model takes only the primary
2080: camera view as visual input.

2893: Appendix C
2894: Retry Annotation Analysis
2895: C.1
2896: Retry Keypoint Definition
2897: A retry keypoint marks the start of correction after a local execution error,
2898: rather than the mistake onset or the completion of recovery. In our setting,
2899: retry events mainly capture localized but consequential execution errors that
2900: require immediate correction, such as misaligned grasps, missed grasps, or
2901: inaccurate placements.
2902: We do not treat all execution errors as retry events. Instead, we only
2903: keep cases with a clear localized correction signal. We exclude long off-task
2904: error segments, such as grasping the wrong object and later completing the
2905: task, collisions with the environment, failed corrections that do not improve
2906: the state, and irreversible failures such as objects falling outside the
2907: reachable workspace. This keeps retry supervision tied to recoverable local
2908: execution errors rather than broad trajectory-level failures.

3096: Ablation Visualizations
3097: We further provide representative value-curve visualizations to complement the
3098: ablation results in Sec. 4.3.
3099: Figure
3100: 6
3101: shows that the drop-regression baseline without
3102: preference loss does not reliably align value drops with annotated retry events.
3103: Although this variant is trained with manually injected drops around retry
3104: windows, its predicted value curve often exhibits misplaced or weak drops on
3105: held-out trajectories. This suggests that directly shaping the absolute progress
3106: target does not necessarily teach the model to recognize the visual meaning of
3107: local execution errors. Instead, the model may fit the injected numeric pattern
3108: in the training data without learning robust visual cues for mistake states.
3109: The visualizations also show that removing soft-window weighting or absolute
3110: calibration leads to less stable global progress estimates. Without soft-window
3111: weighting, retry-related supervision is applied uniformly across approximate
3112: retry neighborhoods, which can create sharper conflicts with the absolute
3113: progress target near window boundaries. As a result, the value curve becomes
3114: more oscillatory even on successful trajectories. Without absolute calibration,
3115: the model relies mainly on local retry-induced preferences and loses a stable
3116: global progress anchor, which similarly increases value fluctuations and weakens
3117: the monotonic progress structure.
