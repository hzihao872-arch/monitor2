# 隐含前置条件证据与原因定位执行计划

日期：2026-10-06。工作目录：`D:/monitor2`。这是研究执行计划；当前只完成本地审查，没有运行 L1/L2 或新增模型结果。现有冻结配置 `research/prerequisite_monitor/development/architecture_next/causal_rescue_20261006/design.json` 和两份输入包保持不变。先读[现有视频审查](../../research/prerequisite_monitor/development/scene_video_next/flat_red_only_six_candidate_v1/independent_scene_and_intervention_audit_20261006.md)。

**目标：**在目标指令不写准备步骤、模型只看目标句和准备视频的条件下，检验原生进度信号是否区分真正解除必要条件、看似动作但条件未解除、无关动作和制造阻挡；用受控干预缩小错误原因的范围。

**证据原则：**先证明每个场景的自然目标、物理必要性和视频可观察性，再看模型。原生分数与显式问答、固定控制器成功率、仿真真值各有不同含义；任何一个不能替代另一个。

## 视频来源决策

**主证据自己在现有 ManiSkill/SAPIEN 环境生成。** 自制才能从同一仿真快照分叉、保持指令与相机一致、保存合法终态/碰撞/状态证据、构造运动相近但结果不同的对照，并在打开模型输出前冻结所有视频。ManiSkill 官方接口支持自定义任务、成功条件、相机和轨迹重放；现有项目已有制样与隔离目录，可继续复用而不下载新大数据。[ManiSkill 自定义任务](https://maniskill.readthedocs.io/en/latest/user_guide/tutorials/custom_tasks/intro.html)、[轨迹重放](https://maniskill.readthedocs.io/en/latest/user_guide/datasets/replay.html)。

**公开视频作外部补充。** RoboCAS 含目标检索和移障等复杂操作，RoboCasa 有组合任务及逐帧子任务标注，可用于检查真实场景类型和外观迁移；目前没有核实它们提供本研究需要的同初态有效/无效/逆转分叉及严格必要性真值，故不把其普通成功视频直接纳入主因果表。[RoboCAS 原论文](https://arxiv.org/abs/2407.06951)、[RoboCasa 数据说明](https://robocasa.ai/docs/build/html/datasets/datasets_overview.html)。若之后发现现成数据确实满足全部准入条件，再逐项审查并补入，不能预设不可用。

## 阶段 3：补足能区分原因的干预

在观察新一批模型输出前另立 `diagnostic_v3.json`；不编辑 v1 冻结设计。每次只改变一个主要信息因子，配相同任务长度/对象提及的控制。诊断不计入自然目标原生得分。

| 对照 | 固定什么、改变什么 | 能缩窄的解释 |
| --- | --- | --- |
| C0 对 C1 | 都提红块；C0 只说红块可见，不给红块与目标的必要关系；C1 给关系 | 区分“被点名而注意到红块”与“得到因果关系” |
| 同一视频的明确红块任务 | 视频、帧不变；改为直接描述红块移出/入框的合法任务 | 若连显式状态变化也不反映，先查视觉/指令读出；任务更换不作原目标成绩 |
| 事实文本替换 | 在显式问答链的后一步，分别提供已验证正确/有意错误的红块前后状态；视频仍相同 | 测下游方向是否受对象状态信息控制；这是特权诊断，不能证明原生模型内部曾有该事实 |
| 关系文本替换 | 保持正确的可见事实，分别提供正确/错误的“该状态是否阻止合法终态”判断 | 测显式进度判断是否真正使用因果关系 |
| 采样或固定视野 | 保持任务、场景、时刻对应；改变可见分辨率或采样，并独立审全帧 | 区分采样漏事件、目标过小与后续推断；裁剪/重渲染分别命名，不混作单因素 |

**出口：**每个错例记录最早可观察错误层、成功和失败的救援干预、仍未排除的替代解释。Q1 全对而原生分数错，只能说“信息可在该提问接口提取，原生分数没有稳定体现”，不能说已窥见内部表征。

## 阶段 4：设计真正的新视频与未见验证

1. 为当前平面占位机制补一个**同 blocked 初态的无效单程动作**：红块被明显推动但仍侵占唯一合法落位；匹配有效移出的长度、时段和视觉显著性。现有 B0 是解除后复原，继续保留作可逆性测试，不拿它代替无效尝试。
2. 至少开发一种**不同物理关系**，优先有唯一开口的刚性容器门/闩或需部署的承托面。每种单独证明目标语义、必要状态、替代路线、可操作性和主视角可见性；被排除的原型也记录。不得用换色、镜像、随机种子算第二机制。
3. 在新机制中加入同一视频改变目标相关性的设计：两个外观接近的目标区域，动作固定，最终目标指向被打开或未被打开的区域。先证明两种目标句自然且对应终态明确；它专测目标关联，不混入现有六段分母。
4. 用开发机制确认接口和预定规则后，**先冻结**模型、提示、帧、评分、纳排和目标样本数，再生成独立的未见配置。以完整配置/机制为统计单位，报告逐机制配对方向、效应差、平局和不确定区间；扰动种子只用于物理稳健性。样本数按开发波动和可承担预算预先计算/确定，不把固定 7/8 描述性门槛当统计证明。
5. 主方法保持原生推理；显式关系提示、问答、额外视角仅作为单列诊断。若主方法在未见条件下排序正确，就按反证报告；若只在一个机制失败，只主张该机制内的限制。

**出口：**至少两个质不同且合格的机制、完整正反对照、未见模型输出和预定分析都齐，才讨论共同问题。若物理必要性或视频可见性失败，先修评测；若原生方法通过，保留负结果。
