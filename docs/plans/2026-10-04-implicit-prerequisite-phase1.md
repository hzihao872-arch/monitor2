## 1. 本阶段究竟要证明什么

给定仅描述最终目标的指令 `l` 和一段完整离线轨迹视频 `v[0:T]`，判断一个非目标物体动作是否**改变了完成目标的机会**。在固定后续控制器类别、动作预算和环境扰动分布下，若移障使目标从不可达变为可达，或显著提高后续成功率，它是有效准备动作；仅仅移动了障碍物、抓取动作流畅、画面有变化，都不足以给进度。

本阶段检验两种方向相反的错误：

1. **漏判**：有效移障后进度不升，或与无效动作无法区分。
2. **误奖**：未解除阻断、移动无关物体时进度上升；妨碍目标的动作得到正向进度。

这里的“因果”是**相对于明确规定的后续策略与预算**的干预效果，不宣称物理世界中存在与策略无关、绝对必要的步骤。主张必须由新测试集和实际模型输出支持；ARS 已发表的错误物体结果只能支持研究动机，不能证明上述两类错误必然出现。

## 2. 详细核对 ARS：可借鉴处与不能照搬处

### 2.1 ARS 原研究做了什么

依据 [ARS 正文 §3–4 与附录 A、C、D、F](https://arxiv.org/html/2609.34484)：

| 环节 | ARS 具体做法 | 对本研究的含义 |
|---|---|---|
| 输入和推理 | 主比较仅给任务指令与离线轨迹；用 Qwen3.6-27B。子代理提出覆盖全程的事件，主代理在独立上下文检查事件和边界，再据此写逐帧进度。可按需补看时间窗/裁剪；事件证据须覆盖区间及前后文。 | 这是应认真测试的强对照，不能把“事件化＋补看验证”直接作为新贡献。结果标签、参考视频和外部评分审计都是 ARS 的可选配置；主实验不启用。 |
| 准备进度 | 附录 A 的进度提示**已明确写入**“对有用的准备给有限分数”，并允许停滞、退步与事后证据回填。 | 我们要测试的是它能否根据可见证据分清准备动作是否真的解除前置条件，而非宣称 ARS 一概不给准备分。 |
| 受控数据 | ManiSkill 运动规划生成桌面双物体拾放视频；25 种物体，500 条轨迹各配正确/错误指令，共 1,000 个视频—指令样本；平均 31.7 帧。仿真特权状态核实夹爪从未靠近错误指令指向的物体。 | 借鉴“受控配对＋状态仅用于真值核验”。但 ARS 是**同视频、换指令**；我们需要**同指令、改变障碍因果角色/动作结果**，不能直接复用其标签定义。 |
| 原指标 | 正确指令上的时序排序 VOC；错误指令上，进度正增量覆盖时长的补数 FPSR；正确轨迹终值减错误轨迹峰值的 CMPG。FPSR 按原生预测时间间隔计时，CMPG 惩罚中途假峰值。 | 借鉴“正例能力＋负例抑制必须联报”及“看峰值、看事件时段”。不能把所有非目标物体动作都当作 mismatch，直接套 FPSR 会把有效移障误判为假进度。 |
| 论文结果 | 表 1：ARS 的 VOC/FPSR/CMPG 为 0.995/0.918/0.904；TOPReward 8B 为 0.930/0.368/0.685，32B 为 0.945/0.383/0.756。附录 D 同报正例增量覆盖 EPCR，避免恒定零分伪装成高 FPSR。 | 结果限于论文的错误指令设置，不是本课题的先验效果或新测试集基线。 |
| 强对照与局限 | ARS 在短语义不匹配测试中的几种流程删减版本接近完整版本（附录 F 表 15）；长轨迹策略学习才明显拉开。TOPReward 原生地按视频前缀逐时打分；ARS 表 1 使用各方法**原生输出点**计指标，插值只用于稠密曲线展示。 | 第一阶段要保留原生采样、原始分数、输出有效率和计算预算；短片结果不足以证明“独立验证”模块本身必需。 |

ARS 的 benchmark 只要求拒绝错误物体操作；它没有把“错误物体动作”与“虽非目标却必要的移障动作”构成因果对照。**这是现有论文的评测覆盖边界，而不是 ARS 已被证实的缺陷。**论文给出的准备动作提示使“ARS 能正确处理本题”成为必须认真考虑的竞争假设。

代码可用性：论文给出 [ARS 仓库链接](https://github.com/midea-ai/ars)，但 2026-10-04 本地 `gh repo view midea-ai/ars` 未解析到公开仓库；目前仅能据论文说明流程，不能称为已复现或运行 ARS。执行时再次核查。若仍不可用，第一批分别列 TOPReward 与 Robometer，随后补 ROVER 和直接提示对照；ARS 标记“待运行”，不以自写近似版冒称原版。

### 2.2 要继承的设计原则

- 固定目标语义，配对改变单一因果条件；仿真特权信息只在制样与盲审真值层使用。
- 同时检测“正例是否获得进度”和“负例是否避免假进度”，禁止靠全程平分或全程常数获得好成绩。
- 保留原生时间戳和预测；报告局部事件窗口、峰值误奖、成对排序与输出失败率。
- 分开讨论方法效应、骨干模型效应和推理预算；记录帧数、分辨率、调用数、token 与耗时。

## 3. 零样本协议与输出对象

**评估输入**：对每个被测方法只提供同一句最终目标指令和该回合完整 RGB 视频。不得提供障碍标签、正确动作步骤、仿真状态、反事实结果、终局成功标签、示范或测试集专用提示。方法接口若强制要求 `camera_view`，适配器仅填所有回合相同、可从画面直接看出的固定视角字符串，并在记录中披露。完整视频只拍到准备动作完成和短暂稳定后的状态；标准答案用的后续成功尝试不放进评分视频，防止答案由结局泄漏。模型可利用完整视频中的后验画面确认障碍是否真正离开。

**两层结果**：① 原生进度曲线 `p(t)`（如方法提供），主分析的事件增量为准备动作稳定后窗口均值减动作前窗口均值；② 原始事件描述/分解，仅作错误诊断，不能给纯数值方法附加新要求。窗口端点依据仿真接触和稳定状态预先标出，独立于模型预测；共同采样网格用于展示，主要判定仍用原生点并报告采样敏感性。

**方法分组**：

| 组 | 方法与约束 |
|---|---|
| 第一批中的免奖励训练对照 | [TOPReward 官方实现](https://github.com/TOPReward/TOPReward)，固定 Qwen3-VL-8B-Instruct 和原生前缀评分；与 Robometer 同批运行。随后加入 [ROVER 官方实现](https://github.com/Philip-MIT/rover-vlm)；ARS 原版可用时加入最关键的强对照。另设同骨干固定直接提示作为简单对照。 |
| 第一批中的已训练奖励模型 | **Robometer-4B 必跑**，用[官方 checkpoint 与自有视频推理脚本](https://github.com/robometer/robometer)。称“对新任务零样本迁移”，逐一注明训练数据、ManiSkill 家族暴露、输入视角和抽帧；不并入“无额外奖励训练”主表。SOLE-R1 等为后续可选。 |

TOPReward 的模型家族、chat template 和 True token 对数概率映射应在开发集确定并固定；不能将每条测试轨迹分别 min–max 归一化。ROVER 官方示例需要外部 VLM 接口，执行前列实际模型、价格和预算；不能因接口便利性更换骨干后把差异全归因于方法。

## 4. 标准答案：把“必要”变成可核验的干预效果

### 4.1 受控环境与动作边界

第一批固定用 ManiSkill 自建刚体任务：Panda 机械臂、蓝色刚体目标、放置区、红色可移动挡块、限制抓取入口的静态几何和固定相机。优先几何明确的**通道/抓取入口被挡**情景，不选只有一条规划器恰好失败、其他正常路线却可绕行的场景。用 [ManiSkill 运动规划数据流程](https://maniskill.readthedocs.io/en/latest/user_guide/data_collection/motionplanning.html)生成轨迹，但障碍关系和反事实核验需另行实现；文档本身不提供本课题真值。

每个候选事件保存动作前仿真快照 `s_pre`。从同一快照分叉：执行指定移物动作 `a`；执行等时长空动作/未移走的对照 `a0`。两支在相同物理随机种子与相同后续预算下，调用**预先冻结**的目标导向继续策略 `pi_G`。`pi_G` 只允许操作目标物体，不替方法移障；另用可移障的通用继续策略作敏感性分析。这样主标签含义清楚：动作是否改善“接下来直接做目标”的机会，而不声称对任意聪明策略都不可替代。

主物理量：`q(s) = P(在预算 H 内完成目标 | s, pi_G)`。每个分叉用相同的一组扰动种子估计 `q`，主因果差值为 `C = q(s_after_a) - q(s_after_a0)`；同时记录几何可达/碰撞检查、目标物体姿态是否被意外改变、移障后物体是否重新挡回去。空动作对照解决“时间流逝本身改变成功率”的问题。另报从原始 `s_pre` 开始、将移障耗时计入总预算的成功率，避免只在动作后重置时钟夸大进度。

规划器失败不自动等于物理不可达：至少用多初始抓取姿态/路径搜索加独立碰撞检查复核，人工确认视频中障碍变化可见；仍有争议的样本标 `uncertain`，不得硬塞进主效应。标签阈值须在读取任何被测输出前冻结。**拟定初始门槛**：有效 `C ≥ 0.30` 且前后可达性证据一致；无效 `|C| ≤ 0.10`；妨碍 `C ≤ −0.30`。中间区间暂不计主分类、完整保留。先在小型制样开发集检查这些门槛是否可分、每支至少 20 个配对继续种子的置信区间是否足以定类；若不足，增加种子或取消该模板，任何调整都要在盲测模型输出前升版并留痕。

### 4.2 成对场景清单

同一场景族固定目标、指令、相机、桌面纹理、机器人起点和准备动作类型；只改变障碍的初始位置或动作终点。每个模板同时保存分叉快照、视频和状态核验日志。

| 代码 | 场景与视频中可见证据 | 预期物理标签 | 必要配对 |
|---|---|---|---|
| B+ | 挡块确实封住目标抓取入口/通道；将它移出后通道持续敞开 | 有效准备，`C > 0` | 与同初态 B0 配对，验证动作结果而非只认“移动挡块” |
| B0 | 同一阻断初态；挡块被推了一下但仍封口，或移出又弹回 | 无效，`C ≈ 0` | 与 B+ 比较；尽量匹配手臂路径、接触时长与视觉运动量 |
| U0 | 挡块原本在通道外；机器人仍作相似搬移动作 | 无关，`C ≈ 0` | 与 B+ 比较；目标、指令、视角不变，只改阻断关系 |
| H− | 初始通道开放；动作把物体推入通道，或让目标更难抓 | 妨碍，`C < 0` | 与同初态空动作/不挡路终点配对 |
| G+ | 直接抓取/放置目标、确有状态推进 | 正向能力锚点 | 防止常数曲线在前四类中看似优秀 |
| N0 | 等时长空动作或明显失败的目标抓取 | 零进度锚点 | 测自然评分噪声与时间漂移 |

第一批拟另做至少 1 个开发用几何模板；保留测试目标为 **4 个未见过的障碍几何模板 × 4 个关键条件 × 3 个初态种子 = 48 段准备动作视频**，另加 G+、N0 能力锚点。这是最小诊断规模目标，只有满足物理与视觉核验的样本才入集，不为凑数放宽规则。开发集与保留测试按**几何模板/场景族**分开，不能把同一初态的分叉视频分别放两边。刚体成立后才扩展柔性毛巾，不把柔性模拟误差混入第一轮判断。

## 5. 标注表、盲法和泄漏防线

每条样本至少含：`scene_family_id, pair_id, seed, instruction, object_ids, video_sha256, camera_config, pre/post_event_frame, action_interval, action_type, simulator_version, policy_version, horizon, continuation_seeds, q_action, q_control, C, reachability_before/after, label, uncertainty_reason, annotator_review`。内部标准答案与给模型的 `instruction+video` 清单分别存放；文件名和路径不得含 `B+`、`success` 等答案字样。

先由仿真计算候选标签，再由不看模型输出的人检查：指令是否只包含终目标、视频是否看得出挡块与通道关系、移动结果是否持续、是否还有目标本身位移或摄像机变化等混杂。对视觉无法判断但仿真有差异的样本，标为“视频不可判”，不用于主实验；它们可以留给第二阶段的信息缺失诊断。人工复核不替代反事实物理核验。

生成脚本、模板参数、随机种子、仿真/模型版本、视频哈希、剔除原因都入清单；冻结评测输入和评分脚本后才运行保留集。任何方法的测试输出都不得用于回改场景、阈值或提示。现有项目里已看过的 VLAC-Cut 洋葱例属于开发讨论材料，不进入这个新保留测试。

## 6. 评测规则：同时抓漏判和误奖

1. **事件方向表**：在 B+ 上计算有效准备检出率；在 B0/U0 上计算误奖率；在 H− 上计算相对空动作的错误正向排序率。报告每个场景族的分子/分母和逐例证据。原生分数尺度不一致，阈值 η_m 只能在各方法的独立开发集零动作噪声上一次性选定，或报告完整阈值曲线；保留集不调。
2. **成对排序**：同模板内，检验 B+ 事件增量 `Δp` 是否大于 B0 与 U0；H− 的事后分数/增量是否低于匹配空动作。报告胜/平/负及平局按 0.5 计的准确率。成对比较是主结果，因为它避免跨模型绝对分数校准争议。
3. **局部时序**：记录首次错误上升、准备动作结束后的净增量、无效轨迹全程最高假进度及其时间段；分开原生预测和仅供可视化的插值，不把“时间自然前进”当作进度。
4. **非退化控制**：G+ 必须能打出可观察的正向信号；同时报告 B+ 召回与 B0/U0 抑制、G+ 增量覆盖，防止全零输出。若方法只能给排序而非逐帧值，另列可支持指标，不强行伪造曲线。
5. **不确定性与统计单位**：每条分叉共享初态和模板，不能把帧数或种子当独立样本。先逐 `scene_family_id` 聚合，再做场景族级 bootstrap 区间；只有 4 族时区间会很粗，主要解释逐族重复方向，不做强总体显著性声明。报告方法运行重复的方差、无效/超时输出数量及完整成本。

**预定判读**：若至少两个独立场景族里，某主对照出现可复核的 B+ 漏判或 B0/U0 误奖，且 G+ 能力锚点排除整体失效，就可以说“该方法在这些受控条件下有此错误”；若几种强方法都稳定正确，缩小问题主张或改变场景，不能以原 ARS mismatch 结果代替。新方法立项须先查普通感知失败、采样遗漏与提示/骨干差异；第一阶段不宣称已找到机制原因。

**关于 H−**：许多进度模型从 0 起且输出非负，初始为 0 时不可能给绝对负增量。因此 H− 另设已有部分目标进展的初态，检查绝对回退；初始为零的 H− 只报告相对匹配空动作/开放状态的排序，并单列平局。不能把输出范围限制误报成推理失败。

## 7. 执行顺序与阶段验收

1. **先取第一组真实视频与两套评分**：按 §0 的 ManiSkill 任务制作同指令、同模板的 B+（有效移障）、B0（移动但未解除阻断）、U0（原本不挡路仍移动）及 G+（直接目标进展）；保存反事实日志。固定 TOPReward + Qwen3-VL-8B-Instruct 和 Robometer-4B 的官方提交、权重、原生抽帧/评分、预算，在这些开发视频上分别烟测并保存原始曲线。若某一方法运行失败，记录失败并先排除环境/显存问题，不把缺输出算模型漏判。之后再核查 ROVER 与 ARS 原版入口。
2. **扩成可复核小样**：把首个开发模板补齐 4 类，跑同初态分叉、多种继续种子和可达性检查；独立视频审查通过后扩到 4 个保留场景族。并仅小范围审查 RoboCAS 是否提供自然正例，不把它与受控保留集混算。建立被测输入包、隐藏真值包与剔除日志。
3. **冻结协议**：在开发集确认帧抽样、窗口、η_m、物理阈值、失败输出规则和统计脚本；将配置文件哈希、版本与日期写入运行台账。
4. **两种方法共同运行**：按冻结清单在相同视频与最终目标指令上运行 TOPReward 和 Robometer。保存原始输出、prompt、帧索引、API/权重版本、调用/token/耗时和失败原因；分别列出免奖励训练与已训练迁移结果。
5. **盲解与错误审计**：评分后才打开隐藏标签。对每个错例核对模型实际看到的帧、物理反事实和人审；不从分数曲线猜测内部推理。给出正反例视频索引、汇总表及区间不确定性。

**第一阶段交付物**：`problem_definition.md`、`scenario_manifest.jsonl`、`oracle_checks.jsonl`、`evaluation_protocol.md`、冻结配置、原始输出台账与错误分析报告。若本轮只完成计划而未运行实验，交付状态必须保持 `unverified`，不能写“问题已证实”。进入第二阶段的条件是出现跨场景、可复核且不能仅由采样/标签问题解释的剩余错误；否则先修正研究问题。
