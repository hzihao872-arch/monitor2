> **新对话执行入口。** 在 `D:\monitor2` 从本文件开始。本任务先分析上一轮封存实验的首次可见错误，再核查一手研究与官方代码，最后只实现并检验一个可证伪的最小改动。场景／视频由 `docs/plans/2026-10-05-prerequisite-monitor-scene-video-task.md` 的另一对话负责；未收到合格开发场景的 `SCENE_READY.json` 前，不从旧材料得出架构有效结论。

**研究合同：**固定桌面单机械臂、独立离线 Monitor，输入只有最终目标指令与准备视频；允许从该视频复看／裁剪。不能向模型提供场景设计图、成功谓词、仿真状态、固定续行策略、后续视频、反事实成功率、条件映射、旧分数或“红物应该先拿走”的提示。模型输出的是可核查的关系和相对进度证据／合理未知，不是精确未来成功概率。新方法与 D2 使用同一冻结骨干、帧、分辨率、视觉调用/输出上限、解析契约和评分器；实际 token、时延、弃答及语义证据质量均报告。

## 2. 阶段 A：从封存输出重做问题归因

**A1：先核原始证据，不先改提示。**对旧六段、六族、s01/s02 建逐例表：最终目标、可见 0/14 秒事实、原始模型文字、对象绑定、候选前置关系、前后关系、目标相关性、方向、证据秒数、结构有效性、弃答和成本。利用 `replay_saved_20261005.json` 和旧脚本核输出来源及 SHA；无需再次调用模型。既有重放差异为 0，若本地重放不一致，先查版本／输入，不把它归为“VLM 不懂逻辑”。

**A2：定位“首次有证据支持的错误”。**固定审查链：`物体/动作可见性 → 对象与源/目标绑定 → 0/14 秒空间关系 → 与最终目标的关联及替代路线 → 方向 → 曲线映射`。每例只把**可从原文和画面支持**的最早环节写成观察结论；模型内部未公开时写“无法归因”。同时记录后续错误，避免“只修第一个词”掩盖别的问题。若构念效度未过，模型方向与旧标签冲突只能作旧协议诊断，不能全记为模型错误。保留 s01 不移杆偏心放置候选、s02 侧抓未排除，以及 Robometer 两个源端族的正向结果作为反证。

**A3：先做错误分布与优先级。**按条件 B+/B0/U0/H−/G+/N0、目标端／源端机制、方法 D/P/F/D2/H0/caption 分组，报“多少例可归因于哪环节、多少例因场景或证据不足不可判”。把输出格式错误、关系语义错误和合理 `unknown` 分开。提出至多两个主故障假说，每个写预测、能推翻它的旧例／未来开发例和所需观测字段。例如“端点空间关系漏读”若在端点事实正确的例上仍经常误判，则不能独占解释。

**阶段 A 产物：**`stage_A_error_map.md` 与 `case_attribution.csv`（或 JSON）；原始输出路径、哈希和每一行理由可追。交付时明确“待修的是观察、绑定、逻辑还是映射”，不以总体正确率代替归因。

## 3. 阶段 B：查一手研究并真正学会其机制

**B1：以 A 的故障为检索问题。**在 arXiv、PMLR、OpenReview、CVF、论文官网与作者官方代码中查截至执行日的相关工作；技术结论以论文原文、附录和官方代码为准，二手页面只用于找线索。关键词至少覆盖 `video goal-conditioned progress / process reward`、`object-centric spatial relation before-after verification`、`robot skill precondition affordance`、`counterfactual feasibility alternative route`、`wrong-object action credit` 和 `occlusion / crop uncertainty`。追核心论文前后向引用，记录检索日期、查询、纳排理由；连续两轮没有出现直接相关新机制时可停止，不为凑篇数扩展一般 VQA。

**B2：优先复核本地已建的文献矩阵，不能重复照抄。**至少深读与 A 直接相关的 ARS、Robometer、TOPReward、ROVER/ProgressLM、一个关系／前置条件方法（如 ReKep 或关系式技能前置条件），以及从新检索发现的最接近工作。可用论文的主文、消融、失败例和官方入口互相核对；官方库不可访问要记日期与错误，ARS 官方原版未跑通就写“未运行”，不能将自写近似实现算作 ARS 原版。不得为读论文下载大权重。

**B3：每个核心方法写“可运行的心智模型”。**记录论文版本和 URL、官方代码 commit/可达状态、它预测的量、推理时实际可见的输入、训练/评测特权信息、视频选帧/裁剪、从观察到关系到分数的具体链、人工规则与模型部分。用本研究 B+、B0、U0、H− 四种情形逐一推演它应怎样处理；说明它能否排除“红物仍占位”“本来就有旁路”“错误物体也动了”，以及它何时会合理弃答。对最相关代码静态追 `入口 → 视频预处理 → 提示/模型调用 → 中间变量 → 分数 → 评测`，写确切文件、行号和不能直接移植的输入假设。至少比较三条竞争路线，并设计一例能**推翻我们声称它不足**的实验。

**B4：形成从来源到设计的决策表。**每个可借鉴点分别回答：它解决 A 的哪条已观察错误？在本任务合法输入下是否可做？需要新增视觉调用/状态/标注吗？已有 D2 是否也能得到同样收益？哪个消融可以验证增量？拒绝“论文用了事件核查，所以我们也叠多个代理”式类比；若前人已有方法在相同输入与目标上充分覆盖，应改为强对照或收窄新意，不预设必须发明新架构。

**阶段 B 产物：**`literature_update.md`、`paper_learning_notes/`、`code_trace_update.md`、`source_to_design_matrix.md`，附一手链接／版本和学习后的反证。不得把“未检到”写成“无人研究”。文献检索与代码阅读完成前不改方法提示。

## 4. 阶段 C：只选一个最小可证伪架构改动

从 A+B 明确列 2–3 个候选及取舍，再选**一个**最小改变。现有待证伪候选是：从最终目标和完整视频提出源或目标处最相关的非目标物关系；分别核实准备前后端点；关系看不清时由该关系决定是否重看同视频局部视图；完整帧与局部视图冲突则 `unknown`。这不是默认最终方案：若 A+B 显示首要错误在任务语义或替代路径推理，而非关系观察，应有记录地换候选。不得硬编码红块、颜色、目标框像素坐标、条件号或旧场景标签。不能同时叠加字幕、F、H、裁剪、投票等多技巧而无法归因。

**C1：写假说与失败预测。**给出该改动应修哪几类 B+/B0/H−，哪类会因遮挡、源端多路径或语义不定仍失败；说明 `unknown` 何时合理，何时只是逃避。指定中间输出：候选对象、源/目标区、前后关系、证据帧、关联依据、替代路线／未知理由、事件方向。不能把评测侧几何真值直接变成提示模板。

**C2：先统一共同契约，再做最小实现。**检查 `monitor_contract.py` 的三值字段、证据时间、同一关系 before/after 和已知的 `comparison=unknown` 风险；若必须修解析契约，对 D2/P/F/候选一致升版并保留旧版结果。用少量语义夹具验证结构和方向规则：无关移动 `true→true` 为零、回原位 `false→false` 为零、新增阻挡 `true→false` 为负、显式完成锚点为正、可见证据冲突为未知。夹具只验证代码行为，不当模型能力证据。避免把旧评测真值注入运行器。

**C3：预算与基线预登记。**同骨干同帧同分辨率的 D1、D2、P、F、H0 与一个候选；至少 D2 与候选要匹配视觉调用次数、每次最大生成 token、上下文轮次和可用裁剪机会。实际输入/输出 token、视频像素、帧索引、裁剪坐标、时延、失败及弃答逐次保存。若候选多一次视觉调用或多看高分辨率图，它是预算不同的附加实验，不能列作同预算主胜利。D2 需得到与候选相同的合理开发机会；TOPReward、Robometer 原生曲线另列，不与同骨干方法的绝对分数混比。F 若没有新的具体替代路线反驳就删，H 若只增加弃答就删。

**阶段 C 产物：**`method_hypothesis.md`、独立版本的新源码／提示、接口测试与 `budget_protocol.md`。在旧开发样本上只做**尚未完成且必要**的格式/局部机制 smoke；不复跑完整旧实验。旧材料用于找 bug、选候选，不称泛化。

## 5. 阶段 D：等场景线合格后才比较方法

先读取并验证 `research/prerequisite_monitor/development/scene_video_next/SCENE_READY.json`，逐项看语义审读、成功谓词、严格**状态**必要性与多路线挑战、单主视角可观察性、至少两个质不同完整六段、输入/真值隔离及 SHA。若只完成一个机制，或“严格必要”仍依赖单一中央上抓控制器，停在方法原型；不能据新分数宣称架构解决了问题。

对已准入**开发机制**运行所缺的同骨干同预算比较。运行器只能接收 `model_input/`；全部原始模型输出、实际帧/预算、错误与弃答先封存，评分器再读 `truth/`。可在开发材料上诊断和修改，但每次变更升版本，保留所有尝试，不按最好单例筛场景。按完整机制留一评估，不能把同一机制的六条件或 20 扰动种子拆作独立训练/测试。逐机制报告 B+>B0、B+>U0、H−<N0、G+>N0、关系/对象证据有效率、覆盖率与弃答、JSON 无效率、运行失败、实际成本；明确统计单元是**独立机制**而非帧或种子。至少给出候选输给 D2 的具体反例和其首次可见失败环节。

**决策门槛：**若 D2 在相同预算、相近覆盖与证据质量下相当或更好，就选 D2 并记录复杂方法无增量；若 P/F 单独足够就删 H；只靠更多 token/裁剪/弃答取胜不算架构优势。只有多个质不同开发机制同向改善、没有关键机制反向，且中间证据指向预定故障修复，才冻结候选。若方法门槛未过，保存负结果并转向评测/问题定义贡献，不造“为了成功”的盲测。

## 6. 阶段 E：冻结、交接与新盲测

冻结代码、提示、模型权重 revision、处理器、输入协议、帧/视图策略、预算、解析与评分器、主指标、弃答/失败规则、停止规则和各文件 SHA，写 `research/prerequisite_monitor/development/architecture_next/METHOD_FREEZE.json`。冻结方法可以是 D2 或更简单的 P/F；须如实命名。冻结前禁止接触新盲测分数。把冻结文件路径交场景对话，等待其依独立门槛制作全新、完整 B+/B0/U0/H−/G+/N0 的测试包。旧九配置、当前开发场景及其改色／镜像／平移版都不能当新测试。

收到盲测匿名输入与哈希后，只读核届时**已有**服务器的连接、GPU、空间、环境和已下载权重；不可访问就停在本地，不新租、不购买、不重下。先用一个旧开发样本做格式 smoke；成功后对冻结方法与同预算 D2 跑完整盲测，封存原文、实际帧、token、成本和失败，取回核哈希，最后才打开真值评分。TOPReward/Robometer PR #33 兼容版如在已有资源下可运行，可按原生语义另列；严格未修改 Robometer 原版有 dtype 故障时不得偷称其分数。ARS 官方原版若不可运行，明确写“未运行”，不可用自写近似版替代。盲测结果不反向改提示；任何修订产生新的开发轮，旧盲测不再独立。

**最终判断：**至少两种质不同、严格必要且可审的全新机制未重复胜 D2，就不宣称架构解决；若目标／必要性仍有歧义，先回场景定义；若架构中间关系仍错，回 A 的对应环节。报告每个机制的正反配对、G+ 锚点、证据有效率、覆盖率/弃答、成本、负结果及实际可支持的最窄主张。
