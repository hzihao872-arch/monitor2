# 隐含前置条件 Monitor：下一步方向诊断计划

日期：2026-10-05。工作目录：`D:\monitor2`。用途：供新对话接续，先判明**场景效度、架构假设、实现错误**各占什么，再决定是否设计新方法或租机验证。当前没有已获证实优于直接提示的架构。

## 1. 已知事实与三个竞争解释

研究合同沿用[总研究计划](2026-10-05-causal-prerequisite-monitor-research-plan.md)：固定桌面单机械臂，独立离线 Monitor；推理输入只有最终目标指令与准备动作视频，可在同一视频内复看／裁剪；输出逐时进度、前置条件、证据帧和不确定性。仿真真值、后续成功视频、旧模型分数不能进入提示。旧六段、六个旧场景族及新评分的 `tray_crossbar`、`source_bridge` 都是开发材料。

现有云端结果见[验证报告](../../research/prerequisite_monitor/new_test_candidates/cloud_results_20261005/cloud_validation_report.md)：Robometer PR #33 dtype 兼容版和 TOPReward 在新两组各 `6/6` 产出有效 15 点曲线，并都赢 `G+>N0`；这证明相关模型、视频解码和显式完成识别链路能工作，**不证明隐含前置标签有效或场景无歧义**。两者在两组隐含配对的大多数排序失败。当前 `action-caption endpoint-slot v1` 每组仅 `3/6` 正确；H0 未胜同预算 D2，且有较多弃答。ARS 原版未运行，不可冒称已比较。代码审计发现 `tray_crossbar` 有不移红杆仍符合现有成功谓词的静态终态候选，详见[构念效度审计](../../research/prerequisite_monitor/development/construct_validity_audit_20261005.md)。

| 假设 | 可观察预测 | 能推翻它的证据 |
| --- | --- | --- |
| **S：场景／标签有问题** | 独立读者对目标完成或移障必要性分歧；不改变障碍也有合理合格终态或可执行续行 | 指令语义一致、几何排除明显替代、不同可行续行均无法在障碍不变时完成 |
| **I：设计思路可行，现有实现出错** | 原始画面能支持正确关系，但字幕、实体绑定、端点槽位、解析或进度映射某一环节丢失／颠倒信息；修正该环节后同样规则对多种开发机制改善 | 即使给下游正确的中间关系，下游仍无法判断；或错误广泛存在于视觉前提本身、无法由单环修复 |
| **A：候选架构假设不成立** | 在效度合格、可观察的例子上，P/F/H 或槽位结构仍不优于同骨干同预算 D2；F 没有提供独立可核查反例，H 只增加弃答／成本 | 多个质不同机制上，中间证据正确，且相同预算的结构方法稳定胜 D2，不靠额外帧、token 或弃答 |

三者可同时成立，不能要求从一次总准确率中选一个。尤其不能用“Robometer 正常输出”排除 S；它的成功头／进度曲线也并非场景效度裁判。

## 2. 第一阶段：无需 GPU 的场景与标签审计

**输入**：六族报告、评估协议、[仿真场景源码](../../experiments/prerequisite_probe/probe.py)、[续行代码](../../experiments/prerequisite_probe/produce.py)、各族 `truth/`、主视角视频与构念效度审计。先检查 `research/prerequisite_monitor/new_test_candidates/cloud_results_20261005/` 的结果和 `experiments/prerequisite_probe/artifacts/`；不修改原始文件。

1. 对每个独立场景配置写一张目标语义卡：原始指令、独立读者认为合格的终态、现有 `evaluate()` 实际检查的量、两者差距。分别审“语义明确”“静态终态唯一性／共存可能”“单视角可观察”“固定控制器成功率”。至少显式尝试偏心放置、叠放、侧入、换抓姿态、绕行和不碰非目标物的路线。
2. 把每个场景标为 `strict_necessity_supported`、`policy_dependent_only`、`ambiguous` 或 `invalid`，给证据和未排除的反例。静态无碰撞候选只证明不能宣称严格必要；实际可执行性未测时保留不确定。20 个扰动种子仅表明指定控制器的重复性，不算 20 个场景。
3. 对 `B+/B0/U0/H−/G+/N0` 同一配置整体判定，不因某个模型猜对而保留配置，不因某个模型猜错而删除。人审先只看指令和视频、记录判断与不确定，再核仿真记录及旧分数；若无法找到真正未见分数的第二读者，明确写“单人事后复核”。

**产物**：`research/prerequisite_monitor/development/construct_validity_matrix_20261005.md` 与逐配置反例记录。**退出条件**：每个现有配置都有明确用途；不合格者仍保留作视觉／接口开发，但不得进入“必要前置条件能力”的主准确率分母。若严格必要的开发配置不足，先设计合格制样标准，不用现有数字判架构输赢。

## 3. 第二阶段：不用新推理定位实现故障

**输入**：[原始云端包和逐段输出](../../research/prerequisite_monitor/new_test_candidates/cloud_results_20261005/cloud_validation_report.md)、[字幕槽位证据审计](../../research/prerequisite_monitor/new_test_candidates/cloud_results_20261005/caption_slots_evidence_audit.md)、v12 D/P/F/H0/D2 记录、既有评分脚本。把每个错例拆为以下串联环节，并保存原文引用及帧号：`看见物体和动作 → 绑定源／目标关系 → 关系前后状态 → 替代路线／目标相关性 → 方向 → 逐时映射`。另列 JSON 无效、弃答和运行失败；视觉观察、目标语义与物理必要性不混为一类。

做两个**仅用于诊断、不计入新方法成绩**的离线干预：

1. 重放已保存的原始模型输出，通过同一解析与映射器，核查是否有可复现的字段颠倒、错误实体绑定或错误 `unknown` 处理；不调用模型、不改真值。修复通用程序缺陷须保留旧输出与修复前后差异。
2. 对已有人审证据的开发例，分别给下游模块“正确的物体／动作字幕”和“正确的前后空间关系”做受控替换。若只修字幕就恢复方向，优先解决观察；若正确关系仍给错方向，检查归因／替代路线；若方向正确但曲线错，修共同渲染器。人工替换带特权信息，不能当作真实 Monitor 得分。

**产物**：`research/prerequisite_monitor/development/error_attribution_20261005.md`，每个错误有原始输出、证据帧、首次出错环节、替代解释和修复后的可证伪预测。**退出条件**：能解释 s01/s02 六段各自的正确、错、弃答，并覆盖六族中 Robometer 正向抓取入口例子；不只挑有利错例。

## 4. 第三阶段：选择最小且跨机制的改动

在看新测试前，只允许提出**一个问题级改动**，写出它要改善的错误集合与会失败的机制。候选按第二阶段证据选择：

- 若主要是关系看错：从目标和视频生成需核查的关系，按该关系选择完整帧或局部视图；两个视图冲突时保留 `unknown`。源端裁剪曾改善一次、目标端裁剪曾损害一次，因此不能固定裁剪或写红杆／托盘坐标。
- 若关系看对而目标相关性错：针对“移了物体但目标仍可完成”及“障碍仍在”的具体替代路线提问；F 必须产生与 P 不同、可在帧上核查的反驳，否则删去 F。
- 若主要是结构或渲染错误：修共同输出契约或确定性映射，对 D/D2/P/F/H 全部应用同一修复；不得只修候选方法。

在**已评分开发材料**上做机制级留一诊断，比较 D1、同预算 D2、P、F、H0／新候选；统一骨干、帧、分辨率、调用上限、输出格式和评价。报告每个机制的关系判断、事件方向、证据有效率、弃答覆盖率、无效率、实际 token／时延。现有 2B 可先做低成本 smoke；若必须用 8B，等已有服务器可用时先只跑开发批次，不立即做新盲测。所有尝试记版本和失败；不得把开发提升称泛化。

**决策门槛**：若 D2 已达到同等效果与证据质量，选更简单的 D2；若 P 或 F 单独足够，删 H；若结构方法只有在更高预算或更多弃答下好看，否定增量；若视觉必要关系无法从输入判定，允许未知并收窄任务。只在多个相异开发机制上显示同方向改善，才冻结新方法。

## 5. 第四阶段：先冻结方法，再造新盲测

冻结代码、提示、模型版本、预算、复看策略、主指标和停止规则。**随后**新建至少两个几何／动作原语明显不同的完整六段配对机制，不能复用已评分的旧六段、六族或 s01/s02，也不能只是换颜色、镜像、横杆位置。场景须同时通过：

1. 最终目标语义清楚，成功谓词与“物体在目标中、由指定表面支撑、已释放且稳定”等自然语言含义相符；不把隐藏规则喂给 Monitor，也不直接命令准备动作。
2. 不改变非目标障碍状态时，明显替代终态在几何上被排除，或经多种可行续行挑战仍不可完成；失败只限于单一固定策略的，标 `policy_dependent_only`，不放入严格必要性主测试。
3. 准备视频主视角足以核查关键关系；不需读隐藏仿真参数才能知道为什么动作相关。真实看不清的样本保留并计入不确定性分析。
4. B+/B0/U0/H−/G+/N0 全收齐，等时长同初态，20 个配对微扰只检验操作稳定性。冻结输入和真值哈希；模型侧只得指令与准备视频。

**产物**：`research/prerequisite_monitor/new_test_candidates/next_round/` 下的场景入选／排除日志、语义卡、反例审查、匿名输入清单、真值隔离清单、哈希和运行卡。独立机制数是样本数，帧数与微扰种子不得充数。

## 6. 第五阶段：仅用现有资源验证与裁决

仅在已租服务器届时仍可访问、有已下载权重时上机；不新租、不购买、不重复下载。先只读核环境、再用旧开发一段做格式 smoke；通过后运行冻结新批次。跑同骨干同预算 D2 与所选方法，并单列 TOPReward、Robometer PR #33 兼容版原生结果；不同骨干／输出语义不能互当严格消融。ARS 官方源码仍不可用则写“未运行 ARS”。原始输出封存并取回后才打开真值评分；保留所有成功、错、弃答、运行失败与排除样本。

主判读按独立机制报告 `B+>B0`、`B+>U0`、`H−<N0`，以及 `G+>N0` 锚点；同时报告前置关系正确率、证据有效率、弃答与成本。若新方法在至少两个质不同且构念效度合格的机制中未重复优于 D2，不能宣称架构解决了该问题。若场景效度仍不成立，先改评测定义；若架构不胜，保留负结果，考虑改以评测贡献为方向。
