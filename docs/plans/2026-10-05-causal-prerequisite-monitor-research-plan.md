## 0. 用户已经确定的研究合同

**研究对象**：固定范围内的桌面单机械臂离线任务。模型只接收最终目标指令和准备动作主视角视频，可以重复查看同一视频的时窗和裁剪；推理时不能读取仿真状态、后续执行、反事实标签或真实成功率。不研究换机器人、换后续策略后分数如何变化。

**具体问题**：目标指令没有写出准备步骤时，非目标物体动作是否真正解除完成目标所需的前置条件？必须分清 B+ 有效移障、B0 看似动作却未解除阻挡、U0 原本不阻挡的无关动作、H− 制造阻挡，并保留 G+ 直接成功与 N0 静止锚点。

**期望输出**：独立离线 Monitor 的逐时进度，外加可核查的中间判断：相关对象、候选前置条件、动作前后是否满足、证据帧、置信度／不确定原因。现阶段选定的**待研究路线**是“可见前置条件检查＋反事实续行挑战”；这不是已经验证的新颖方法，也不预先规定必须使用 ARS 的双代理结构。

**真值边界**：仿真中的同初态分叉、等时长空动作与固定后续控制器只用于制样和评测。当前物理效应 `C=q_action−q_control` 是这套固定控制器及预算下的操作性真值，不等于模型从视频能直接知道的事实。模型输出不应伪称精确预测 C；应给可核查的状态判断、相对进度或明确弃答。

## 4. 从问题机制推导架构，不先写提示词

建立 `research/prerequisite_monitor/mechanism_spec.md`，先定义可观察的状态转变：

`goal → candidate prerequisite → visual evidence before/after → blocker/action effect → counterfactual challenge → credit/unknown`。

候选前置条件必须由**最终目标和画面**提出，不能把红块、绿盘坐标或六个开发模板硬编码为方法知识。结构化记录至少有：实体与目标关系、前／后 `true|false|unknown`、支持帧及可见区域、动作造成的关系变化、可能的替代路径、置信度与弃答理由。视觉遮挡或仅凭画面无法判断抓取通道时，允许 `unknown`，不能编造精确物理成功率。

比较三个架构候选，而不是只实现用户选择的混合路线：

| 候选 | 核心 | 主要风险 | 在开发集上必须排除的解释 |
| --- | --- | --- | --- |
| P：关系／前置条件检查 | 目标条件分解、前后关系核验，再映射进度 | 规则过窄、看似理解其实记住托盘占位 | 未见对象、目标和阻挡关系仍成立 |
| F：反事实续行问答 | 同一模型分别问动作前后能否完成目标及阻碍 | 幻觉、顺序偏置、答案受提示暗示 | 交换问题顺序／同义措辞后仍稳定，证据与帧一致 |
| H：混合并交叉质疑 | 先做 P，再用独立上下文 F 找替代解释；一致才给确定分 | 复杂度和调用预算增加，可能仅靠更多 token 获益 | 与 P、F 及同预算直接提示相比有增益 |

用户倾向 H，但它仍须经过文献查重和开发诊断。允许研究后发现简单 P 或 F 已足够，此时选择简单方案并记录理由。若反事实问答只是在重复前置条件描述，不构成独立验证，应重新设计或删去。

**拟议输出接口**（设计阶段确定字段后冻结；这里只是要求，不是代码）：每个时间点的原生进度／增量；事件级 `object, relation, before, after, evidence_frames, alternative_explanation, confidence, status`；状态至少区分 `supported_positive / supported_zero / supported_negative / uncertain`。B+ 只有在障碍确实解除且与目标有关时才得到正向准备信用；B0/U0 不能因红块动了就加分；H− 应退步；G+ 要明确正向。若证据不足，输出未知并计入覆盖率，不能把弃答从分母移走。

**产出**：`docs/plans/2026-10-05-causal-prerequisite-monitor-design.md`，含组件图、数据流、伪代码、输入权限、失败处理、预算、相关工作对比和可证伪预测。先用 2–3 个真实例子逐步手算，再决定模块、提示或模型调用；不为得到想要的分数修改物理标签。

**阶段门槛**：能明确说出 H 比 ARS 的事件核查多验证了什么、该增量如何从视频证据得出、什么结果会证明 H 没必要。若回答不了，就先补文献／问题定义，不进入服务器实现。

## 5. 低成本本地开发：把六族当开发集，不假装盲测

先用现有 36 个编号视频和旧六段调试输入、解释格式与数值映射。开发集要保留全部六族和 Robometer 抓取入口的正向反例；不得只挑 TOPReward 错例。固定三个并行比较：同骨干直接提示 D、P、F、H，记录调用数、实际解码帧、token／显存、输出有效率和弃答率。若 H 比 D 使用更多视觉证据或 token，增加同预算 D 控制；资源不同的比较单独标注。

优先做**诊断而非调分**：逐例检查实体识别是否正确、关系变化是否正确、反事实挑战有没有提出真实替代、错误发生在信用映射还是视觉理解。用真值只在输出完成后核对；不得把 `truth/` 路径、编号映射、后续视频或模型旧分数放入新方法提示。需要人工标注中间前置条件时，保留未见模型分数的独立复核记录；同一人二次查看不称独立盲审。

本地便宜阶段的退出条件：至少 B+/B0/U0/H− 各类均有可解析的中间记录、G+/N0 锚点不崩；对六族的正确／错误及弃答有逐例解释；P/F/H 相较 D 的效果和成本已能比较。开发集上的成功只决定是否值得冻结新测试，**不构成最终效果证据**。

## 6. 新测试、冻结和服务器验证

在看新方法对测试场景的分数之前，先制作**全新的独立场景配置**，优先增加与既有“占托盘／挡抓取入口”不同的可核验前置机制；若新机制主视角不可判或固定控制器不可靠，记录排除原因，不放宽物理门槛。每个合格配置必须一次收齐 B+、B0、U0、H−、G+、N0；验证同初态、等时长对照、视频可见性、逐种子 `q_action/q_control/C`、实际解码帧，并冻结指令、事件窗口、阈值、规则、输入哈希、模型版本与代码。至少准备两个质不同机制的小型完整批次作为第一轮新测试；若不能做到，只报告开发诊断，不称验证。数量根据物理合格率和算力扩展，不能用 20 个扰动种子充作 20 个独立视觉场景。

**2026-10-05 构念效度补充门槛**：`C` 只证明指定续行策略在给定时限内的成功率差，不能单独证明“无关物体动作是完成最终指令的必要前置条件”。冻结新场景前，先独立写清自然语言目标允许的最终状态、物体支撑／稳定条件和机械臂可用动作范围；成功判定必须与该语义一致，并对从上面放、侧边放、与障碍共存、接触移动障碍等替代方式做反例搜索。若无需改变障碍状态就存在满足目标的无碰撞最终摆放，不能标成严格必要；若仅固定控制器失败，只能标成该控制器的策略依赖案例。物理续行可作为必要证据之一，还须有几何排除或多种可行续行的挑战，且把未证实的替代路线记录为不确定。场景入选需同时过“指令语义明确、必要性成立、视频中可观察、正反配对有效”四关；已评分案例不得因重释标签变回盲测。详情及现有场景审计见 `research/prerequisite_monitor/development/construct_validity_audit_20261005.md`。

预先固定主判读：B+ 相对 B0 与 U0 的事件增量排序，H− 相对 N0 方向，G+ 正向锚点；并报告中间前置条件判断正确率、证据有效率、弃答覆盖率、运行有效率和每视频预算。保留合理窗口边界敏感性，不逐视频 min–max；开发集 N0 不足以冻结噪声阈值时不报阈值化漏判率。按**场景配置与机制**报告，不能用帧数、种子数或同一几何的扰动伪装独立样本。

三类结论分开：① 本受控场景中的正确／错例；② 跨新机制是否重复；③ 能否外推一般机器人任务。若 H 只在托盘场景获益、依赖额外帧／更大模型／更多 token、或全靠弃答降低错误，按实际原因收窄主张。若 ARS／简单 P 或 D 已解决，不宣布 H 新颖；可转为评测贡献或重新审视问题。

### 2026-10-05 上机后新增：跨问题机制的改进门槛

首轮新测试 `tray_crossbar` 与 `source_bridge` 已评分，两者虽分别作用于目标放置端和源抓取端，却共用红色横杆视觉原型；从此都归入**开发材料**。当前动作字幕／端点槽位候选未在隐含前置条件主配对上显示稳定收益，不能以其中一个错例的修复宣称架构改进。事后源区裁剪纠正一次视觉关系判断，固定托盘裁剪却使另一个关系判断变差；这只生成待证伪的跨场景问题假设。

下一版必须按**错误机制**而非视频编号设计：区分实体绑定、物体相对源／目标区域的三维位置、可达性与替代路线、证据不足时的弃答。方法接口只允许由最终目标和视频提出“目标物、源抓取区、目标放置区、接近／搬运通道”的候选关系；视图选择由待核查关系驱动，并保留完整帧与局部帧冲突。不得出现“红杆”“绿盘”、固定像素坐标、场景编号或针对单一物件外观的判断分支。若任何部件必须依赖这些内容，只能标为该场景诊断工具，不作为通用 Monitor。

先在所有**已评分开发机制**按完整机制留一进行开发核查，分别报告源端、目标端、占据、上方净空等错误；不能把同机制的 B+、B0 或扰动种子拆到训练和验证两边。改动前写出会同时改善哪些错误、在哪些相异机制上可能失败，再检查证据帧与弃答率。不能以 pooled 均值盖住某个机制的反向结果，也不能通过提高弃答率换取表面正确率。

完成开发后，**冻结方法代码、提示、裁剪策略、预算、主判读和停止规则，再制作全新完整正反配对测试**。新测试应包括至少两个在几何形态或动作原语上明显不同、且不共用红色横杆原型的物理机制；每族仍需 B+/B0/U0/H−/G+/N0 与固定续行物理验证。比较相同骨干、相同调用／视觉预算的直接提示，并同时报告每个独立机制的三项隐含配对、证据有效率、错误／弃答／运行失败分母。只有收益在多个相异机制重复、没有关键机制反向，并且不靠更多预算或事后调参，才讨论问题层面的改进；否则明确缩小适用范围或否定候选。当前两组新测试不得再充当下一版盲测。
