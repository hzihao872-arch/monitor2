# 从现有证据到可检验架构：隐含前置条件进度监测研究计划

日期：2026-10-07（北京时间）  
状态：研究与设计计划；本文件不选定最终架构，不启动服务器，不把开发结果称为 G2。

## 0. 要解决的问题与决策原则

研究对象是固定桌面单臂任务：监测器只得到**最终目标文字与当前回合的主视角 RGB 准备动作视频**，判断动作是否让最终目标更可继续完成、没有帮助、重新受阻，或已经完成。尤其要识别“必要条件已解除，目标物还没有放到位”。输入不含真值、模拟器状态、固定续行控制器、成功示范、旧模型分数或条件代号；同一视频可按固定预算回看与裁剪。若可见证据无法排除替代路线，允许回答 `unknown`，并计入覆盖率分母。

这次工作的核心不是把 P4 的一句任务文字写进提示，而是回答三个连续问题：**模型看到了什么状态变化？为什么这项变化对目标续行有用？怎样把证据转成能撤销的进度而不误伤真正完成？** 架构必须由可定位的错误与一手研究支持，再与简单方法在相同预算下竞争。优先选择能通过检验的最小系统；没有证据支持的模块不保留。

项目级边界沿用[研究共识](../../research/00_project_contract.md)与[可观察机制规格](../../research/prerequisite_monitor/mechanism_spec.md)。本计划将旧六段、旧场景族以及 2026-10-07 的 A/B 两机制九段全部视为**已暴露的开发材料**；无论进一步分析多深，它们都不能充当未见 G2。TOPReward、Robometer 的原生实现和 P0 主指标保持原样。后续若上机，只连接用户已开启的现有实例，先核实例、输入与权重哈希；不得另租、下载或替换权重、上传真值。

## 1. 起点：已有证据已经说明什么、尚未说明什么

| 观察 | 对架构研究的意义 | 不能推出 |
| --- | --- | --- |
| P0：TOPReward 的两机制六个 E 优势配对均失配；Robometer 的 A 为 1/3、B 为 3/3；两者 G 完成对照均正向 | 问题存在于具体任务、机制和读出组合中，B 的 Robometer 是必须保留的正面反例 | “现有模型都不懂因果”或“准备动作永远不计分” |
| P2：相同输入 540 个逐点原始值完全一致 | 本次 P0 失配不是同输入重跑波动 | 跨场景稳健性 |

| P5：定点 visual 原答只有 9/18 可解析，初末状态精确 2/18、3/18；necessity 可解析 18/18、精确 10/18，E 两段均错 | 视觉事实、续行概念和输出协议都有实质风险 | P5 两问独立，故不能直接把 TOPReward 失配定位到视觉或续行某一环 |
| P6：直接问答表面 14/18，但 12 个未变和 2 个 G 占满正确项，E/H 核心 0/4；有些 R 答案方向对而理由错 | 总准确率会掩盖关键能力，必须同时检查证据正确性与 E/H/G 控制 | 正确标签等于正确推理 |

**阶段交付 A：** `evidence_atlas.md`、机器可读案例索引与复验记录。每条原因判断必须指向原答、真实视频帧或原生曲线；看不到内部过程时只写“输出符合某解释”，不写“模型内部先发生了某错误”。复验若发现输入/模型哈希不符，先停下说明，不继续作架构归因。

## 2. 用竞争假说解释“任务文字敏感”

在设计模块前，为每个假说写清已支持、反证和最便宜的区分实验。至少比较以下六种解释，允许多种同时成立：

| 假说 | 应观察到什么 | 关键反证或混淆 |
| --- | --- | --- |
| H1 相关对象/区域没有被稳定选中；明确前置文字帮助定位 | 明确关系后，模型引用的结构与前后状态更准确；仅给一般提醒不够 | 文字改分但证据仍错，说明可能只是语言偏置 |
| H2 状态看对了，模型却把“目标还没完成”当成“没有进展/无法续行” | 正确的前后视觉事实与错误 E 方向并存；区分 `already_done` 与 `can_continue` 后修复 | 前后状态本身错，则先处理感知 |
| H3 原生数值头测量的是任务完成相容性，不直接测未来可行性 | G 稳定正向，E 随任务文字起伏；可解释的状态判断与原生分数分离 | 不能由黑箱分数单独证明内部表示不存在前置关系 |
| H4 P4 是措辞、长度、语义重定义或提示迎合，而非真正利用前置证据 | 等长改写、同义改写和**错误前置断言**都会改变分数，甚至与可见画面相矛盾；G 可能失配 | 假关系只用于开发抗误导诊断，不能进入正式推理协议 |
| H5 可见状态正确，但替代抓放路线或目标约束不清，使“必要”判断不成立 | 独立几何/人工审读对可行路线有分歧；同一视觉状态可对应不同合法续行 | 不能用固定控制器的成败代替视频可见的必要性 |
| H6 时间读出与撤销处理有问题 | R 中段、末段和无动作锚点比较呈不同结论；逐点关系记录与窗口差值分离 | P3 静帧和窗口重算不能事后改写 P0 指标 |

优先从既有结果做**无需新模型调用**的交叉核查：P0/P4 同视频的全部 15 点及 G/R 控制、P5/P6 原答与审读帧、旧 H0 的弃答来源。必要时才设计有区分力的小型开发诊断：匹配任务文字长度与语法、控制是否给出真实/错误/未给前置关系、分离视觉状态问答与合法续行问答、核验相同实际帧和 token。每项先写“若结果 X 则选/弃哪条路线”，没有决策价值的变体不跑。针对 P4 的控制必须报告 E/S/I/N/H/R/G 全九条件，不能只挑改善的 E。

**阶段交付 B：** `hypothesis_register.md`。每条有预测、支持/反对证据、尚不能区分之处、下一次最小诊断和停用条件。最多做两轮有区分力的开发诊断；若仍分不清，不把猜测写成确定机制，也不无限增加同一 A/B 视频的提示试验。

## 3. 有针对性地研究前人的方法与代码

从[现有一手文献矩阵](../../research/prerequisite_monitor/literature_matrix.md)、[官方实现追踪](../../research/prerequisite_monitor/code_traces.md)、[后续文献更新](../../research/prerequisite_monitor/development/architecture_next/literature_update.md)和各篇原文/官方仓库继续，不从零铺开宽泛综述。按上节的具体错误追文献：

1. **任务文字与进度读出：** 重核 TOPReward 的 `True` token 与前缀构造、Robometer 的逐帧 progress/success head、P4 实际文字差异。比较 ARS、ROVER、ProcVLM、R²VLM、PRIMO R1 如何定义进度与步骤，而非只列名字。
2. **视觉关系与前置条件：** 重核 Sharma–Kroemer、SORNet、ReKep 的关系表示、物体绑定与技能前置监督；弄清推理时是否需要 3D、分割、技能标识或示范，哪些思想能在单 RGB 视频下接受证据核查。
3. **反事实可行性与替代路线：** 研究 CoINS 等工作如何定义“移走对象真的使路线可行”，其导航/embodiment 假设与本题差距；寻找可用的质疑方式，但不复制它们不可用的特权状态。
4. **证据验证与不确定性：** 检查 ARS 的二次核查/裁剪、相关工作的拒答和解析失败处理；旧 H0 全弃答的教训是“多加核查”不能自动算进步。

每篇只以论文、补充材料和可核实官方代码写机制卡：**预测量、推理输入、训练监督、关键调用链、视觉证据怎样进入判断、准备动作/撤销如何计分、可否弃答、计算代价、与本项目最相近及最不同之处、可运行身份**。论文报告、我们的代码静态推断、我们的实测分列。没有原版权重或官方入口的写“未运行”；不得手写近似版并称官方对照。重点审 8–12 篇最相关工作和其必要引用链，连续两轮没有新增能改变设计的机制后停止扩展；若发现直接解决同输入问题的现有方法，更新候选与新颖性边界。

**阶段交付 C：** `prior_work_to_design.md`，每项借鉴同时注明它解决哪条可观察错例、需要什么额外输入、如何与本方案竞争及哪项消融会检验贡献。不能把“关系检查”“步骤分解”“反事实移障”“事件核查”单独作为新颖点。

## 4. 架构设计：让任务文字产生可核查的状态约束，而非注入答案

先定义共同输出，再比较候选实现。输出应分开：①目标是否已经完成 `goal_done`；②候选前置关系及前/中/末可见状态；③该关系对合法续行的相关性与替代路线；④有符号进度变化及撤销；⑤证据时间/区域与不确定原因。`beneficial` 不等于已经完成，`harmful` 也不等于视觉场面变乱。进度索引不是未来成功概率。R 若中段条件解除、末段重新阻挡，最终准备信用应撤销；G 已完成必须单独走完成分支。可见关系正确但合法路线尚不确定时，输出区间/未知而不臆造确定正分。

**核心设计问题：任务文字怎样被“放大”？** 候选答案是将目标语义用于自动提出可验证的前置命题，而不是把人工已知的“打开盒盖/展开承托板”塞给模型：

```text
最终目标 + 当前视频
  → 自动提出候选目标物、目的地与可能的可见前置关系
  → 同视频定位前后证据，核查对象绑定、关系真假与遮挡
  → 质疑：原先有无替代路线？改变后是否仍有其他阻碍？
  → 将目标已完成、准备改善、无关/无效、重新阻挡、未知分开读出
  → 逐时记录，可在关系撤销时回收先前信用
```

这是**可检验的模块接口草案**，不是已决定全部模块都要实现。任务文字只负责给出候选语义，画面负责验证；任何自动生成的关系都要面对“目标相关但画面不支持”“画面变化但目标无关”“还有替代路线”三个反驳。不能硬编码 A/B 颜色、盒盖、黄板、坐标或条件编号。一个自生成前置命题若被可见证据推翻，系统应纠错或弃答，而不是将它当成补给 TOPReward 的真值。

按递增复杂度研究四个候选，均用同一骨干、同一实际视觉预算与共同输出字段：

| 候选 | 要测试的机制 | 主要失败风险与保留条件 |
| --- | --- | --- |
| D：直接目标条件判断及同预算 D2 | 不拆模块时能否已经做好 E/H/G/R；这是首要竞争者 | 若它与复杂方法同样正确、证据同样可靠，选 D |
| T：自动任务语义适配 | 从目标与视频**自动**提出前置命题，再作视觉核查/读出；比较只给一般提醒、给自生成关系、给人工关系的开发上界 | 人工 causal_fact 只能作诊断上界；自生成关系错误或 G 受损即不采用；不能把改写后的 TOPReward 称原生 P0 |
| P：目标相关视觉状态记录 | 绑定对象和目标区域，提取 0/中/14 秒证据与关系变化，再作显式可撤销映射 | 旧 P/H0 曾错选关系及端点；必须通过这些回归例且避免只靠大量弃答变好 |
| F/H：在 P 基础上独立质疑合法续行 | 专门检验“清除了看得见的东西是否真的改变可完成性”、替代路线与残余阻碍 | 只有在 P 已看对状态却仍错判价值，且比同预算 D2/P 多修复关键错例时才增加；否则舍弃 |

先审**能否把 T 与 P 合并成一次有证据的调用**；若 P 已足够，不制造 F/H 的额外调用。对于需要两次调用、额外裁剪、更多 token 的版本，同时给 D 相同权限并记录实际帧、视觉/文本 token、延迟和显存；不同预算另列成本曲线。与 TOPReward、Robometer 的比较保留它们的原生输出定义和版本名称，不能把训练目标不同的分数当同量纲数值对比。已有可运行的专用同输入方法应按原生入口列强基线；没有现成权重的明确记未运行，不为凑对照临时下载。

**阶段交付 D：** 一页 `architecture_decision_record.md`（每个模块对应哪条错例/一手启发/反例/消融，含被拒方案），以及版本化 `architecture_spec.md`（合法输入、模块 I/O、时间索引、证据引用、状态逻辑、unknown、解析失败、成本上限）。架构只在此决策记录通过后实现。

## 5. 比较实验与阶段门槛

### 本地研究与开发门槛

1. **证据门槛：** A/B 与旧场景的哈希、原答、逐条件预期和旧构念缺陷可追；P0、P4 等不混并。凡原答不足以区分瓶颈的病例，标不可定位。
2. **设计门槛：** 每个模块须有一条非泛泛的失败例、一篇真正相关的前人机制及一项能推翻它的消融；任务文字是否改写、人工信息是否进入推理均公开。
3. **接口门槛：** 在开发材料上先完成无模型 dry run、字段校验、证据索引、R 正转负/撤销、G 完成优先、unknown 与失败留存；解析修复若改变提示，要对所有候选统一处理并升版本。
4. **判别门槛：** A/B 九段与旧失败例须同时检查 E>S/I_b/N_b、H<I_o/N_o、G>N_o、R 中段与末段、关系证据有效率、覆盖率、解析率和成本。所有九条件和错误/平局/失败均入表。旧场景只用于回归，不强行按有争议真值优化。

先做一轮小样本 smoke 找程序或格式错误，再做至多两轮已登记的机制设计迭代。每轮只解决一条明确假说：记录旧版本、变动点、完整病例结果、消融、为何继续/停止。禁止根据某个 E 改善而忽略 G、H、R；若旧 `relation_endpoint_v1` 式全弃答再次出现，直接判为覆盖失败。若 D/D2 已达到关键条件且证据正确，停止增加模块。若视觉状态仍错，先研究定位/回看；若状态对而续行错，再考虑 F/H；若两者对而曲线错，优先修读出逻辑而不是加一次 VLM 调用。

### 冻结与服务器门槛

开发结论足以选一项最小架构后，冻结提示、代码、解析、预算、全部条件指标、平局/失败/unknown 处理、停止规则和评估脚本，形成 `METHOD_FREEZE` 与上机运行卡；保存哈希。不得拿开发 A/B 调参后直接称 G2。服务器开启后才核对用户提供的实际端点和租期：只读 GPU/磁盘/提交/权重/输入哈希预检，旧格式 smoke，一条开发例 pilot；任一身份不符即停。每个阶段先估实测时长，并留至少 10 分钟下载验封缓冲。先原始输出封存与下载逐文件验哈希，再在本地揭盲评分。绝不覆盖 P0 封存原件，也不修改 TOPReward/Robometer 原生方法。

### 未见 G2 门槛

G2 另建**真正未见**场景，在看模型结果前确定机制、几何/相机/轨迹变化、目标句、九条件制样规则与样本量；独立审查关键视觉状态、替代合法路线、固定续行的物理构念和可观测性。若仍是同步运动学场景，明确限定论断，不声称真实机器人规划能力。主表同时列冻结架构、D/D2、原生 TOPReward 和 Robometer、可运行的强相关方法；跨机制分层报关键 E/H/G/R、证据有效率、覆盖率、预算和不确定区间。开发集上的人工 causal_fact 只报告为上界诊断，不能成为正式方法输入。未见结果不用于临时修提示；若失败，保留原结果、分析原因，再将修订作为新版本在下一批未见场景测试。

## 6. 最终应交付什么，以及何时改变研究方向
