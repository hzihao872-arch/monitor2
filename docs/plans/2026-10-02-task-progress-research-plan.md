## 一、必须继承的研究共识

### 1. 已固定的研究问题与方向

核心问题是：

> 机器人正在发生的变化，是否真正满足任务要求？此前已经取得的进展，是否仍然有效？

这里的“第 10 条”和“第 11 条”只是前期讨论中的编号。本计划保留其含义，不依赖新对话能看到原始编号清单：

- **第 10 条是主要问题：**局部子目标达成，却破坏了其他任务要求、保持条件或依赖，监测器可能因此错误确认有效进度或任务完成。
- **第 11 条是研究线索：**实际变化偏离预期时，需要区分正常慢速、必要调整、停滞和真正退步；这种偏差可以帮助发现疑点和分配核验资源。

总体方向是冻结已有模型，把研究贡献放在任务要求如何引导观察、预期如何触发核验、核验结果如何支持进度更新的推理过程上。方向中的这些关系不等于预先指定三个独立模块，也不等于规定信息流必须采用某一种实现。

研究价值要通过公平条件下的判断改善来证明。不要求先证明其他架构无法表达同样的机制，也不把“普通依赖图可以实现”当作否定研究价值的充分理由。

### 2. 已固定的 EvoNav 学习定位

**学习 EvoNav 如何开展和论证架构研究，不以其具体方法作为我们架构的迁移模板。**

重点学习它如何提出问题、解释设计选择、选择比较对象、控制混杂因素、验证机制、处理失败案例和限定结论。逐步分析的是其研究与论证链条，而不是要求我们的系统逐模块对应 EvoNav。

论文中的论证顺序不一定等于作者实际开展研究的时间顺序。除非有直接材料，否则只能讨论可观察到的研究逻辑，不能声称还原了作者真实研发过程。

### 3. 暂不固定的内容

下列内容只是此前帮助阐释方向的候选设想，不能在后续执行中自动升级为需求：

- “生成推进和保持条件—形成短期预期—竞争解释核验—局部更新进度”的四步架构。
- 必须使用两个竞争解释、针对性历史检索、依赖图、显式记忆或特定状态机。
- 固定数量的模块、固定调用顺序、固定检索策略或固定提示词。
- 此前提出的具体消融、基线名单、数据集、指标及预期改进幅度。
- 对创新性、优于已有工作或可投稿等级的结论。

可以重新考虑上述设想，但必须给出具体错误、相关证据和可检验的理由。

| 研究线 | 输入 | 产出 | 边界 |
|---|---|---|---|
| 研究流程学习 | EvoNav 原文、附录及必要的官方材料 | 如何建立和验证架构贡献的分析 | 不直接据此决定我们的模块 |

两条线在假说表达、实验设计和证据审查时汇合。EvoNav 是流程参照，其论证方式也需要批判性检查。

## 二、执行原则与证据规则

1. **先理解研究流程，再探索架构，再验证。**不在第一轮阅读后立即把原有四步闭环写成定稿。
2. **区分四类陈述：**原文事实、我们的解释、待检验假说、已获得的实验结果。在表格的具体条目中标记，不靠文首的一句免责声明代替。
3. **先查一手来源。**核验论文标题、作者、版本、链接、附录和官方代码；搜索摘要只作定位。无法访问的来源明确记录。
4. **公平不等于只写“相同预算”。**后续要明确模型版本、输入权限、实际证据、调用次数、图像数、token、延迟和外部信息来源。
5. **关注在线可获得的信息。**在时刻 t 作出的判断不能使用 t 之后的观察；预测不能充当已发生事实；标注答案不能进入模型输入。
6. **保留不知道。**遮挡、视角不足或指令歧义不能被强制解释成成功或失败。用户要求与系统推断必须分开；不能为迎合观察擅自放宽要求。
7. **保留反例和负结果。**先固定开发集与测试集边界，再调提示和阈值；不要只保留有利轨迹或挑选最好的一次运行。
8. **阶段产出代替反复口头确认。**在已授权阶段内自主推进。事实不明确时先查证；真正缺少必要信息才集中提问。出现需要改变固定问题或引入训练的决定时，再交由用户判断。
9. **不预设工具负担。**在确定模型和数据之前，不安装整套训练环境，不启动付费任务，不为方法阅读先复现完整导航系统。
10. **当前未授权多代理工作。**后续默认单个执行者推进，不因阶段可拆分而自动创建子代理或新聊天。

## 五、阶段 1：拆解 EvoNav 的研究论证链

**目的：**理解它如何建立“架构带来价值”的证据，而非学习一套准备照搬的架构。

**行动顺序：**

1. 第一遍通读摘要、引言、方法、实验、局限和附录，画出论文实际提出的主要主张。
2. 第二遍按“问题—设计理由—实验—结果—结论”逐条建立对应，标出原文位置。
3. 阅读方法到足以理解实验干预的程度。说明模块作用可以帮助理解论证，但不制作“我们的对应模块”表。
4. 对每个主结果检查比较对象、输入、资源、评测条件和统计信息；判断结果能排除什么替代解释。
5. 审查每项消融究竟改变了什么。如果同时改变预算、信息或参数量，明确其归因局限。
6. 审查泛化、鲁棒性、效率和案例分析分别支持什么；没有的证据写“未报告”或“未找到”。
7. 必要时核查官方代码中的配置或评测逻辑，只核查影响论文解释的细节；本阶段不要求完整运行导航系统。
8. 最后做一次反向审查：如果我是审稿人，还会要求哪种对照？哪些表述比证据更强？

**逐条记录模板：**

| 字段 | 要填写的内容 |
|---|---|
| 作者主张 | 忠实转述，避免把我们的设想混进去 |
| 来源位置 | 论文版本、章节、表/图或附录位置、直接链接 |
| 作者提供的证据 | 实验对象、比较方式、指标和结果 |
| 对照的作用 | 排除了哪个替代解释，仍剩下什么 |
| 证据边界 | 数据范围、预算差异、统计缺口等 |
| 我们的评价 | 支持充分、支持有限、无法判断，并说明理由 |
| 流程启发 | 可借鉴的研究操作，不写对应算法模块 |

**产出：**`research/02_evonav_argument_map.md`。

**验收：**主要贡献主张均能对应到原文证据或明确缺口；能够区分整体有效、某机制有作用、机制解释成立这三种强度不同的结论。

## 六、阶段 2：提炼可参考的研究流程

**目的：**把论文阅读转成可执行的研究方法，而不预定我们的技术方案。

**行动：**

1. 按阶段 1 的证据，整理 EvoNav 对问题提出、设计依据、基线、消融、效率、泛化及失败分析的处理。
2. 为每项可借鉴流程写明：原文如何做、目的是什么、我们需要满足哪些前提、应怎样调整、不能据此推出什么。

5. 检查全文是否仍存在“照着 EvoNav 模块设计我们系统”的隐含假设，发现后修正。

## 七、阶段 3：将研究问题落实为可判断的错误与案例

**目的：**明确系统究竟要判断什么，以及什么证据能区分判断对错。

**行动：**

1. 区分历史事件、当前有效条件、整体完成判断、不确定状态；这是任务与标注层面的区分，不要求架构必须用四个存储槽实现。
2. 明确允许的输入：指令、截至当前的视觉历史、动作信息、传感器或其他元数据。尚未选择的输入列为选项，不默认全部开放。
3. 建立候选错误分类：错误确认、错误撤销、漏检失效、停滞误判、证据不足却过度确信。后续按实际任务合并或调整。
4. 选取一小组具有区分力的轨迹或概念案例，包含正常推进、正常慢速、必要调整、局部成功伴随关系失效、无效重复动作和观察不足。
5. 沿时间轴记录可见信息、要求、参考状态、可判断时刻及缺失证据。概念案例必须标注为示例，不能当作实测样本。
6. 对关键案例配对，尽量只改变一个关系或事件，检验错误是否真正来自我们关心的问题。
7. 制定初步标注规范。参考真值可以依据完整视频或独立传感器，但模型在线输入严格截断；同时标记“最早可观察时刻”，不要因失效当时不可见而错误评价检测延迟。

**示例边界：**杯子与托盘的故事仅用于解释任务问题，不规定数据集必须包含杯子和托盘，也不证明现有方法已经出现该错误。

**产出：**`research/04_problem_and_cases.md`。

**验收：**每类核心错误都有明确判定条件和反例；未知不被混成失败；能够说明一个方法怎样才算改善、怎样只是换了一种错误。

**行动：**

6. 比较已有方法是否已覆盖我们的机制组合或错误类型；若差别只在名称，缩小或修正贡献表述。

## 九、阶段 5：形成可证伪假说与候选架构

**目的：**把问题证据和文献启发转成少量可比较的设计。

**行动：**

1. 对最关键错误提出机制假说，明确可能的收益、代价和失败情形。
2. 为每个假说写出：触发场景、所需信息、预期改善、替代解释、最便宜的区分实验、否定条件。
3. 形成少量具有实质差异的候选架构；可从两到三个开始，数量按问题复杂度调整，不以堆模块为目标。
4. 对每个候选写清输入输出、状态维护、信息传递、触发时机、证据权限、预算和不确定性处理。
5. 每个新增机制都要对应具体错误和检验方式；解释不了的机制先移除。
6. 预先写出减少复杂度的方案：若强基线已经解决问题，是否还有有价值的剩余差距？

**假说模板：**“在场景 X、输入与预算 Y 下，机制 M 应改善指标 Z；若对照 C 同样改善，或改善仅由资源增加解释，则不能支持该机制主张。”

**产出：**`research/06_hypotheses_and_candidates.md`。

**验收：**候选设计由案例和文献支撑；不是对 EvoNav 的模块映射；每项机制都有能使其被否定的实验结果。

## 十、阶段 6：先制定评测协议，再进行系统调试

**目的：**使后续结果能够区分架构收益、信息收益和计算收益。

### 1. 数据与标注

选择包含目标错误、具有时序信息且权限清楚的数据。可以先用已有离线轨迹评估监测器；是否需要模拟器或真实机器人，取决于研究主张。若监测结果会影响后续动作，离线实验不能单独证明闭环任务成功率改善。

制定训练或开发与测试划分，即使不训练模型也要防止提示调试污染测试。优先按任务、场景或轨迹来源隔离近重复样本。正式规模由先导方差和所需精度决定，不在没有依据时承诺固定样本数。

对含糊关系定义标注准则，并检查标注一致性；有分歧的样本不能为了让结果好看而随意剔除。

### 2. 基线选择

至少评估以下基线类型是否适用，并在协议中说明保留或排除理由：

- 同一冻结模型直接综合判断指令和观察。
- 生成任务条件后逐项检查的强基线。
- 经阶段 4 核验、最接近本问题的已有方法。
- 若候选架构使用额外推理调用，设置资源相当的重复判断或其他推理分配对照。

以上是比较问题清单。具体实现要适配任务，并给基线合理的开发预算，不能故意使用弱提示。

### 3. 两种需要区分的公平比较

**证据选择实验：**各方法具有相同的历史访问权限和资源上限，可以选择不同证据，用于判断证据选择策略是否有价值。

**判断机制实验：**尽可能向不同方法提供相同实际证据并匹配资源，用于判断推理和更新方式是否有价值。

两者不能混写成笼统的“相同信息”。若无法同时匹配调用、token、图像和延迟，明确主预算约束，完整报告其他成本，必要时绘制性能与成本曲线。记录预算上限与实际消耗，包含预处理、检索及所有额外模型调用。

### 4. 指标与分析

在开发阶段结束前选定主要指标及其分母，并冻结计算脚本。可考虑以下候选指标，但不能未经任务定义直接全部采用：

- 无效进度或错误完成被确认的比例。
- 仍然有效的进度被错误撤销的比例。
- 关系失效或停滞的检出情况与检测延迟。
- 不确定输出的覆盖率与已作判断的错误率，防止靠始终输出未知获得表面优势。
- 当前有效条件或整体进度状态的准确性。
- 实际调用、图像、token、延迟与运行失败率。

局部判断与整体完成可分别评估；不要直接把所有情况压成一个不透明百分比。若输出数值进度，先给出定义和标注依据。

采用配对比较；置信区间或重采样应考虑同一轨迹内帧的相关性，不能把每帧都当独立样本制造虚假的显著性。随机性重复次数及样本规模由先导结果决定。

### 5. 消融与反证

消融由最终假说决定，不提前固定成原先四步模块清单。每次干预说明同时改变了哪些资源和信息；直接删除模块可能让系统失去必要输入，需考虑合理替代对照。若主张模块交互有效，设计能够比较单独作用与联合作用的实验，不仅比较完整版和空白基线。

选择可能不利于候选方法的场景：预期错误、关系不可见、历史证据缺失、正常调整、保持条件无关或发生变化但不影响任务等。评估复杂架构是否在简单任务上付出不必要代价。

**产出：**`research/07_evaluation_protocol.md`。

**验收：**无需看结果就能判断什么结果支持或否定假说；输入、成本、主要指标、划分和分析方法已明确；论文级主张与实验能力相匹配。

## 十一、阶段 7：最小实现与先导实验

**目的：**用低成本检查可测性、数据质量、基线强度和机制信号。

**行动：**

1. 确认阶段 6 协议后选择最小可运行环境，固定模型版本与参数，建立数据清单。
2. 先实现输入截断、标注读取、输出记录、指标计算及强基线，再加入一个候选设计。
3. 进行小样本端到端运行，检查信息泄漏、指标实现、预算记录、缓存、错误处理和恢复能力。
4. 只在开发数据上调试，记录全部尝试，包括失败运行和否定结果。
5. 对错误逐条回看证据，判断是感知问题、证据选择、推理、状态更新还是标签问题。
6. 依据先导结果估计资源与不确定性，决定扩大实验、修改机制、回到问题定义或放弃候选。

冻结模型的推理研究无需检查训练损失、反向传播或优化器；不要机械套用训练项目流程。涉及模型与代码实现时，再制定具体工程计划和必要测试。

**产出：**`research/08_pilot_report.md`、实际代码、可重复运行命令、`experiments/run_ledger.csv`。

**验收：**从输入到评测的链路可以重跑；改善不能明显归因于泄漏、预算不公平或标注错误。小样本信号只用于后续决策，不写成正式效果结论。

## 十二、阶段 8：受控实验与贡献审查

**行动：**

1. 在冻结的测试协议下运行主要对比、机制实验、必要的成本分析和泛化检查。
2. 保存版本、配置、数据划分、模型标识、随机性设置、原始输出、成本、错误和指标。
3. 依据假说分析结果，不因看到结果才改变主要指标或排除不利样本；探索性分析另行标记。
4. 将每项拟写贡献绑定到实验、指标和可追溯产物。
5. 审查三个问题：整体是否更好、关键机制是否有作用、证据是否足以支持提出的解释。
6. 明确负结果、适用范围和未解决问题；若结论仅在特定任务成立，就保留该限定。

**产出：**`research/09_results_and_claims.md`、由记录生成的表图、复现说明。

**验收：**合作者能从原始记录重建主要结果；结论强度不超过证据。论文撰写、投稿与发布是后续任务，本计划不自动授权发布。

## 十三、阶段回退与停止规则

| 发现 | 应采取的行动 |
|---|---|
| EvoNav 没有充分证明某项机制 | 如实指出，补充我们需要的验证动作，不照搬薄弱证据 |
| 找到已有工作已解决相同问题 | 重新定位差异，必要时缩小贡献；不通过改名保留创新性宣称 |
| 强基线在目标案例上已表现充分 | 寻找有证据的剩余困难，或承认当前候选没有必要 |
| 改善只来自更多调用或更多图像 | 修改资源对照，或将主张限定为成本允许下的系统收益 |
| 正常调整被大量误撤销 | 回到假说与判定机制，不能只报告漏检率下降 |
| 模型缺乏所需感知能力 | 明确瓶颈，检查可用证据；未经用户决定，不改成训练新模型项目 |
| 任务状态缺少可靠标注 | 先解决定义与标注，不用不透明的模型评分替代真值 |
| 单一指标改善但未知输出激增 | 检查覆盖率与错误率的权衡，不将保守弃答当作全面改善 |
| 多次实验没有支持机制假说 | 保留负结果，修改或停止该候选，不无限叠加模块 |
