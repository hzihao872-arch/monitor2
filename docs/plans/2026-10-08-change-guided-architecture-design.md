# 变化引导的操作进度 Monitor：架构方向与能力设计备忘

日期：2026-10-08。状态：**设计候选，不是已验证或冻结的最终方法。** 继承[研究冻结方向](../../research/prerequisite_monitor/RESEARCH_IDEA_FREEZE_20261008_zh.md)与[实施计划](2026-10-08-change-guided-task-knowledge-monitor-plan.md)。本备忘只讨论架构，不启动模型实验。

## 一、先定义要增强的能力，而非预选模块数

目标是从最终任务和 RGB 视频前缀判断已发生环境变化的任务作用。当前 A/B 开发失败首先是模型漏看目标区域的盒口或承托板，其次才可能是看对变化却误判价值。VICtoR 已有目标驱动任务知识与视觉状态匹配；ARS 已有自适应取证、事件提出和独立核验。因此，“有任务知识”“多次看图”“有验证 agent”均不能独立构成新贡献。本项目真正需要检验的是：**具体变化进入局部任务知识生成，是否让模型更可靠地发现并评价对最终目标有用、无关、损害或被撤销的条件。**

选择方案时将三个候选当作真实竞争者：A 是直接目标条件判断加同预算复核；B 是目标先行生成条件再验证；C 是变化先行生成局部条件再验证。推荐把 C 作为研究假说，而非先验胜者。若 A/B 已解决关键问题，最终系统就收缩为它们。训练评估器属于后备路线：只有确认视觉事实、任务作用或读出中的稳定瓶颈且免训练办法在可接受成本下无法修复，才另行比较训练的收益。

## 二、推荐研究的系统骨架

```text
目标 g + 截至 t 的 RGB 前缀
  → [先找实际变化] 从视频前后稳定画面定位发生变化的结构与区域
  → [LLM 任务关系推理] 从目标与实际变化生成局部条件、任务作用假说与反例
  → [独立证据核验] 重新取前/中/后原帧及必要裁剪，否决错误事实或命题
  → [任务作用判断] 完成 / 直接就绪 / 部分准备 / 无关 / 阻碍 / 不确定
  → [前缀事件账本] 当前净作用、曾有进展及其撤销、证据和成本
```

这是一条能力路径，不要求每个方框单独调用模型。先比较单调、两调及必要时触发的追加取证；增加调用必须在同预算对照下带来独立收益。初期不建巨大场景图、不预置 A/B 关系词表、不要求完整动作规划。每个中间命题都带 `观察事实 / 推测的任务作用 / 视觉验证结论` 的身份，不能把生成的用途当作画面事实。

### 1. 视频先行的变化发现：只围绕已经发生的变化

- 当前受控视频机位固定、环境变化集中，第一步可以用始末稳定帧差、短时运动和机器人遮挡剔除定位**真的变了什么**；这一步不从目标反推可能的盒盖、板或其他前置物。对于有相机移动的扩展数据，先做配准或把视角不稳标为不确定。
- 初次采用全帧和均匀时间采样；对检测到的变化区域再读取高分辨率原帧与邻近时刻。变化前、变化后、机器人离开后的稳定画面都要核查；R 类还必须看到中段和末段。裁剪同时保存全帧位置。若视频没有可支持的变化，允许空事件。
- 变化候选产生后，才把目标文字交给任务关系 LLM。为判断变化是否作用于目标，可让核验器查看目标物/目的地的上下文画面；这是**检查已发现变化的关系**，不是从目标生成一串未发生的候选前置条件。
- 将候选限制为少数可见事件；漏检率和假检率分别测。若仍漏 A/B，先改始末取帧、遮挡处理、分辨率或变化定位，不增加目标先行推理层。

### 2. LLM 任务关系推理器：从变化提出可被推翻的局部知识

这是明确的 **LLM 组件**，与前一步的视觉变化提取分工。它接收最终目标、前缀内自动提取的变化事实、该变化周围的可见上下文和固定通用机器人能力约定；不接收人工关系答案、仿真真值或未来结果。它只问“**已经发生的这项变化**与目标物/目的地是什么关系，是解除阻碍、创造条件、造成阻碍、部分帮助，还是无关”，不先列出目标可能需要的全部前置条件。例如“板移到目标足迹下方，可能建立稳定放置所需的承托”。输出是简短的**候选关系**、预期可见证据、可能使该解释失效的反例，以及 `相关/无关/未知` 的初步判断，不直接给最终奖励。对于粉色物体移动，它可以明确提出“未发现与当前目标的关系”，而不是强行编造用途。

对每条变化至多保留少数主要命题。LLM 还需区分：变化是否对应**正确目标区域**；它可能建立的是直接操作条件，还是只减少部分准备；在原状态下是否可能有不经过该变化的替代路线；变化后是否仍有残余阻碍。这是任务关系推理，而不是纯视觉识别或完整策略规划。下一步 VLM/视觉取证器重新读取原帧，核验候选关系所依赖的实体绑定与前/中/末状态。核验结果返回后，可由同一 LLM 的第二个逻辑阶段依据**已核实事实**判断任务作用；两次逻辑阶段可以共享底座，但其输入和原答须分开封存，才能分辨关系生成错误与视觉核验错误。

局部命题不等于必要性定理。单视角 RGB 看不到完整碰撞几何和接触状态时，不能凭语言推断“唯一合法路径”。知识要能随着新前缀更新：同一结构后续被移回时，旧命题的当前状态改变；旧时刻的实际输出留档，不能用新帧追溯美化当时的预测。原则上只维持与目标和当前变化相关的少量命题，不维护全场景无关关系。

### 3. 独立核验：真正反驳自己，而非重复同一句判断

验证器拿到命题、原始视频前缀和可查询帧/裁剪，但必须重新陈述**中性视觉问题**：哪个结构、在目标区域哪里、前/中/末分别处于什么状态，有何像素证据。先判断视觉事实，再判断命题支持度；不能先看到“应有帮助”就把板的端点想象成已部署。验证器可指出实体混淆、时间端点看反、残余阻挡、目标区域不匹配或证据不足。命题修改后，旧核验失效并重查，这一点参考 [ARS 的证据规则](https://arxiv.org/html/2609.34484v1)。

验证可以是独立上下文的一次短调用，也可以在简单案例中省略额外模型调用，具体由开发消融决定。额外调用只在事实冲突、遮挡、候选之间争议或物理可行性不明时触发。格式校验只保证字段和时间索引合法，不代表视觉真实；旧 v0.2 的 valid 原答已说明这一点。输出字段保持短：事件、命题、证据秒数/区域、支持/否决/未知、判断和原因。解析失败保留原答计入分母，不自动修成“正确”。

### 4. 任务作用与可撤销读出：先用多维状态，再决定数值奖励

先分别输出 `goal_done`、`direct_ready`、`partial_preparation`、`impact` 和 `reversal`。开了一点盖子可能减少剩余操作，却仍不具备直接放入条件；R 中段建立条件、末端撤销，应记录中段收益和末段信用回收；G 的真实完成要优先判，不受准备规则误伤。无动作锚点测漂移，错误目标配对测虚假信用。

如果要给策略学习连续进度，先用独立数据校准从已核实状态到进度的映射，并检查“错误重复开关结构也能刷分”的循环。没有可靠校准时，先用高置信正向事件筛选动作块，不假装拥有 0–100% 的通用进度值。单视角看不清支撑、接触或替代路线时保留未知，同时报告覆盖率；弃答不是免费正确。

### 5. 前缀事件账本：让监测器在时间上自洽

账本记录每个时刻**当时可用**的证据、候选、验证结果与输出版本。新帧可以改变当前信念，也可注明旧事件被撤销；评测过去时刻时只能读取旧快照。实现层需针对未来帧访问、未来标签、跨病例缓存与后验生成摘要设置自动阻断。ARS 可在离线完整轨迹中以后续证据核实过去事件；我们的在线前缀约束是明确不同的实验条件，不能借它的结果替代本项目实测。[ARS 问题设定](https://arxiv.org/html/2609.34484v1)

## 三、哪些细节有资格进入最终架构

| 观察到的失败 | 优先研究的能力细节 | 何时不加/删掉 |
| --- | --- | --- |
| A/B 的 E/H 仍漏盒口或承托板 | 始末稳定帧差、机器人遮挡剔除、全帧与变化区裁剪双视角、短时序密采样 | 正确变化召回未提高；多像素成本压倒收益。 |
| 看到了移动却绑定错目标 | 双盒左右目标互换、原图坐标记录、目标物/目的地分别绑定 | 目标先行或直接法同样能排除错误目标。 |
| 端点事实正确而用途仍反转 | 局部条件生成、替代路线/残余阻挡质疑、部分准备与直接就绪分离 | 同预算直接法已达到同样的任务作用判断。 |
| 命题生成对但验证仍迎合它 | 独立上下文、中性视觉问题、可推翻反主张、修改后重新取证 | 核验不降低错误接受率，或过度弃答/损 G。 |
| R 有峰值但末态复原；G 被误伤 | 当前状态与事件历史分开、完成优先、信用回收 | 输入事实本身错时，先不调数值读出。 |
| 8B 视觉能力到顶、但有正确定位的 oracle 上限 | 在同一输入协议下比较更强骨干、必要时蒸馏/训练 | 模型身份、权重、显存及成本未确认；仅更大模型带来的增益不算架构增益。 |

模块评估先使用已有 A/B 九条件作**开发诊断**，但不凭它们决定泛化。最能识别核心贡献的是双盒交叉、同视频换目标及同目标换变化；再做真实未见布局和新机制。C 必须在同底座、同信息边界和相近预算下胜过直接法及目标先行法，而且优势来自可核验的变化和任务作用，不是更长提示、更多调用、错误弃答或人工答案。TOPReward 与 Robometer 的原生结果、Robometer 的 B 正例、G 完成和所有负控必须同时保留。若能运行 ARS 原版或诚实标注的前缀适配，则作为强竞争者；当前论文所链官方仓库网页不可访问，不能凭论文描述冒充官方运行。

## 四、最终研究应怎样闭环

达到“最好”需要三层证据一起成立：**机制**（变化引导知识确有独立收益，视觉事实与理由可审计）、**外推**（新布局/资产和真正新机制上仍有用）、**效用**（相同轨迹池与训练预算下，进度筛选改善可交互机器人策略）。[ARS](https://arxiv.org/html/2609.34484v1) 的强处正是把受控错目标测试、工作流消融和策略学习连起来；它的短视频消融也显示复杂核验未必在每种场景都有增益，所以本方案采用按不确定性触发的取证，而非默认越多 agent 越好。

现有 A/B 滑块按预定轨迹运动，适合诊断 monitor，不能直接当作策略学会开盖/展开板的证据。下游需另有可交互机构或真实可控技能、混合质量轨迹、统一策略初态/更新数和成功判据。若 monitor 只提高标签准确率却没有策略收益，保留它作为评估结果，不把下游价值写成已成立。若只有两种开发机制有效，也不声称通用机器人任务知识生成。整个研究以错误归因驱动架构升级，而非以模块数量驱动。
